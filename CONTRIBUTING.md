# Contributing to Aetox

Aetox is built by one person who uses it for real work every day. Bug reports and sharp questions are
what move it forward fastest. Here is what helps, and what happens to what you send.

## The shape of this repository

The source of record is private (`Mikedev115/Aetox-src`). This public repository receives the documents
and the releases: the READMEs, release notes, the measurement shelf under `docs/reports/`, the scoop
manifests and the built installers.

So a pull request that changes source code **cannot be merged here directly** — there is no source here to
merge into. It is still read, and it still counts: send the failing test, the patch, or the reproduction,
and it is ported into the source of record with your name in the release notes. A few PRs have landed that
way.

## A bug, reported so it can be fixed

Include these six things. Reports with them get dealt with in one pass; reports without them cost a round
of questions first.

1. **The version** — Settings › About, or `aetox --version` in a terminal.
2. **The door you were in** — Assistant or Code.
3. **The model and provider** you had selected.
4. **The permission level** — Ask, Unsafe only, or Full access.
5. **What you asked for, in the words you used**, and what happened instead.
6. **The log** — Settings › About has a button that fills in the version and the last log for you; paste
   what it gives you.

Do not paste API keys. Aetox strips them from logs, but read before you send.

If the problem is that Aetox did something you did not allow, say which setting you were on — that is the
detail that decides whether it is a bug or a design choice, and it goes to security if it is a bug. See
[SECURITY.md](SECURITY.md).

## A feature

Describe the job you were trying to finish, and what you do today instead of it. That is far more useful
than a list of settings you would like the app to have. If you have already found another tool that does it
well, say what you liked about it.

Before you write, check [ROADMAP.md](ROADMAP.md) — some things are already decided against, with the reason.

## Translations and documents

The READMEs are English, Thai and Chinese. Corrections to wording, a wrong link, a screenshot that no
longer matches the app — all welcome. Say which line or which section, and which of the three files it is in.

## Skills and teams

Reusable skills and teams are published from [github.com/aetox-skills](https://github.com/aetox-skills),
which takes contributions directly. A skill that works there can be installed into Aetox.

## Security

Never in a public issue, a discussion or a pull request. [SECURITY.md](SECURITY.md) says how to report
privately, and what we promise in return.

## What gets closed, and why

- **Support questions** — move to [Discussions](https://github.com/Mikedev115/Aetox-Harness/discussions),
  where the answer stays useful to the next person.
- **Feature requests already decided against** — closed with a pointer to the line in `ROADMAP.md`.
- **Bug reports with no version and no log** — asked once, then closed. Without those two, the report
  cannot be reproduced.
- **Anything generated by a bot and read by nobody** — closed on sight.

Being closed is not a judgement of the person who sent it.

## Licence of what you send

You keep the copyright in what you send. By sending it you allow it to be used in Aetox under the
project's licence — see [LICENSE](LICENSE). There is no CLA to sign.
