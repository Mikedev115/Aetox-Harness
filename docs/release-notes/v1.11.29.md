## แถบเลือกเอนจินกลับมาบนแชทโค้ด

- **เดิม** ทุกเซสชันบนโต๊ะโค้ดถูกบันทึกพร้อมทีมของโต๊ะตั้งแต่ `266a1158a` (12 ก.ย. 2026) แต่ guard เส้นทางของฝั่ง UI นับ `team` เป็นเหตุห้าม แถบเลือกเอนจินจึงไม่ถูกวาดเลยบนแชทโค้ดทุกอัน และเมื่อเลือกเอนจินจากหน้า External Adapters แล้วช่องพิมพ์ก็ไม่เปลี่ยนตาม เพราะ `externalCodeRuntime` ผูกกับเงื่อนไขตัวเดียวกัน ฝั่ง engine ไม่เคยห้ามแชทที่มีทีม (`supportsCodeRuntime` ตรวจแค่ desk/chair/side/transport) สองฝั่งจึงตัดสินไม่ตรงกัน
- **ตอนนี้** `supportsCodeRuntimeRoute` ตัด `team` ออกจาก guard ให้ engine เป็นผู้ตัดสิน · `space` ยังคงไว้ เพราะเทสต์ตรึงว่าแชทในโปรเจกต์ใช้โมเดลปกติ · เพิ่มเทสต์ตรึงว่า team ไม่ปิดแถบอีก
- **เทสต์** `npx vitest run codeRuntime, codeRuntimeComposer, sessionEngineMark, codeRuntimeOptions` = 118 passed
- **ไฟล์** `desktop/frontend/src/lib/codeRuntime.ts` · `desktop/frontend/src/test/codeRuntime.test.ts`

## wails ตรงกับ CLI ในเครื่อง — `wails dev` เปิดได้โดยไม่พัง `go.sum`

- **เดิม** ตัว CLI ของ wails ที่ติดตั้งในเครื่องเป็น 2.17.1 อยู่แล้ว แต่ `go.mod` ปักที่ v2.15.0 ทุกครั้งที่สั่ง `wails dev` มันดัน `go.mod` ขึ้นเองแล้วพังที่ `go.sum` (`missing go.sum entry`) ทำให้ dev เปิดไม่ได้
- **ตอนนี้** wails v2.15.0 → v2.17.1 · go directive 1.25.8 → 1.26.0 · transitive ที่ `go mod tidy` ปรับตาม (x/net, x/sys, x/crypto, echo, goldmark ฯลฯ) ไม่มีการปักเวอร์ชันของ wails CLI ไว้เป็นเงื่อนไข
- **ตรวจ** `go build ./desktop/... ./cmd/... ./internal/...` ผ่าน · `go test ./internal/engine -run CodeAdapter|CodeRuntime|CodeCLI` ผ่าน · CI อ่านรุ่น Go จาก `go-version-file: go.mod` จึงตามเอง
- **ไฟล์** `go.mod` · `go.sum`
