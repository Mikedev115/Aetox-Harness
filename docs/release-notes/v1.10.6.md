# 🧩 Aetox v1.10.6

วันที่ 20 ตุลาคม 2026

**แชทที่ Claude Code กับ OpenCode ตอบเห็นบริบท แคช ลิมิต และไฟล์ที่แก้ได้เหมือนแชทของ Aetox · ผู้ช่วยตัดคลิปที่แนบมาได้เลย · Antigravity ใช้เครื่องมือ Aetox ได้**

## แชทที่ CLI ตอบ ไม่ใช่แชทมืดอีกแล้ว

เจ้าของ 20 ต.ค.: "บริบทหาย" · "นับถอยหลังที่ Claude เก็บแคชให้ และขีดจำกัดการใช้โมเดล" · "Claude code แก้อะไรไปไม่เห็นขึ้นเหมือนตอน Aetox ทำงานเลย" · "กดเปลี่ยนโหมดไม่ได้ รำคาญมากเวลามันขอ"

- **เดิม** แถบท้ายแชทของ CLI ว่าง ปุ่มบีบอัดบีบ transcript ของ Aetox ซึ่ง CLI ไม่เคยอ่าน ไฟล์ที่ CLI แก้ไม่ขึ้นการ์ดไฟล์ที่เปลี่ยน
  ตัวเลือกโหมดกับโมเดลกดไม่ได้ตลอดที่เทิร์นรัน และข้อความที่พิมพ์ระหว่างนั้นต้องรอ
- **รุ่นนี้**
  - แถบท้ายบอกบริบทของทั้งแชท ตัวนับถอยหลังแคช และหน้าต่างลิมิต 5 ชม. / 7 วันพร้อมเวลารีเซ็ต
    แคชเป็นค่าประมาณจาก request ล่าสุดกับชั้นแคชที่ CLI รายงาน หน้าจอบอกว่าประมาณ ตัวเลขเก็บข้ามการรีสตาร์ต
  - ถึงลิมิตแล้ว ข้อความบอกว่าติดหน้าต่างไหนและรีเซ็ตกี่โมงตามนาฬิกาผู้ใช้
  - ไฟล์ที่ CLI แก้ขึ้น +/- diff การ์ดไฟล์ที่เปลี่ยน และใบส่งงานเหมือนที่ Aetox เขียนเอง เช็กลิสต์ของ Claude Code เข้าแถบ "สิ่งที่ต้องทำ"
  - chip โหมดกดได้ตอนเทิร์นรัน Claude Code เปลี่ยนทันที ตัวอื่นเริ่มเทิร์นหน้า การ์ดขออนุญาตที่ค้างอยู่ปล่อยตัวเองถ้าโหมดใหม่ไม่ต้องถาม
    อนุมัติแผนของ Claude Code แล้วออกจาก Plan จริง chip ตามไปด้วยแสงวาบหนึ่งครั้ง ไม่มีบรรทัดในแชท
  - ตัวเลือกโมเดลก็เปิดตอนรัน Claude Code เปลี่ยนทันที effort รอเทิร์นหน้า
  - พิมพ์ข้อความระหว่างเทิร์นได้ Claude Code เอาไปต่อคิวเป็นเทิร์นถัดไป ข้อความที่ CLI รับไม่ทันกลับเข้าคิวของ composer
  - ปุ่มบีบอัดส่ง `/compact` ให้ CLI เอง และโชว์เฉพาะเมื่อ CLI เสนอคำสั่งนั้น
  - เมนู `/` ได้คำสั่งของ CLI ในโฟลเดอร์นั้นก่อนหมวดอื่น คำสั่งสำเร็จรูปมีคำอธิบาย สกิลของปลั๊กอินบอกว่าปลั๊กอินไหน
    คำสั่ง `/status` `/help` `/memory` `/doctor` ตอบเองไม่ได้ในโหมดนี้ จึงไม่เสนอ
  - เบราว์เซอร์ของ Aetox ที่ MCP ให้ถูกบอกโมเดลว่าเป็นหน้าต่างที่ผู้ใช้เห็น ไม่ใช่ fetch ของ CLI
- **OpenCode โดยเฉพาะ**
  - อ่านขนาด window ส่วนที่ prompt ใช้ได้ก่อน compact และว่าโมเดลอ่านรูปหรือ PDF ได้ไหม โมเดลค่าเริ่มต้น big-pickle ไม่รับรูป
    รูปที่แชทส่งไปเคยหายเงียบ ตอนนี้ข้อความท้ายคำตอบบอกว่ารูปถูกตัดออก
  - ไฟล์แนบส่งเป็น resource link ปุ่ม allow always ใช้ได้ คำตอบที่ถูกตัดเพราะเพดาน output บอกว่าถูกตัด
  - Stop ขอให้ OpenCode จบเอง (`session/cancel`) ก่อน kill เพราะ kill ทิ้งเทิร์นครึ่งเขียน
  - resume ไม่ replay ทั้ง session ซึ่งเคยเป็นส่วนที่ช้าที่สุดของทุกเทิร์น
  - การ์ดในตั้งค่าบอกการใช้ 7 วันที่ OpenCode นับเอง

ไม่ได้ทำ: โควตาของแพ็กเกจ ไม่มี CLI ตัวไหนบอกใน protocol การ์ดจึงแสดงเฉพาะที่ CLI นับเอง · บีบอัดบริบทของ CLI จากฝั่ง Aetox เอง

## แนบคลิปมา ผู้ช่วยตัดให้ได้เลย

- **เดิม** โต๊ะผู้ช่วยไม่ถือเครื่องมือ `cut` จนกว่าห้องตัดจะเปิด คลิปที่ลากเข้าแชทเพื่อให้ตัดจึงถูกถอดเสียงอย่างเดียว
- **รุ่นนี้**
  - โต๊ะผู้ช่วยถือ `cut_open` ซึ่งเป็นประตูที่เปิดห้อง ส่วน edit, look, render ห้องให้ยืมตอนเปิดอยู่ เหมือนเดิม
  - สคีมาของ `cut` ที่ย่อเหลือบางแอ็กชันส่งเฉพาะอาร์กิวเมนต์ของแอ็กชันนั้น เพราะสคีมา ops ของ `edit` คือเกือบทั้งเครื่องมือ
  - บรรทัดคลิปแนบบอกทางเข้าห้องตัดเฉพาะแชทที่ถือ `cut` จริง โต๊ะโค้ดไม่ได้ถือ จึงไม่ถูกบอกถึงเครื่องมือที่ไม่มี

## Antigravity ใช้เครื่องมือ Aetox ได้

- **เดิม** agy ไม่มี flag MCP ต่อเทิร์น ไม่มีช่องต่อ system prompt (หมายเหตุของ Aetox ถูกทิ้งทุกเทิร์น) และ headless ข้าม `ask_question`
  จนโมเดลเข้าใจว่าผู้ใช้ไม่ตอบ
- **รุ่นนี้**
  - เครื่องมือ Aetox ของแชทเป็น plugin `aetox` ในโฟลเดอร์ของเทิร์นที่ส่งด้วย `--add-dir` ค่าใน env ไม่ลงไฟล์
    การเรียก server ของ Aetox เองไม่ขึ้นการ์ดเพราะ bridge ถืออำนาจตัดสินอยู่แล้ว
  - ผู้ช่วยของ Aetox เป็น subagent ของ agy มีสวิตช์แชร์เครื่องมือ Aetox ในตั้งค่า
  - หมายเหตุของ Aetox ส่งเป็น rule `.agents/rules/aetox-N.md` ในโฟลเดอร์เทิร์น งาน one-shot (ข้อความ commit, จัดกลุ่ม) จึงไม่วิ่งโดยไม่มีคำสั่งอีก
  - คำถามของ agy ขึ้นการ์ดคำถามเดียวกับ Claude Code
  - แถวบัญชีบอกว่าจ่ายด้วยอะไร (บัญชี Google, API key หรือ cloud) อ่านแค่ชื่อกับ flag ไม่อ่าน credential
  - ตั้งค่าบอกเมื่อมี agy รุ่นใหม่ (อ่านจาก CHANGELOG ของ agy เอง ไม่ต่อเน็ต) และมีปุ่มอัปเดต เพราะ Aetox ปิดตัวอัปเดตของ agy ทุกรอบที่สั่งเอง
    คนที่ไม่เคยรัน agy เองจึงค้างที่ 1.3.3 ทั้งที่ 1.4.2 ออกแล้ว

## เปิดห้องที่ยังไม่อยู่บนโต๊ะ และปุ่ม ดู ไม่เปิดแท็บซ้ำ

- **เดิม** สั่ง "เปิดหน้าอัดเสียงให้ที" แล้วไม่มี tool ไหนเปิดห้องเปล่าได้ ผู้ช่วยไปขับหน้าต่างผ่าน UI Automation 7 รอบแล้วค้าง
  จาก 15 ห้อง เปิดได้เต็มแค่ 2 และปุ่ม ดู บนการ์ดหน้าเว็บเปิดแท็บใหม่ทุกครั้ง กดสามทีได้สามแท็บของหน้าเดียวกัน
- **รุ่นนี้**
  - `desk room` เปิดห้องที่หน้าต่างบอกว่าตัวเองเปิดให้ได้ (รายชื่อเดียวกับปุ่ม + และการ์ดห้อง) `desk list` พิมพ์บรรทัด rooms
    แชทที่ไม่ได้อยู่บนจอ ห้องไปรอบนโต๊ะที่เก็บของแชทนั้น
  - `meeting new` เปิดหน้าอัดใหม่ตั้งชื่อจากแชทได้ ไม่เริ่มอัดและไม่แตะไมค์ ถ้ามีประชุมกำลังอัดอยู่จะยกแท็บนั้นขึ้นมาแทน
  - ปุ่ม ดู ยกแท็บเบราว์เซอร์เดิมที่เปิด address นี้อยู่ขึ้นมา ใช้ทั้งกับไฟล์และ `openUrlInWorkbench`
