# 🪟 Aetox v1.11.26

วันที่ 19 พฤศจิกายน 2026

รุ่นนี้เก็บงานจากการใช้งานจริงสองด้าน — การสลับโต๊ะที่เคยค้างทุกครั้งกับการกลับเข้าแชทที่ต้องยิงอ่านทีละคำสั่ง และมือถือที่เห็นสิ่งที่คอมเห็น (สถิติ เครื่องนี้ MCP สกิล adapter) โดยหน้าจอแยกกันแทนที่จะยัดในชีตเดียว

## สลับโต๊ะจบในคำสั่งเดียว และกลับแชทเดิม 2 คำสั่ง จาก 14

- **เดิม** กดสลับโค้ด → ผู้ช่วยเท่ากับเปิดแชทใหม่สามครั้ง (`newSessionAt` สร้างแชทที่โต๊ะปลายทาง, `clearProjectFocus` สร้างอีกครั้งเพื่อถอดโปรเจกต์) และขาเข้าถึงของทั้งสองรอบอ่านสถานะกลับทีละคำสั่ง — model, desk, chair, team, transport, space, stance, quality, ห้ารายการ, tree, git — หน้าจึงค้างทุกครั้งที่สลับ
- **ตอนนี้** `OpenDoor` ตัดสินเรื่องโปรเจกต์และเกิดแชทในคำสั่งเดียว แล้วตอบ `SessionOpenState` ชุดเดียวกับ `OpenSession` · `startNewSessionAt` สร้างแชทที่โต๊ะปลายทางด้วย bootstrap ครั้งเดียว และโต๊ะที่ถูกปฏิเสธไม่ทิ้งแชทใหม่ไว้ข้างหลัง
- **ขาเข้าถึง** `SessionOpenState` พา tail ของแชทมาด้วย (Spend, Plan, PlanReports, TaskChips, BackgroundTasks, BackgroundRuns, Watches) UI จึงไม่ต้องยิงอ่านซ้ำ · tray poll เริ่มเฉพาะเมื่อมีงานวิ่งอยู่ · วัดบน dev: สลับโค้ด→ผู้ช่วย 372 ms, ผู้ช่วย→โค้ด 420 ms, ไม่มี error ใหม่บนหน้า
- **ตัวเลข** `doorReturn` นับคำสั่งจริง: กลับแชทเดิมจาก 14 → 2 และกดสลับแล้วเปิดแชท = 9 round trip
- **ไฟล์** `internal/engine/sessions.go` · `desktop/frontend/src/lib/stores/cockpit.svelte.ts` · `internal/engine/open_door_test.go`

## มือถือ — สิ่งที่คอมเห็น ขึ้นบนมือถือ

- **ปุ่มเดียวเปิดเมนู** ปุ่มกราฟเปิดสี่รายการ (แชทนี้ · เครื่องนี้ · การใช้งาน · External Adapters) และ MCP/สกิลเข้าลิสต์เมนูซ้าย · แต่ละหน้าโหลดเฉพาะตอนเปิด ไม่ poll · การใช้ทั้งเครื่องออกจากชีตแชท เหลือตัวเลขของแชทกับเครื่องนี้
- **หน้าสถิติเต็ม** `/api/usage` เป็นต่อโมเดล + ค่าใช้จ่าย · `/api/machine` เป็นดิสก์ทุกตัว/การ์ดจอ/uptime · adapter ลดข้อมูลบน PC ก่อนส่ง มือถือไม่ต้องรับตารางหรือ heatmap 53 สัปดาห์
- **หน้าตั้งค่าเป็นสารบัญ** เปิดด้วยการ์ดสถานะ (เครื่องไหน เชื่อมต่อไหม เห็นกี่แชท) แล้วแยกค่าที่เป็นของมือถือเอง (ธีม ภาษา การแจ้งเตือน เสียง เวอร์ชัน/อัปเดต) ออกจากรายงานจาก PC ห้าหน้าที่อ่านอย่างเดียว · ค่าที่ต้องแก้บน PC ไม่ขึ้นเป็นแถวที่กดไม่ได้
- **ชีตโมเดลสามแถว** ผู้ให้บริการ · โมเดล · ระดับความคิด แบบเดียวกับเดสก์ท็อป — รายชื่อทั้งแคตตาล็อกของเจ้านั้น (เดิมเห็นแค่ 2 ตัวที่ติดดาว จาก 184) พร้อมช่องค้นหาเมื่อเกิน 8 รายการ และซ่อนแถวที่ไม่มีความหมายเมื่อมีเจ้าเดียว
- **แถบบนบอกโต๊ะ** ชื่อโต๊ะเป็นบรรทัดหลัก ชื่อแชทเป็นบรรทัดรอง และชิปเหนือกล่องพิมพ์เหลือเฉพาะสิ่งที่ยังต้องเลือก — เลิกบอกโต๊ะซ้ำสองที่ในจอเดียว
- **สลับโต๊ะได้ทุกเมื่อ** เดิมปุ่มสลับไม่ทำอะไรขณะมีแชทเปิด แชทใหม่จึงเกิดเป็นโหมดโค้ดด้วย key โฟลเดอร์ที่เครื่องนั้นไม่ได้รับสิทธิ์ แล้วส่งอะไรกลับไปที่ PC ไม่ได้เลย · ตอนนี้ settleDesk ตรวจ key กับรายการโฟลเดอร์จริงก่อนสร้างแชท และกล่องพิมพ์บอกว่าแชทใหม่จะเป็นโต๊ะไหน
- **โหมดครบสี่ตัว** (เพิ่ม มุ่งเป้า) พร้อมคุณภาพและสิทธิ์ของแชทใหม่ และมือถือรองรับสามภาษา (เพิ่มจีน) ครบ 359 คีย์
- **มือถือเลือก CLI runtime ให้แชทได้** ผ่าน `MobileSetAdapter` — API ใหม่อีกสี่ตัว (`/api/mcp`, `/api/skills`, `/api/adapters`, `/api/adapter`) เรียก engine ตามชื่อผ่าน allowlist และปฏิเสธระหว่างเทิร์นรัน
- **ไฟล์** `internal/mobilelink/extras.go` · `internal/engine/mobile_options.go` · `mobile/src/components/{StatsMenu,UsagePage,MachinePage,McpPage,SkillsPage,AdaptersPage,Settings,ModelSheet}.svelte`

## การ์ด context — แถว MCP ขึ้นแม้เครื่องมืออยู่บนชั้นวาง

- **เดิม** แชทที่มีเซิร์ฟเวอร์ MCP ถูกกันนิยามไว้บนชั้นวางเห็นแต่บรรทัด "MCP อีก 6 ตัวอยู่บนชั้นวาง" โดยไม่มีแถว MCP ให้อ่าน จึงอ่านได้ว่าหมวด MCP หายไป — engine ส่ง slice `mcp` ที่ 0 โทเคนมาโดยเจตนา แต่ UI กรอง slice ที่ 0 ออกทั้งแถว
