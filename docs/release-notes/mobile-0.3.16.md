## มีอะไรใหม่ (มาจาก Aetox บน Windows 1.11.32)

- **ช่วงงานถูกพับเหมือนเดสก์ท็อป** เปิดแชทโค้ดยาว ๆ (50 ช่วงงาน, tool 184 ครั้ง) เดิมเห็น prose ของทุกช่วงกางเต็มต่อด้วยข้อความตอบจบ เป็นกำแพงข้อความ ขณะที่เดสก์ท็อปยุบช่วงที่จบแล้วเหลือบรรทัดเดียว — ตอนนี้สัญญา `mobilelink` ส่งเลขช่วงมา (`Step.Phase`, `Part.Phase/Secs/Open`, `Message.Tools`) และ `mobilePhases` ตัดเทิร์นจุดเดียวกับเดสก์ท็อป (`turnPhases.ts phasesOf`): ประโยคหรือคำผู้ใช้เปิดช่วง, tool ที่ตามมาเป็นของช่วงนั้น, คำตอบคือทุกอย่างหลังงานชิ้นสุดท้าย · ช่วงที่จบยุบรวมเป็นบรรทัดเดียว กดแล้วได้บรรทัดละช่วง กดอีกทีเห็นประโยคและรายการเครื่องมือของช่วงนั้น · คำพูดผู้ใช้กลางเทิร์นไม่พับ · เทิร์นที่ PC ยังไม่ส่งเลขช่วงยังวาดแบบเดิม
- **พับ/กางค่อย ๆ และแสงวิ่งบนคำที่ยังไหล** เดิมกดพับ/กางแล้วกระตุกฉับ (slide เดสก์ท็อปใช้ cubicOut ทั้งเข้าและออก) และตอนคำไหลมาไม่มีอะไรบอกว่ากำลังมา หน้าจอนิ่งเหมือนค้าง — ตอนนี้ fold = 220 ms cubicInOut พร้อมการ์ด reduced-motion, ลูกศรพับหมุน 90° ด้วย transition แทนการสลับไอคอน และมีแสงวิ่งเฉพาะบล็อกที่ยังไหล (มี `@supports` กันข้อความหาย และ `@media` reduced-motion ให้เหลือสีปกติ) · วัดในพรีวิว: `background-position` 105.66% → 35.69% ใน 700 ms, ตอนพับรายการ 51px → 45px@70ms → 1px@190ms แล้วถูกถอด
- **คลิปและเสียงใหญ่เล่นได้** เพดาน 16 MiB เดิมไม่ใช่ข้อจำกัดของมือถือ แต่เป็นผลจากการที่ engine ถือไฟล์ทั้งก้อนในหน่วยความจำ ไฟล์ 21.2 MB จึงถูกปฏิเสธก่อนยิง request และปุ่ม "บันทึก" ก็วิ่งเส้นเดียวกัน — ตอนนี้ engine เสิร์ฟไฟล์จาก handle ที่ตรวจแล้วด้วย `http.ServeContent` (Range/206) gateway เป็น reverse proxy ไปที่นั่น มือถือเล่นวิดีโอ/เสียงจาก URL ตรง ๆ และ seek ได้โดยไม่ต้องโหลดครบ · ตัวดูไฟล์เลือกรูป/คลิป/เสียงจาก `fileURL` ไม่สร้าง Blob และซ่อนปุ่มแชร์เมื่อไฟล์ใหญ่เกินเพดานที่ยังโหลดทั้งก้อน
- **เริ่มแชทด้วยโหมด "เป้าหมาย" ได้** เดิมด่านฝั่ง PC (`ValidOptions`) ยอมรับแค่ plan/consult/act ทำให้การส่งที่เลือก "เป้าหมาย" จากชีตถูกปฏิเสธก่อนถึงเอนจิน ตอนนี้ `goal` ผ่านด่านและมีเทสต์บังคับว่าทุกชื่อที่ตัวเลือกบนโทรศัพท์เสนอต้องผ่าน
