# 🪟 Aetox v1.10.20

วันที่ 27 ตุลาคม 2026

**หน้า MCP server เหลือสองโซนด้วยแถวเดียวที่บอกสาเหตุบนแถวเอง ชีตยกสาเหตุขึ้นก่อน error ดิบ · batch แก้ไฟล์รับ `all` ต่อรายการ · และข้อความ find ไม่ตรงบอกบรรทัด ตัวอักษร และ codepoint ที่ต่าง**

## หน้า MCP server เหลือสองโซน และแถวเดียวใช้ทั้งหน้า

- **เดิม** หน้าเดียวกันมีห้าแบนด์ที่หน้าตาไม่เหมือนกัน — ไทล์ของที่ติดตั้งแล้ว · ห้องสมุด · ที่เจอในแอปอื่น · ทะเบียน · มาใหม่ — สามแบบแถวกับสามคำกริยาสำหรับการกระทำเดียว และทุกแบนด์พูดประโยคเดียวกันว่า "ของที่ยังไม่เปิด" ส่วนเหตุผลที่เซิร์ฟเวอร์ตัวหนึ่งต่อไม่ได้อยู่ในชีตเท่านั้น
- **รุ่นนี้** เหลือสองโซน: `capability.zoneMine` (เซิร์ฟเวอร์ของคุณ) กับ `capability.zoneFind` (หาเพิ่ม) และทุกแหล่งใช้แถวเดียวที่ `data-src` บอกว่ามาจากไหน
- **แถวของเซิร์ฟเวอร์ที่ติดตั้ง** (`serverRow`) มีสี่อย่าง: ตราและชื่อ · ข้อเท็จจริงที่ตัดสินแถว · ปุ่มที่ต้องกด · ประตูไปชีต ตัวที่ต้องแก้ขึ้นบนสุดด้วย `installedRank` (พัง → รอเข้าสู่ระบบ → ปกติ → ปิด) เรียงผ่าน `orderedInstalled`
- **สาเหตุมาอยู่บนแถว** แถวที่ทดสอบไม่ผ่านแสดง `humanErr(s.err)` หรือ `capability.rowNeedsConn` เมื่อคีย์มาจากการเชื่อมต่อที่ยังไม่ได้เชื่อม พร้อมปุ่มที่พาไปที่ที่แก้นั้น (`openCapabilityAt('connections', …)`) ไม่ต้องเปิดชีตก่อนจึงจะรู้ว่าพังเพราะอะไร
- **หาเพิ่มเป็นรายการเดียว** ช่องค้นหาเดียว แล้วชิป `findChips` แยกแหล่ง: ทั้งหมด · เพิ่มได้เลย · ต้องเข้าสู่ระบบ · เจอในเครื่องนี้ · มาใหม่สัปดาห์นี้ ต่างกันที่ชิปต้นทาง (`capability.srcShelf` · `srcHere` · `srcRegistry`) ไม่ใช่ที่รูปร่างแถว
- **ชิปที่ตอบศูนย์แถวไม่ถูกเสนอ** `findChips` ตัดชิปที่ไม่มีของในหมวดที่เลือกอยู่ และไทล์หมวด (เดิม) ยังเป็นการเข้าห้องสมุดเมื่อยังไม่ได้เลือกหมวดและยังไม่ได้พิมพ์อะไร
- **ตัวเลขบนชิปนับตามที่หน้านั้นแสดงจริง** `findTotal` รวมแหล่งอื่นก็ต่อเมื่อยังไม่ได้เลือกหมวด (ผู้ทดสอบ 27 ต.ค. 2026 เห็น "ทั้งหมด 51" ข้างแถวแปดแถว) และ `findEmpty` ไม่พูดว่า "ต่อครบทุกตัวแล้ว" ใต้ไทล์หมวด เพราะไทล์ไม่ใช่รายการ
- **ทำไมเลือกทางนี้** ห้าแบนด์ตอบคำถามเดียวกันว่าอะไรยังไม่อยู่บนเครื่อง คำตอบที่ต่างกันคือคำตอบที่คนอ่านต้องแปลเองทุกครั้ง — และแถวเดียวทำให้แถวที่พังใช้ที่ทางเดียวกับแถวที่ใช้ได้
- ยังใช้ `pageWindow` จำกัดจำนวนแถวที่วาด (`winShelf` ตัวเดียว แทนที่จะเป็น `winShelf` + `winSignIn` แยกกัน) ตามกฎใน `AGENTS.md`

## ชีตของเซิร์ฟเวอร์: สาเหตุขึ้นก่อน แล้วค่อย error ดิบ

- **เดิม** แท็บอยู่กลางชีต สถานะเป็นแถวหนึ่งใต้หัว และประโยคสาเหตุ (`not signed in to github`) อยู่ท้ายกองแดงสี่บรรทัด ใต้รายละเอียดทางเทคนิค
- **รุ่นนี้** แท็บขึ้นไปอยู่ใต้หัว สถานะเป็นเม็ดที่หัวข้างชื่อ (`cap-st` ทุกแท็บเห็น) และเนื้อหาเริ่มด้วยบล็อก `.cap-fix` ที่บอกสาเหตุเป็นประโยค (`capability.sheetCauseConn` / `sheetCauseSignIn`) ตามด้วยคำอธิบายว่าทำไมและแก้อะไร (`sheetWhatConn` / `sheetWhatSignIn` / `sheetWhatGeneric`) ปุ่มที่แก้ และ `<details class="cap-fix-raw">` ที่พับ error ดิบไว้ข้างใน (`capability.sheetRawDetail`)
- **บล็อกนั้นอยู่เหนือเนื้อหาของทุกแท็บ** ไม่ใช่ในแท็บใดแท็บหนึ่ง เพราะปัญหาเป็นของเซิร์ฟเวอร์ และแท็บเครื่องมือทั้งแท็บพูดเรื่องเดียวกันคือ "ต่อไม่ได้"
- **ท้ายชีตเหลือปุ่มหลักปุ่มเดียวทางขวา** บันทึก/เพิ่มเป็น `ctrl-primary` ชิดขวา ส่วนลบเป็น `ctrl-danger` ชิดซ้ายสุด ห่างจากมือที่เอื้อมไปกดบันทึก และ `capability.mcp.ask_btn` / `pause_btn` อยู่ข้างลบ
- **ทำไมเลือกทางนี้** คำถามที่คนเปิดชีตมาถามคือ "ทำไมตัวนี้ไม่ทำงาน" คำตอบจึงต้องอยู่ก่อนรายละเอียด ไม่ใช่หลังมัน
- ปุ่มทดสอบยังมีที่อยู่บนแถวและในบล็อกสาเหตุ เพราะ "ยังใช้ได้ไหม" เป็นคำถามที่ต่างจาก "ทำไมพัง"

## batch แก้ไฟล์รับ `all` ต่อรายการ และ find ที่ไม่ตรงบอกตำแหน่งอักขระ

- **เดิม** `editItem` ใน `internal/skill/edits.go` ไม่มีฟิลด์ `All` และสคีมาของ `batch` ไม่ได้ประกาศ `all` เลย สิ่งที่โมเดลส่งมาจึงถูกทิ้งเงียบ ๆ และข้อความปฏิเสธบอกแค่ "matches N times … add surrounding lines to make it unique" ทั้งที่ทางออกคือธงที่ถูกเมิน
- **รุ่นนี้** `editItem.All` มีจริง ประกาศในสคีมาทั้งของ `edits.go` และ `change_pack.go` ข้อความ "find ไม่ตรง" ไม่มีอีกแล้ว: การแมตช์ซ้ำจะบอกชื่อ `all=true` พร้อมจำนวน occurrence ที่จะเปลี่ยน
- **`all` ระดับ call ถูกปฏิเสธโดยบอกที่ที่มันควรอยู่** ไม่ใช่เมิน — flag ที่ไม่มีใครอ่านแย่กว่า flag ที่ผิด
- **ผลลัพธ์บอกจำนวนที่เปลี่ยนจริง** `applied N edits (M occurrences) to F files` เมื่อ `all` ทำงานมากกว่าหนึ่งจุด และหลัง edit ที่ `all=true` จะไม่ใช้ `placeAfter` เดาจุดให้ edit ถัดไปในไฟล์เดียวกัน เพราะไฟล์ไม่มี "จุดสิ้นสุด" จุดเดียวแล้ว (`inOrder=false`)
- **find ไม่ตรงบอกบรรทัด ตัวอักษร และ codepoint** `differsAfterLine` ใน `internal/skill/lineendings.go` เทียบบล็อกทั้งก้อนจากบรรทัดที่ตรงกัน แล้วบอกว่าต่างที่บรรทัดไหน ตัวอักษรที่เท่าไร ข้อความสองฝั่งคืออะไร และ `charLabel` ให้ codepoint ของทั้งสองตัว — พร้อมชื่อสำหรับอักขระที่มองไม่เห็น (`invisibleNames`: NO-BREAK SPACE, ZERO WIDTH SPACE, BYTE ORDER MARK ฯลฯ)
- **ไม่มีบรรทัดไหนตรงเลยก็ยังมีที่ให้ดู** `closestLine` เสนอบรรทัดที่ใกล้ที่สุดพร้อมตัวอักษรที่ต่าง และเงียบเมื่อตรงกันไม่ถึงแปดตัวอักษร เพราะห้าตัวอย่าง `func ` ชี้ไปที่ทุกฟังก์ชันในไฟล์
- **ทำไมเลือกทางนี้** ความต่างที่ตกมาถึงข้อความ "compare from line 87 down" คือตัวที่หน้าตาเหมือนกัน — `desks.ts` บรรทัด 88 ที่ `"):` อ่านกลับมาเป็น `...":` กลางประโยคไทย — ตาที่พลาดครั้งแรกจะพลาดครั้งที่สอง การบอกตำแหน่งอักขระจึงเป็นคำตอบเดียวที่ทำอะไรได้
- นับเป็นตัวอักษรไม่ใช่ไบต์ (`runeColumn`) เพราะบรรทัดไทยนับตัวอักษรแบบที่คนอ่านนับ และออฟเซตไบต์จะชี้เข้าไปกลางตัวอักษร ส่วน `window` ตัดบริบทไว้ 24 ตัวอักษรสองข้าง
- `all` อยู่ที่แต่ละรายการ ไม่ใช่ทั้ง call เพราะ batch ที่เปลี่ยนทุกจุดของ find หนึ่งและจุดเดียวของอีกอันคือสองเจตนา และเทียบกับ harness อื่นในเครื่อง (Claude Code, Codex, OpenCode, Crush, Pi) แล้วทุกตัวประกาศ replace-all ไว้ในสัญญาของ tool — เป็นการเข้าที่มาตรฐานที่มีอยู่ ไม่ใช่ของใหม่

## รอบที่ไม่บอกการแบ่ง cache ไม่ทำให้ยอดทั้งห้องขึ้นว่าไม่ทราบ

- **เดิม** `cacheComplete` เป็น false แล้วแผงยอดใช้จ่ายขึ้น "ไม่ทราบ" ทั้งก้อน ทั้งที่อินพุตส่วนใหญ่ถูกวัดไปแล้ว (9router + Antigravity, 27 ต.ค. 2026: 1 รอบจาก 24 ทำให้ 207k ของอินพุต 271k หายไปจากหน้าจอ)
- **รุ่นนี้** อินพุตของรอบที่ผู้ให้บริการบอกจำนวนโทเคนแต่ไม่บอกการแบ่ง cache ถูกนับแยกเป็นด้านที่สาม ไม่ใช่ถูกเติมเข้าฝั่ง miss และไม่ใช่ปิดทั้งแผง
- **ที่เก็บค่า** `SessionSpend.CacheUnknown` (`internal/engine/usage.go`) นับจาก `CacheUnknownTokens` ของแต่ละรอบ · `cacheUnknown` ใน `TurnSpend` และ `emptyTurnSpend` (`types.ts`) · `applyUsageRound` (`stores/cockpit.svelte.ts`) บวกอินพุตของรอบที่ไม่รายงาน (`round.cacheReported !== true`)
- **ที่แสดงผล** `Chat.svelte` คำนวณ `measuredIn = in − cacheUnknown` แล้ว miss = `measuredIn − cached` เปอร์เซ็นต์คิดจาก `measuredIn` และเพิ่มบรรทัด `chat.cacheUnaccounted` ที่บอกจำนวนโทเคนที่อยู่นอกการแบ่งเป็นตัวเลข
- **เปอร์เซ็นต์ยังไม่แสดงเมื่อการแบ่งไม่ครบ** และเอนจินรุ่นเก่าที่ไม่มีฟิลด์นี้ยังขึ้น "ไม่ทราบ" ตามเดิม เพราะไม่มีตัวเลขที่บอกได้ว่าขาดเท่าไร
- **ทำไมเลือกทางนี้** การเติมอินพุตนั้นเข้าฝั่ง miss คือการรายงานตัวเลขที่ผู้ให้บริการไม่เคยบอก และการปิดทั้งแผงเพราะรอบเดียวก็เช่นกัน — อินพุตที่บอกไม่ได้ว่าอยู่ฝั่งไหนควรถูก set aside ไม่ใช่ทำให้ที่เหลือสูญหาย

## คลังสตูดิโอเหลือโฟลเดอร์ที่ผู้ใช้เพิ่ม

- **เดิม** ไบนารีบรรจุชุดเสียง Kenney Interface Sounds 100 ไฟล์ พร้อมแค็ตตาล็อก 1,502 บรรทัดและใบอนุญาต แล้วแตกไฟล์ลง data root ของทุกเครื่อง `studioShelves` วางคลังในตัวไว้หน้าคลังของผู้ใช้เสมอ
- **รุ่นนี้** `internal/assetlib/builtin.go` กับไฟล์เสียง แค็ตตาล็อก และใบอนุญาตถูกถอดออกจากทรัพยากรในตัว `studioShelvesWith` เหลือคลังของผู้ใช้ในลำดับที่เขาเพิ่มเข้ามา
- **สถานะที่หน้านั้นพูดตอนนี้เป็นความจริงของเครื่องนั้น** `studioReady` และ `asset_find` รายงาน "คลังสตูดิโอยังว่าง" พร้อมที่ทางไป ตั้งค่า → คลังสตูดิโอ เมื่อยังไม่มีโฟลเดอร์ใดถูกเพิ่ม แทนที่จะขึ้น "ok" ทุกเครื่องเพราะมีของที่ติดมากับโปรแกรม
- **`Library.Builtin` ยังอยู่ในรูปร่างของ store** พร้อมคำอธิบายใหม่ว่า Aetox ไม่มีคลังที่ติดมากับไบนารีแล้ว แต่ field ยังอยู่เพื่อให้คลังที่ ship ในอนาคตอ่านเหมือนเดิม
- **ทำไมเลือกทางนี้** ทรัพยากรที่บรรจุไว้ลดลง และหน้าสตูดิโอ เครื่องมือค้นหาสื่อของเอเจนต์ กับแถวความพร้อม พูดถึงชุดเดียวกันได้ในที่สุด

## เลือกหลายไฟล์ในหน้าสตูดิโอ

- **เดิม** การซ่อนหรือเพิ่มไฟล์เข้าคลังทำได้ทีละไทล์ผ่านเมนูของไทล์นั้น คลังที่มีเสียงเป็นร้อยจึงต้องกดร้อยครั้ง
- **รุ่นนี้** ปุ่ม `settings.studioPickMode` เปิดโหมดเลือก (`aria-pressed` บอกสถานะ) ไทล์แต่ละอันมีช่องทำเครื่องหมาย `.sb-pick` ที่มุมภาพ และกรอบ `.picked` บอกสิ่งที่กำลังจะถูกซ่อน
- **แถบเดียวทำงานทั้งชุด** `.sb-bulk` แสดงจำนวนที่เลือก พร้อม "ใส่ในโปรเจกต์" (`usePicked` → `StudioCopyAsset`) · "ซ่อนที่เลือก" (`hidePicked` → `StudioSetHidden`) · เลือกทั้งหมด · ล้าง
- **ที่เลือกไม่ตามข้ามบริบท** การเปลี่ยนตัวกรองหรือหน้า และการกด Escape ล้างที่เลือกและออกจากโหมด เพราะสิ่งที่ติ๊กไว้เป็นของแถวที่อยู่บนจอตอนนั้น
- **ทำไมเลือกทางนี้** store ถูกอ่าน–เขียนทั้งก้อน คำสั่งจึงวิ่งทีละ id ตามลำดับ ไม่ยิงพร้อมกัน (จะทับคำตอบกันหนึ่งอัน) แล้วโหลดรายการใหม่ครั้งเดียว ถูกกว่าการแก้สี่สิบแถวในหน่วยความจำ และเป็นตัวเลขชุดเดียวกับที่ยอดรวม โฟลเดอร์ และการเรียกครั้งถัดไปของเอเจนต์อ่าน
- การกดบนไทล์ในโหมดเลือกคือการติ๊ก ยกเว้นที่ปุ่มเล่น เส้นทาง และเมนู ซึ่งยังทำงานของตัวเอง ส่วนช่องทำเครื่องหมายเป็นทางที่คีย์บอร์ดเข้าถึงได้

- ชิปของหน้า MCP ใช้ `.cap-chip` กับ `.cap-lines`/`.cap-srow` ชุดใหม่ใน `style.css` และแถวเปลี่ยนเป็นหนึ่งคอลัมน์เมื่อแถวกว้างต่ำกว่า 620px (`@container`) ไม่ใช่เมื่อหน้าต่างแคบ เพราะรางข้างของห้องกินที่ไป 180–360px
- `setShelfFilter` และ `winSignIn` ถูกถอดออกจาก `Capability.svelte` — ทั้งตัวกรองหมวดและตัวกรองแหล่งผ่าน `setFindSource` ที่เดียว
- tests ที่เพิ่มในรุ่นนี้: `edits_test.go` (`TestEditsAllChangesEveryOccurrence`, `TestEditsAmbiguityNamesTheAllFlag`, `TestEditsRefusesAllOnTheCallInsteadOfEachEdit`, `TestEditsDoesNotPlaceARepeatAfterAnAllEdit`) · `lineendings_test.go` (`TestNoMatchNamesTheFirstCharacterThatDiffers`, `TestNoMatchNamesAnInvisibleCharacter`, `TestNoMatchStaysQuietWhenNoLineIsClose`) · `studioBrowser.test.ts` (เลือกหลายไทล์แล้วซ่อนในครั้งเดียว)
- tests ที่ปรับให้ตรงของจริง: `capabilityRoom.test.ts` เพิ่มการตรวจไทล์หมวด การแบ่งชิปตามชนิด และการย้อนกลับจากหมวด · `sessionSpend.test.ts` กับ `turnSpend.test.ts` เพิ่มการนับโทเคนที่ไม่ทราบค่า cache · `capabilityLoad.test.ts`, `mcpSheetWho.test.ts`, `installCard.test.ts` ปรับ selector ตามหน้าตาใหม่โดยไม่ได้ลดความเข้มของ assertion · `mocks/wailsApp.ts` เพิ่ม `StudioCopyAsset` · `assetlib_test.go` ลบเทสต์ของคลังในตัวที่ไม่มีแล้ว · `studio_browse_test.go` สร้างคลังตัวอย่าง 60 ไฟล์เองแทนที่จะนับจากชุดในตัว · `param_names_test.go` อัปเดตรายการชื่อพารามิเตอร์ที่พินไว้เป็น `all`
- `Settings.test.ts` แก้ชื่อหัวข้อคู่มือเป็น "เกี่ยวกับ Aetox Harness" ให้ตรงกับหัวข้อที่แอปแสดงจริง
