# 🪟 Aetox v1.10.31

วันที่ 30 ตุลาคม 2026

**ร้อนแก้สามข้อในรุ่นนี้ — Ctrl+V ในช่องแชทวางได้ทุกชนิดอีกครั้ง แถวโมเดลกลับมาอ่านออกว่าเป็นโมเดลไหน และสวิตช์แจ้งเตือนของบอทแสดงตรงกับค่าจริงแล้ว**

## แชท: Ctrl+V วางได้ทุกชนิด ไม่ใช่ไม่ได้เลย

- **สาเหตุ** ฝั่ง Windows คืน `[]string(nil)` เมื่อคลิปบอร์ดไม่มีไฟล์อยู่ข้างหลัง JSON ทำให้ค่านั้นกลายเป็น `null` แล้วโค้ดฝั่งจออ่าน `.length` ของมัน — โยนข้อผิดพลาดออกมาหลังจากที่ `preventDefault` ตัดการวางปกติไปแล้ว ผลคือ **กด Ctrl+V แล้วไม่มีอะไรเกิดขึ้นเลย ทุกชนิด** ทั้งภาพแคปเจอร์ ไฟล์ และข้อความ ตั้งแต่รุ่น v1.10.30
- **แก้ที่ต้นเหตุ** ฝั่ง Windows คืนลิสต์ว่าง `[]` เสมอ ไม่คืน nil อีก คำตอบ «ไม่มีไฟล์บนคลิปบอร์ด» จึงเป็นลิสต์ว่างจริง ๆ ตามที่ฝั่งจอคาดไว้
- **กันไว้อีกชั้นฝั่งจอ** ค่าที่ไม่ใช่ลิสต์ถือว่า «ไม่มีไฟล์» และเส้นทางไบต์ของภาพถูกเรียกต่อได้แม้ตัวอ่านรายการไฟล์จะล้ม การวางภาพแคปเจอร์จึงไม่ตายเพราะของที่มาไม่ครบ
- **การวางที่ไม่พบไฟล์ยังไม่นับเป็นข้อผิดพลาด** ไม่มีข้อความรบกวนบนแชท และระหว่างที่โปรแกรมอื่นถือคลิปบอร์ดอยู่จะลองสั้น ๆ ไม่กี่ครั้งแล้วเงียบเหมือนเดิม

## โมเดล: ชื่อค่ายกลับมาอยู่ในชื่อโมเดล

- **สาเหตุ** v1.10.30 ตัดคำของบริษัทที่ติดอยู่ต้น id ออกด้วย (`mimo-`, `deepseek-`, `claude-`) ตามคำสั่ง «ตัดชื่อบริษัทข้างหน้าออก» ซึ่งกว้างเกินกว่าที่ตั้งใจ แถวจึงเหลือ `v2.6-pro` กับ `v4.1-flash` — ชื่อที่ไม่มีอะไรบอกได้ว่าเป็นโมเดลไหน (เจ้าของ 30 ต.ค. 2026: "ชื่อโมเดลก็ขึ้นแค่ v4.1-flash")
- **ตอนนี้ตัดเฉพาะส่วนนำหน้าถึง `/`** คือชื่อเส้นทางของเกตเวย์ (`anthropic/`, `cc/`, `xiaomi/`, `deepseek/`) ส่วนคำของค่ายที่ติดอยู่ใน id อยู่ครบ: `mimo-v2.6-pro` · `deepseek-v4.1-flash` · `claude-haiku-5-5`
- **รูปที่เขียนด้วยจุดยังตัดได้** `anthropic.claude-haiku-5-5` คือวิธีที่ Bedrock เขียนส่วนของค่ายเดียวกัน จุดไม่เคยอยู่ต้นชื่อจริงของโมเดล จึงตัดหัวถึงจุดได้
- **สิ่งที่เหลือต้องขึ้นต้นด้วยตัวอักษรและมีเลขรุ่น** กันไม่ให้เหลือ `pro` หรือ `4-argon` ที่ไม่บอกอะไรเลย
- **id ยังเป็นสัญญากับผู้ให้บริการ** ส่งกลับตามเดิมทุก lookup ยังคีย์ด้วย id สิ่งที่เปลี่ยนคือคำที่คนอ่านในแถว และช่องค้นหายังค้นได้ทั้งชื่อที่เห็นกับ id

## ช่องทาง: สวิตช์แจ้งเตือนของบอทตรงกับค่าจริง

- **สาเหตุ** ฟิลด์ `channel_notices_off` ประกาศด้วย `omitempty` ค่า `false` จึงหายไปจาก JSON ที่เอนจินส่งมา หน้าจอไม่ได้รับคำตอบเรื่องนี้เลยและคงค่าปิดที่มันถืออยู่ — เปิด «บอททักเมื่อคุณไม่อยู่» ไว้แล้วบอทยังส่งข้อความไป และหน้าจอยืนยันว่าปิด (เจ้าของ 30 ต.ค. 2026: "ผมปิดไม่ให้ส่งข้อมูลไปเทเลแกรมตอนผมไม่อยู่ ทำไมมันยังส่งไป")
- **แก้ที่ต้นเหตุ** ถอด `omitempty` ออก `false` จึงเดินทางมาถึงหน้าจอเสมอ หน้าจอไม่ต้องเดาว่า «ไม่มีฟิลด์» แปลว่าปิด
- **สวิตช์ไม่ค้างเป็นปิดเมื่อเขียนค่าไม่สำเร็จ** เดิมเมื่อบันทึกค่าไม่ผ่าน สวิตช์ค้างเป็นปิดทั้งที่ค่าเดิมยังเปิดอยู่ ตอนนี้สวิตช์กลับไปตามค่าที่แถวถืออยู่ พร้อมข้อความบอกเหตุ จอจึงอ่านว่าเงียบทั้งที่บอทยังพูดไม่ได้อีก

## ความมั่นใจของรุ่น

- เพิ่มเทสต์ฝั่ง Windows 1 ข้อที่ยืนยันว่า `channel_notices_off` ติดไปกับ JSON ทั้งตอนเป็น `true` และ `false` และเพิ่มเทสต์หน้าจอ 1 ข้อที่ให้เอนจินปฏิเสธการเขียนค่า สวิตช์ต้องกลับมาเปิดพร้อมข้อความบอกเหตุ
- เพิ่มเทสต์การวางจากคลิปบอร์ด 1 ข้อสำหรับเคสที่รายการไฟล์กลับมาเป็น `null` — ภาพต้องได้ทางของตัวเองและไม่มีอะไรถูกแนบ ทั้งไฟล์ชุดนี้ผ่าน 8/8
- ปรับชุดทดสอบชื่อโมเดลเป็น 22 เคสจาก id จริงของ 9Router, Bedrock, Copilot และแคตตาล็อก เคสที่ยืนยันว่า `deepseek-v4.1-flash` กับ `claude-haiku-5-5` อยู่ครบ และเคสที่ยืนยันว่า `google/Gemini-pro` ยังเหลือ `Gemini-pro`
- ปรับเทสต์หน้าจอของ Settings ให้คาดหวัง `deepseek-v4-flash` และ `deepseek-v4-pro` ตามที่แถวอ่านได้จริง
- ตรวจฝั่ง Windows ด้วยเทสต์ที่ยืนยันกับคลิปบอร์ดจริงของแพ็กเกจ `desktop` และ `go vet` ผ่านทั้งคู่
