# 🪟 Aetox v1.10.42

วันที่ 1 พฤศจิกายน 2026

**รุ่นนี้ปิดงานภาษาให้จบ — ข้อความผิดพลาดของทุกแพ็กเกจที่เหลือย้ายมาอยู่ในไฟล์คำแปลชุดเดียว เอนจินจึงพูดภาษาที่ตั้งไว้ตั้งแต่เปิดแอป ไม่ใช่ไทยครึ่งหนึ่ง** และพ่วงของใหม่หกอย่างที่เห็นได้ทันที: หน้าความจำที่เห็นไฟล์ทั้งหมดในตารางเดียว, เซิร์ฟเวอร์ MCP ที่ทวงคีย์แบบ Bearer มีช่องให้กรอกแล้ว, เอเจนโหลดเครื่องมือของตัวเองตั้งแต่รอบแรก, ปุ่มคอมมิททุกกลุ่มไม่ถูกปิดเพราะกลุ่มที่ยังไม่มีข้อความ, ชื่อชุดคำสั่งแสดงตามภาษาที่ตั้งไว้ และคลังความรู้ที่ระบุพาธไว้ให้ผู้ช่วยไปอ่านเอง

## ข้อความผิดพลาดของทั้งแอปอยู่ในไฟล์คำแปลชุดเดียว

- **เดิม** แพ็กเกจที่เหลือยังเขียนข้อความผิดพลาดเป็นประโยคภาษาไทยฝังในโค้ด: การอัปเดต (ยอดนิยมที่สุดคือ "ตรวจแฮชไม่ผ่าน" กับ "ช่องทางนี้ไม่อัปเดตอัตโนมัติ"), YouTube, เสียงพูดเข้าและออก, สกิล, การมอบงานให้ลูกมือ, ห้องตัดต่อ, GitHub, การเชื่อมต่อ, LINE, n8n และ Windmill, คลังสื่อ, บัญชี, เอเจน, โมเดล และเครื่องยนต์ จากหน้าจอที่ตั้งภาษาอังกฤษไว้จึงยังเห็นภาษาไทยโผล่มาในกล่องข้อผิดพลาด
- **สาเหตุ** สองชั้นพร้อมกัน — ข้อความถูก composited เองในทุกฟังก์ชันด้วยประโยคไทย และข้อความถูกเลือกตอนที่ error เกิด ไม่ใช่ตอนที่หน้าจอวาด หน้าจอจึงไม่มีคีย์ให้แปลง แม้จะรู้ภาษาที่ตั้งไว้ก็ตาม
- **รุ่นนี้** มีแพ็กเกจคำแปลกลางอยู่ฝั่งเอนจิน เก็บคู่ `คีย์: ประโยค` ภาษาไทยเป็นต้นฉบับและภาษาอังกฤษต้องครบทุกคีย์ (1,044 คีย์) ทุกแพ็กเกจในรายการข้างบนเรียกผ่านคีย์แทนการเขียนประโยคเอง — ข้อความที่เล่าเรื่องไฟล์ ชื่อเซิร์ฟเวอร์ จำนวนไบต์ หรือเพดานของปลายทางยังคงพาตัวเลขจริงมาในประโยค
- **คีย์เดียวใช้ร่วมหลายที่** ถ้อยคำที่เคยเขียนซ้ำ เช่น "ต้องระบุ video id" หรือ "ต้องระบุ id ของ workflow" ตอนนี้เป็นคีย์เดียวกันทุกจุดที่ใช้ แก้ที่เดียวแล้วตรงกันทั้งแอป
- **ภาษาตรงกันตั้งแต่บูตแรก** ก่อนหน้านี้ภาษาของเอนจินถูกตั้งเฉพาะตอนกดสลับภาษาในหน้าตั้งค่า เปิดแอปมาที่ภาษาอังกฤษแล้วข้อความแรก ๆ จึงยังเป็นไทย รุ่นนี้ตั้งภาษาก่อนสร้างตัวติดต่อโมเดล และตั้งใหม่ทุกครั้งที่สลับภาษา
- **สถานะระหว่างเทิร์นเป็นรหัส** บรรทัดใต้สปินเนอร์ ("กำลังคิดคำตอบ…", "กำลังรันเครื่องมือ…") ส่งเป็นรหัสสั้น ๆ ที่หน้าจอเอาไปเลือกคำเอง จึงเปลี่ยนตามภาษาได้กลางเทิร์น และข้อความอย่าง "หยุดคำสั่งนี้แล้ว" หรือ "เปิดสกิล … ไม่สำเร็จ" ก็มาจากคีย์แปลเช่นกัน
- **เพิ่มภาษาใหม่ไม่ต้องแก้โค้ด** หนึ่งภาษาคือไฟล์ประโยคหนึ่งไฟล์บวกหนึ่งบรรทัดลงทะเบียน และมีเทสต์บังคับว่าทุกภาษามีคีย์ชุดเดียวกับภาษาไทย
- **ไม่ได้ทำ** มีหนึ่งจุดที่ยังอ้างคีย์ที่ยังไม่มีประโยค (ตอนบันทึกว่าแชทนี้ต่อกับเซสชันของเอนจินภายนอกตัวไหน) ซึ่งจะขึ้นเป็นชื่อคีย์แทนข้อความ และภาษาจีนในหน้าจอยังไม่มีการแปลฝั่งเอนจิน — ข้อความจากเอนจินจะถอยไปภาษาอังกฤษ

## หน้าความจำใหม่: ไฟล์ทั้งหมดในตารางเดียว

- **เดิม** ไฟล์ความจำกระจายอยู่สามที่ตามเจ้าของไฟล์ — หน้า "เกี่ยวกับคุณ" หน้าเอเจน และแท็บความจำของหัวหน้า — ส่วนไฟล์ของ 39 สาขาไม่โผล่ที่ไหนเลย ใครจะรู้ว่าผู้ช่วยจำอะไรไว้บ้างต้องเปิดทีละหน้า
- **เดิม (ต่อ)** ปุ่มรวมความจำค้างเป็นชิปเทานานถึง 150 วินาทีโดยไม่บอกว่ายังทำงานอยู่ จนดูเหมือนแอปค้าง
- **รุ่นนี้** ตั้งค่า › ความจำ เป็นหน้าเดียวที่รวมทุกไฟล์: ใครอ่าน ขนาด เหลือที่ว่าง และเรียงเป็นสามชั้น (ตัวเรา / ตัวหลัก / ลูกมือ) พร้อมคิวข้อความที่รออนุมัติให้จำ
- **ระหว่างรวมความจำมีนาฬิกาเดินและเพดาน 150 วินาที** การรอจึงไม่ดูเหมือนแอปค้าง และรู้ว่าเมื่อไรจะจบ
- **เปิดไฟล์เองได้** แต่ละขอบเขตมีความจำมีปุ่มเปิดไฟล์ด้วยโปรแกรมแก้ไขของเครื่อง สำหรับคนที่อยากเขียนเพิ่มทั้งไฟล์ ไม่ใช่แก้ทีละบรรทัดบนหน้า — ขอบเขตที่ยังไม่มีไฟล์จะเปิดโฟลเดอร์ให้แทน
- **ไม่ได้ทำ** ถ้อยคำของหน้านี้ยังไม่ได้ย้ายเข้าไฟล์ภาษาเหมือนหน้าอื่น การเขียนกลุ่มที่เหลือของ Git split ยังต้องกดเอง

## เซิร์ฟเวอร์ MCP ที่ทวงคีย์แบบ Bearer มีช่องให้กรอกแล้ว

- **อาการ** เชื่อมเซิร์ฟเวอร์ MCP ในเครื่อง (127.0.0.1) ที่ต้องใช้ bearer แล้วไม่มีการ์ดให้กรอกคีย์ รอหลายนาทีจนจบด้วย "ติดตั้ง 127 ไม่สำเร็จ" และเซิร์ฟเวอร์ที่ config ใส่ `${MT5_TOKEN}` ไว้ใน header ก็ไม่ขึ้นช่องกรอกเหมือนกัน
- **สาเหตุ** สามชั้น — การทวงคีย์แบบ `401 + WWW-Authenticate: Bearer` (แบบที่เซิร์ฟเวอร์ Python ตอบกันเป็นปกติ) ถูกอ่านว่าเป็น "ต้องเข้าสู่ระบบผ่านเว็บ" จึงลบช่อง Authorization ออกและปิดปุ่มไปเลย · ตัวอ่าน placeholder รู้จักแต่ `${input:…}` ไม่รู้จัก `${VAR}` ที่ config ของคนอื่นใช้จริง ค่าจึงถูกเขียนลงเป็นตัวอักษร · เซิร์ฟเวอร์ที่ไม่ตอบอะไรเลยไม่มีช่องไหนให้กรอกทั้งสิ้น
- **รุ่นนี้** การทวงแบบ Bearer ถือว่า "ต้องใส่คีย์" การ์ดจึงขึ้นพร้อมช่องให้กรอก (ประมาณ 5-6 วินาที ไม่ต้องรอครบ 15) · `${VAR}` สามแบบ (`${VAR}`, `${VAR:-ค่าเริ่มต้น}`, `$VAR`) กลายเป็นช่องกรอกบนการ์ด · เซิร์ฟเวอร์ที่ไม่ตอบอะไรได้ช่อง Authorization แบบไม่บังคับ (ไม่กรอกก็ไม่ถูกเขียนลงรายการ)
- **เลิกคืนข้อความดิบ** เมื่อเทิร์นถูกหยุดระหว่างรอการ์ด ตอนนี้บอกเป็นคำว่าหยุดรอ ยังไม่ได้ติดตั้งอะไร และไม่ต้องไปหาทางติดตั้งอื่น
- **ไม่ได้ทำ** ชื่อเซิร์ฟเวอร์ที่มาจาก URL แบบไอพีกับพอร์ตยังถูกตัดเหลือ "127" และไม่ได้ทดสอบกับเซิร์ฟเวอร์ที่ใช้การทวงคีย์แบบอื่นนอกจาก Bearer

## เอเจนโหลดเครื่องมือของตัวเองตั้งแต่รอบแรก

- **เดิม** เซิร์ฟเวอร์ MCP ที่ผูกไว้กับเอเจนถูกกั้นด้วยชั้นพักเครื่องมือ (shelf) เหมือนของโต๊ะ เอเจนจึงต้องเสียหนึ่งรอบไปเปิด shelf ก่อนจะใช้เครื่องมือที่งานของมันต้องใช้อยู่แล้ว
- **สาเหตุ (วัดแล้ว)** จากงาน 15 เทิร์น shelf ประหยัดได้แค่รอบเดียว — 6.6% บนเซิร์ฟเวอร์ GitHub (195,000 → 182,208 โทเคน) แต่เซิร์ฟเวอร์ที่ติดมาเผื่อกินหนักตอนไม่ได้ใช้ (Vercel 1,815,000 → 29,040) คำถามที่ควรถามจึงไม่ใช่ "schema ใหญ่แค่ไหน" แต่เป็น "เซิร์ฟเวอร์นี้คืองานของเอเจนตัวนี้หรือเปล่า"
- **รุ่นนี้** เซิร์ฟเวอร์ที่ผูกกับเอเจนถูกส่งให้ครบตั้งแต่รอบแรก ส่วนตัวที่ติดมากับโต๊ะยังพักไว้เหมือนเดิม ค่าเริ่มต้นตัดสินให้เอง (มีแต่ agent: เปิด · มีโต๊ะร่วม: ปิด) และการเลือกของคนถูกจำลงไฟล์จริงทั้งเปิดและปิด
- **สวิตช์อยู่ที่เดิม** แท็บ "ใครใช้" ของชีต MCP มีสวิตช์บนแถวเดิมของรายการเครื่องมือ พร้อมต้นทุนต่อข้อความบนแถวนั้น ให้เห็นว่าการเปิดไว้กินอะไร
- **ไม่ได้ทำ** เอเจนที่ถือเซิร์ฟเวอร์ใหญ่ไว้ใช้เป็นครั้งคราวต้องปิดสวิตช์เอง ระบบยังไม่เดาให้ตามการใช้งานจริง

## ปุ่มคอมมิททุกกลุ่มไม่ถูกปิดเพราะกลุ่มที่ยังไม่มีข้อความ

- **อาการ** กด "คอมมิททุกกลุ่ม" ไม่ได้เลยถ้ายังมีกลุ่มที่ AI ยังไม่ได้เขียนข้อความ ทั้งที่กลุ่มอื่นพร้อมแล้ว และป้ายบนปุ่มบอกให้ไปเขียนข้อความที่เหลือก่อน
- **สาเหตุ** เอาจำนวนกลุ่มที่ยังไม่มีข้อความไปล็อกปุ่มทั้งแถว แทนที่จะข้ามกลุ่มนั้นตอนคอมมิท
- **รุ่นนี้** คอมมิทเฉพาะกลุ่มที่ถูกเลือกและมีข้อความ แล้วบอกจำนวนกลุ่มที่ข้ามให้เห็นในข้อความแจ้งผล ไม่ปล่อยให้เงียบหาย และไม่หยุดทั้งชุดเพราะกลุ่มที่ยังไม่พร้อม · ข้อความแจ้งผลค้างนานขึ้นเป็น 8 วินาทีเมื่อมีกลุ่มถูกข้าม และขึ้นเป็นข้อมูลกลาง ๆ ไม่ใช่เครื่องหมายสำเร็จ เมื่อไม่มีกลุ่มไหนคอมมิทได้เลย
- **ไม่ได้ทำ** ข้อความแจ้งผลยังไม่มีปุ่มพาไปเขียนข้อความของกลุ่มที่ถูกข้าม

## ชื่อชุดคำสั่งแสดงตามภาษาที่ตั้งไว้

- **เดิม** รายการชุดคำสั่ง (preset) ขึ้นชื่อภาษาไทยทุกตัว แม้หน้าจอตั้งเป็นภาษาอังกฤษหรือจีน
- **สาเหตุ** ชื่อถูกเก็บไว้ในไฟล์ preset เป็นภาษาไทยช่องเดียว ไม่มีที่ให้เก็บชื่อภาษาอื่น
- **รุ่นนี้** ไฟล์ preset พกชื่ออังกฤษและชื่อจีนของตัวเองมาด้วย และตัวอ่านเลือกตามภาษาที่ตั้งไว้ ถอยกลับเป็นชื่อไทยเมื่อไฟล์นั้นยังไม่มีชื่อในภาษานั้น
- **ไม่ได้ทำ** เนื้อหาและคำอธิบายในตัว preset ยังเป็นภาษาไทย ภาษาที่รองรับยังมีแค่ไทย อังกฤษ และจีน

## คลังความรู้: ระบุพาธไว้ ให้ผู้ช่วยอ่านเอง แล้วจำเท่าที่อ่าน

- **เดิม** คลังความรู้เรียนรู้แบบเหมาโหล — ยิงโมเดลทีละไฟล์เพื่อทำชื่อเรื่อง สรุป และข้อเท็จจริงตอนลิงก์โฟลเดอร์ เรียนซ้ำตอนว่าง และฉีดข้อความที่ค้นเจอเข้าเทิร์น เนื้อหาจึงมีสองชุด คือไฟล์จริงกับสำเนาในฐานข้อมูลที่มีกติกาเดินของตัวเอง และ "ข้อเท็จจริง" ที่โมเดลแต่งขึ้นก็ซ้ำกับความจำที่ผู้ช่วยจดอยู่แล้ว
- **รุ่นนี้** เหลือทางเดียว: ระบุพาธไว้ พอเอเจนไปอ่านไฟล์จริงก็จำเท่าที่อ่าน — อ่านแล้วทำดัชนีทันทีโดยไม่ยิงโมเดล และไฟล์ที่อ่านไม่ครบก็ไม่ถูกเก็บ
- **ค้นแล้วเจอของเก่า** แถวที่ไฟล์เปลี่ยนไปแล้วจะถูกอ่านใหม่ตอนค้น (สูงสุด 8 แถวต่อครั้ง) คำตอบจึงไม่มาจากสำเนาที่เก่าแล้ว
- **เครื่องเรียนรู้เดิมถูกลบทั้งชุด** ทั้งการเรียนอัตโนมัติ ช่วงเวลาเรียนตอนว่าง ช่องถามจากคลังความรู้ และข้อเท็จจริงที่โมเดลแต่งขึ้น
- **หน้าจอ** เหลือ ลิงก์โฟลเดอร์ ต้นไม้ไฟล์ และตัวอย่างไฟล์ — ไม่มีกล่องเรียนรู้ ไม่มีแถบความคืบหน้า และคำว่า "เรียนรู้แล้ว" เปลี่ยนเป็น "อ่านแล้ว"
- **ไม่ได้ทำ** รายการที่เคยเรียนรู้ไว้ก่อนอัปเดตใช้ต่อไม่ได้ ต้องให้ผู้ช่วยกลับไปอ่านไฟล์ (ข้อมูลเป็นแคชที่สร้างใหม่ได้ด้วยการอ่าน) และการค้นยังดูสูงสุด 8 แถวต่อครั้ง
