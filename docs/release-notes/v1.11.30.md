# 🪟 Aetox v1.11.30

วันที่ 20 พฤศจิกายน 2026

รุ่นนี้เพิ่มสกิลที่ยิงระบบที่เพิ่งสร้างจริง (`aetox-pentest`) และปิดช่องที่คู่สกิลความปลอดภัยขาดอยู่ ทั้งเรื่องยืนยันตัวตน ทรานแซกชันของ session, CORS, mass assignment, สิทธิ์ของไฟล์ และเวอร์ชันของ runtime ที่โค้ดมองไม่เห็น

## `aetox-pentest` — สกิลยิงระบบที่เซสชันนี้สร้าง บน loopback

- **เดิม** คู่สกิลความปลอดภัยมีสองกริยา คือเขียนโค้ดให้ปลอดภัย (`aetox-security`) กับตรวจโค้ดที่มีอยู่ (`aetox-security-audit`) ไม่มีตัวไหนยิงของจริง ผู้ใช้จึงไม่มีทางรู้ว่าแอปที่เพิ่งสร้างกันทนการโจมตีแค่ไหน
- **ตอนนี้** สกิลใหม่บังคับให้เป้าเป็นสิ่งที่เซสชันนี้สร้างและรีเซ็ตได้ บน `127.0.0.1`/`::1`/`localhost` เท่านั้น ทำงาน 5 ขั้น: ตั้ง scope → ยืนเป้าและพิสูจน์ reset → แผนที่ผิว → ยิงทีละนัด → ตัดสินและรายงาน แล้วส่งแก้ผ่าน `aetox-security` · เครื่องมือแบ่งเป็นขั้นบันได 0–4 (test client, scanner ที่ติดตั้งอยู่แล้ว, container, MCP, host ที่ผู้ใช้มีสิทธิ์พร้อม authorization line) ทุกขั้นต้องถูกเขียนลง scope ก่อนใช้ · ผลตัดสินเป็น `vulnerable`/`protected`/`not shown` และ finding ต้อง replay ได้
- **ที่มา** เทคนิคในเมทริกซ์มาจากเคสสาธารณะ 8 เคส (Capital One 2019, MOVEit CVE-2023-34362, Citrix Bleed CVE-2023-4966, Equifax CVE-2017-5638, Log4Shell CVE-2021-44228, Mirai, Snowflake 2024, Uber 2016) และเขียนเป็นแพทเทิร์นให้เลือกตามผิวที่เจอ ไม่ใช่ลิสต์ที่ต้องไล่ครบ — มีบรรทัดบอกสัญญาณว่าเดินผิดทางสามข้อ
- **เทสต์** `bundled_pentest_test.go` 4 ตัว: before claim ระบุว่าเป็นระบบที่สร้างในเซสชันนี้และอยู่บนเครื่องนี้ · desks=coding · references ทั้งสี่มีจริง · LICENSE ติดไปกับสกิล
- **ไฟล์** `internal/skill/skills/aetox-pentest/{SKILL.md,LICENSE,references/scope.md,references/attempts.md,references/harness.md,references/tooling.md}`

## คู่สกิลความปลอดภัยมีแถวสำหรับ auth/session/JWT, CORS, mass assignment และ runtime

- **เดิม** `defenses.md` มี 30 แถว ครอบ injection, path, crypto และการเก็บรหัสผ่าน แต่ไม่มี CWE 347 (ตรวจลายเซ็น token), 384/613 (session fixation/อายุ), 915 (mass assignment), 942 (CORS), 732/276 (สิทธิ์ไฟล์) หรือ 1104 (runtime) · `audit.md` มีแถว Authentication กับ Session อย่างละบรรทัด และไม่มีคำถามเรื่องเวอร์ชันของ interpreter เลย
- **ตอนนี้** `defenses.md` 41 แถว เติม 307, 347, 384/613, 640, 915, 1004/614/1275, 942, 693, 22/732, 1395 และ 1104 พร้อม input ที่ต้องรันในทุกแถว · `audit.md` 29 แถว: Authentication แตกเป็น token/check/session, เพิ่มแถว `Runtime and its limits` และ `File permissions`, เติม CORS ที่ reflect `Origin` และคำถาม mass assignment · `classes.md` มีบล็อก `Identity and session` ให้ paste เข้า brief ของ hunter · `scanners.md` มีหัวข้อ "What no scanner here reads" เรื่อง `php -v`/`node --version`/`php.ini`
- **เหตุผล** เฉลยของเราเองมีคลาสพวกนี้อยู่แล้ว — SEC5 (crAPI) มี `jwt-alg-confusion`, `jwt-jku`, `jwt-kid-devnull`, `jwt-none-plain`, `token-not-verified`, `otp-bruteforce-v2`, `video-mass-assignment` และ SEC4 (NodeGoat) มี `session-fixation`, `session-cookie-flags` — แต่สกิลไม่มีแถวให้โมเดลใช้หา
