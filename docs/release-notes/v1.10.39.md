# 🪟 Aetox v1.10.39

วันที่ 31 ตุลาคม 2026

**รุ่นนี้เป็นรุ่นของข้อความที่ Aetox เขียนเองและของคำตอบที่มันกล่าวอ้าง** — ตัวเขียนข้อความคอมมิตได้เห็นคอมมิตของรีโปทั้งเรื่อง ไม่ใช่แค่หัวเรื่อง จึงเขียนกลับมาเป็นข้อความที่มีเหตุผลและบอกสิ่งที่ยังไม่ได้ทำ และสกิลตรวจความปลอดภัยบอกเองว่าอะไรที่มันพิสูจน์ไม่ได้ในเครื่องนี้ แทนที่จะปล่อยให้อ่านได้ว่าผ่านหมดทั้ง class

## ข้อความคอมมิต: เดิมเห็นแค่หัวเรื่อง จึงเขียนกลับมาแค่หัวเรื่อง

- **อาการ** ตัวเขียนข้อความคอมมิตอ่าน recent log ด้วย `git log -n 8 --oneline` จึงเห็นแต่ subject ของแปดคอมมิตหลัง แล้วเลียนแบบสิ่งที่เห็น: มันตอบกลับมาเป็น subject บรรทัดเดียวทุกครั้ง ไม่มี body ที่บอกอาการ เลขที่วัดได้ เหตุผลที่เกิด และสิ่งที่ตั้งใจละไว้ ทั้งที่รูปแบบจริงของรีโปนี้มีครบทั้งสี่อย่าง (`docs/RELEASING.md` และ `.claude/skills/release/SKILL.md` เขียนไว้แบบนั้น)
- **สิ่งที่มันเห็นเปลี่ยนจากหัวเรื่องเป็นทั้งเรื่อง** ทั้ง `GitSuggestCommitMessage` และ `GitSuggestSplitCommits` อ่าน log ด้วย `--pretty=format:%s%n%n%b` แทน `--oneline` ส่งให้โมเดลหกคอมมิตพร้อม body (ตัดที่ 40 บรรทัด) ส่วนขั้นจัดกลุ่มยังได้แต่ subject เหมือนเดิม เพราะงานของมันคือแยกไฟล์เป็นคอมมิต ไม่ใช่เขียนข้อความ
- **พรอมป์ต์ขอสิ่งที่ขาด ไม่ใช่ขอให้ "เขียนดีขึ้น"** ลำดับของ body ถูกเขียนเป็นขั้น: อาการ พร้อมเลขเมื่อ diff มีให้เห็น → ทำไมจึงเกิด → สิ่งที่ตัดสินใจ → บรรทัด `- ` ของการเปลี่ยนแต่ละอย่างจัดกลุ่มตามความหมาย ไม่ใช่ตามไฟล์ → บรรทัดปิด `Not done:` เมื่อมีของที่ตั้งใจไม่ทำ · summary เปลี่ยนจาก "บอกว่าอะไรเปลี่ยน" เป็น "บอกอาการที่ diff แก้หรือพฤติกรรมที่เพิ่ม"
- **เลขจะเขียนก็ต่อเมื่อ diff มีเลขให้** ถ้า diff ไม่มีตัวเลขให้อ้าง body บอกอาการเป็นคำและไม่แต่งตัวเลขขึ้นมา — กฎนี้อยู่ในพรอมป์ต์ตรง ๆ เพราะข้อความที่ใส่ตัวเลขสวย ๆ ลงไปโดยไม่มีที่มาก็คือข้อความที่ตรวจไม่ได้
- **คู่มือ coding mode กฎเดียวกัน** `internal/mode/modes/coding.md` เปลี่ยนจาก "อ่าน `git log` หลายหัวข้อล่าสุด" เป็นอ่านข้อความเต็มพร้อม body และข้อความที่เขียนต้องบอกอาการกับเลข (เมื่อมี) เหตุผล สิ่งที่ตัดสิน และสิ่งที่ละไว้ ไม่ใช่รายการไฟล์
- **ไม่ได้ทำ** ยังไม่ให้โมเดลดึงเลข issue/PR จาก diff เองเมื่อเห็นรูปแบบชัด — ฟีเจอร์นี้รอผลลัพธ์จริงจากรอบก่อนหน้า ตามที่บันทึกไว้ในคอมมิต

## สกิล aetox-security: บอกด้วยว่าคำตอบพิสูจน์อะไรไม่ได้

- **อาการ** คำตอบของ security review ก่อนหน้านี้ทำให้อ่านได้ว่าช่องโหว่ทั้ง class ผ่าน เพราะไม่ได้แยกให้เห็นระหว่าง "ลองยิงแล้วไม่เข้า" กับ "ไม่ได้ยิง เพราะเครื่องนี้ยิงไม่ได้" (ต้องมีอุปกรณ์อื่น บัญชีอื่น หรือ outbound callback) ไม่มีบันทึกว่าอะไรพิสูจน์ได้และอะไรไม่ได้
- **หัวข้อใหม่ใน SKILL.md** "What the answer says it could not prove": ช่องโหว่ที่ไม่มี run รองรับต้องเขียนเป็น *named* พร้อมบรรทัดที่ยืนของกลไกป้องกันและสิ่งที่ run จะต้องแสดง ไม่ใช่ *passed* ส่วน class ที่เครื่องนี้ทำไม่ได้ต้องถูกเอ่ยชื่อพร้อมของที่มันต้องการ ไม่ใช่เงียบหายไป
- **`references/coverage.md` ใหม่** ตารางที่บอกว่าแต่ละ class ถึง verdict ไหนได้บนเครื่องที่มีแค่รีโปกับเชลล์ และอะไรคือสิ่งที่พิสูจน์มัน: command/SQL/template injection, path traversal, SSRF, XSS, upload, regex ที่ค้าง, authorization ข้ามผู้ใช้, session/token, secret ในโค้ด, crypto at rest, misconfiguration, error path, supply chain, CI/CD, logging และ business logic · สี่ verdict คือ `proved` · `named` · `needs what is not here` · `not checked`
- **สกิลเปิดเมื่อไรไม่เปลี่ยน** `before:` และ `description:` ของสกิลไม่ได้แก้ รุ่นนี้จึงเพิ่มสิ่งที่คำตอบต้องพูด ไม่ได้ขยายขอบเขตการเรียกใช้ · เครดิตของ Strix `owasp-top-10-testing` (Apache-2.0) ที่อ้างถึงในรอบแรกถูกถอดออกตามที่เจ้าของดูแล้ว โดยเก็บหัวข้อกับตารางไว้
