# 🪟 Aetox v1.10.18

วันที่ 26 ตุลาคม 2026

**ลิงก์ที่ขอเปิดแท็บใหม่ได้แท็บใหม่ใน Aetox แทนที่จะเด้งออกไปเบราว์เซอร์ระบบ — แผงไฟล์จำมุมมองและโฟลเดอร์ที่ปักดาวได้จริงหลังรีสตาร์ต — และเมาส์ไม่หายตอนสลับแท็บในแผงขวา**

## ลิงก์ที่ขอเปิดหน้าต่างใหม่ — ได้อีกแท็บ ไม่ได้เบราว์เซอร์ระบบ

- **เดิม** ไม่มีใครฟัง `NewWindowRequested` ของ WebView2 เอนจินจึงทำตามปริยาย คือเปิดเบราว์เซอร์ของระบบขึ้นมา ทั้งที่ผู้ใช้กดลิงก์ในแท็บของ Aetox (เจ้าของเจอ 26 ต.ค. 2026: *"คลิกแล้วมันเด้งออกมา"*)
- **รุ่นนี้** ลิงก์ `target="_blank"` และ `window.open` กลายเป็นอีกแท็บในแอป การคลิกไม่พาอะไรออกนอก Aetox อีก ส่วนที่รับประกันว่าไม่เด้งออกอยู่ที่ชั้นเอนจิน (`chromium.go`, `NewWindowRequested`) ไม่ใช่ที่ตัวจัดการ จึงไม่มีทางที่เส้นทางอื่นจะหลุดไปเปิดเบราว์เซอร์ระบบ
- **แท็บใหม่เป็นของใคร** ตามแท็บที่มันเกิดมา แท็บของเอเจนต์เปิดอีกแท็บของคนงานคนเดียวกัน ซึ่งเอเจนต์เลือกและใช้งานได้เหมือนแท็บที่มันเปิดเอง ส่วนแท็บของผู้ใช้เปิดอีกแท็บของผู้ใช้บนหน้าที่เขาคลิก สลับกันเมื่อไรก็ได้ทั้งหน้าแท็บของเอเจนต์โผล่บนแถบของผู้ใช้ หรือเอเจนต์ได้แท็บที่เครื่องมือของมันเองไม่ยอมแตะ
- **`window.open('')` ไม่เปิดแท็บเปล่า** เพราะสคริปต์หมายจะเขียนเอกสารลงหน้าต่างที่มันได้มา และเอนจินเขียนลงหน้าต่างที่ถูกส่งให้ ซึ่ง Aetox ไม่ได้ส่งให้ แท็บเปล่าจึงมีแต่ทำให้ดูเหมือนคลิกแล้วเกิดแท็บ คำขอยังถูกนับว่าจัดการแล้วตามที่ชั้นเอนจินทำไว้ แค่ไม่ถูกวาดที่ไหน
- **การชูแท็บเดิมกับการเปิดแท็บใหม่เป็นคนละเรื่อง** `openUrlInWorkbench` รับพารามิเตอร์ `fresh` แล้ว ลิงก์ที่ขอแท็บใหม่จึงได้แท็บใหม่จริง ไม่ใช่กระโดดไปแท็บที่เปิดค้างอยู่ ส่วนลิงก์ในแชทที่กดซ้ำยังพาไปที่แท็บเดิม เพราะจุดประสงค์ของมันคือไปให้ถึงหน้านั้น
- **เหตุการณ์ที่ส่งไปหน้าจอผูกกับแชทของคนงาน** แท็บใหม่ของเอเจนต์จึงขึ้นในแชทที่มันทำงานอยู่ และคลิกในแชทเบื้องหลังก็ไปรอที่โต๊ะของแชทนั้น ไม่เด้งขึ้นทับของคนอื่น
- tests ที่เพิ่มในรุ่นนี้: `browserNewWindowTab.test.ts` (เหตุการณ์ `new-browser-tab` และพารามิเตอร์ `fresh`), `browser_newwindow_test.go` (แท็บของเอเจนต์กับของผู้ใช้ และ URL ว่าง) และ `aetox_new_window_test.go` ที่ชั้นเอนจิน พร้อม live test ที่คลิกของจริง

## แผงไฟล์จำมุมมองและโฟลเดอร์ที่ปักดาวได้จริง

- **เดิม** ทั้งสองค่าถูกอ่านตอนสร้าง explorer ตั้งแต่ 24 ต.ค. 2026 แต่คีย์ของมันเป็น `const` ที่ประกาศอยู่ใต้จุดนั้น `loadFileView` จึงอ่าน `FILE_VIEW_KEY` ใน temporal dead zone โยน `ReferenceError` แล้วถูก catch คืนค่า `list` ทุกครั้ง และ `loadPinnedFolders` ก็คืน `[]` ด้วยเหตุเดียวกัน ผลที่ผู้ใช้เห็นคือมุมมองที่เลือกไว้กลับเป็นรายการทุกครั้งที่เปิดแอป และดาวที่ปักโฟลเดอร์หายหมด
- **รุ่นนี้** ย้ายคีย์ทั้งสองขึ้นไปก่อน explorer พร้อมคอมเมนต์กำกับว่าทำไมต้องอยู่ตรงนั้น และ `fileViewOf` ถูก import เข้ามาจริง ซึ่งก่อนหน้านี้ไม่เคยถูก import เลย
- test `explorerViews.test.ts` import โมดูลใหม่หลังเขียน `localStorage` ก่อนแก้ได้ `list` หลังแก้ได้ `icons` และคุมโฟลเดอร์ที่ปักดาวไว้ด้วย เทสต์นี้จึงจับอาการที่ผู้ใช้เห็น ไม่ใช่แค่ค่าที่อ่านได้

## งานตั้งเวลาใหม่ — ชนิดข้อมูลตรงกับที่เอนจินส่ง

- แบบฟอร์มสร้างงานใหม่ประกอบ `Schedule` ไม่ครบสองฟิลด์ที่เอนจินเพิ่มมา (`kind` และ `on`) ด่านตรวจชนิดของหน้าจอจึงฟ้องทั้งไฟล์
- ค่าที่ส่งไปเท่ากับค่าปริยายของ Go อยู่แล้ว พฤติกรรมจึงไม่เปลี่ยน แต่ชนิดข้อมูลควรตรงกันเพื่อให้ด่านตรวจของหน้าจอกลับมาเขียว

## เมาส์ไม่หายตอนสลับแท็บในแผงขวา

- **เดิม** คลาส `AetoxBrowserHost` ลงทะเบียนโดยไม่ตั้ง `Cursor` ค่าเป็น NULL `DefWindowProc` จึงตอบ `WM_SETCURSOR` ด้วยเคอร์เซอร์ว่าง ในช่วงที่ยังไม่มีเอนจินวาดทับ คือราว 700 ms ระหว่าง `CreateWindowExW` ถึง `Embed` และตอนโชว์หน้าต่างที่พิกัดเดิมก่อน reflow เคอร์เซอร์จึงไม่ถูกวาดเลยจนกว่าจะย้ายออกจากบริเวณนั้น (เจ้าของ 26 ต.ค. 2026: *"เมาส์ชอบหายเวลากดสลับแถบขวาไปมา"*)
- **รุ่นนี้** คลาสมีลูกศรเป็นของตัวเอง ลูกที่วาดหน้าอยู่แล้วยังตั้งเคอร์เซอร์ของตัวเองตามเดิม ลูกศรนี้จึงเห็นเฉพาะตรงที่ทางเลือกคือ "ไม่มีอะไร" ไม่ใช่การทับรูปร่างที่เอนจินตั้งไว้แล้ว

## เปลี่ยนอื่น ๆ ในรุ่นนี้

- `desktop/browser.go` มี `onNewWindow` ใน `tabCallbacks` และผูกที่จุดเดียวกับ callback อื่นก่อน `Embed` เพราะลิงก์แรกที่หน้าเว็บวาดอาจถูกคลิกได้ทันที
- แพตช์ `third_party/go-webview2` เพิ่มอินเทอร์เฟซ `NewWindowRequested` และตั้งธงว่าคำขอถูกจัดการแล้วจริง ไม่ใช่ปล่อยให้ WebView2 ไปเปิดเบราว์เซอร์ระบบให้เอง
