# 🪟 Aetox v1.11.7

วันที่ 11 พฤศจิกายน 2026

**รุ่นนี้ทำให้โปรเจกต์ที่อยู่บนคลาวด์บอกตัวเองได้และไม่ถูกอ่านทั้งโฟลเดอร์โดยไม่ตั้งใจ · แถบโปรเจกต์อ่านเร็วขึ้นเป็นแถวเดียวพร้อมไอคอนของโปรเจกต์เอง · เปิดแชทใหญ่ไม่ค้างหน้าโหลดอีก · และการเก็บ snapshot ไม่ปล่อยให้ pack ครึ่งทางกินดิสก์จนเต็ม**

## โฟลเดอร์บนคลาวด์บอกตัวเอง และไม่ถูกอ่านทั้งโฟลเดอร์โดยไม่ตั้งใจ

- **เดิม** โปรเจกต์ที่อยู่ใน OneDrive หรือ Google Drive ดูเหมือนโฟลเดอร์ธรรมดา แต่ไฟล์ที่ยังไม่ถูกดึงลงเครื่องคือการดาวน์โหลดเมื่อมีคนเปิดอ่าน เปิดแชทจึงช้า ค้นหาไม่เจอไฟล์ และไม่มีจุด undo — โดยไม่มีอะไรบนจอบอกว่านี่คือสาเหตุ
- **รุ่นนี้** เอนจินอ่านชื่อไคลเอนต์จาก volume และโฟลเดอร์ของมัน แล้วบอกบนแถบโฟกัสของแชท (`OneDrive`, `Google Drive`) พร้อมบรรทัดใต้ช่องค้นหาว่า "ยังไม่ได้ค้น n ไฟล์ที่อยู่บน OneDrive"
- การเก็บ snapshot และการเปิด store ของ undo **ข้ามโฟลเดอร์คลาวด์ทั้งโฟลเดอร์** เพราะ `git add --all` บนโฟลเดอร์ที่ยังดึงไม่ครบคือการดาวน์โหลดทั้งโปรเจกต์ — เดิมจบด้วย "ไม่มีอะไรให้ undo" ทุกเทิร์นหลังรอ 15 วินาที
- `read` รอไฟล์ที่กำลังดึงด้วยงบ 5 วินาทีแล้วบอกให้ลองใหม่ (การดึงยังทำต่อ) · `grep` ข้ามไฟล์ที่ยังไม่ถูกดึง นับไว้และบอกจำนวนท้ายผล — `cloud: true` ขอให้ดึงและค้น · `repo_map` ข้ามไฟล์เดียวกัน
- งบ 10 วินาทีของ `grep` ถูกผูกกับ context จริงแล้ว เดิมมีแต่ประโยคบอกท้ายผล ไม่มีอะไรหยุดการเดินไฟล์
- **ไฟล์** `internal/clouddir/` · `internal/engine/app.go` · `internal/engine/undo_browse.go` · `internal/skill/{grep,read,repomap,search_files}.go` · `Chat.svelte` · `SearchPane.svelte` · `locales/{th,en,zh}.ts`

## แถบโปรเจกต์เป็นแถวเดียว มีไอคอนของโปรเจกต์เอง และตัวที่เปิดอยู่ขึ้นบนสุด

- **เดิม** การ์ดโปรเจกต์สูง 58-78px ซ้อนชื่อ ชิป stack คำอธิบาย จำนวน และบรรทัด marks — switcher อ่านช้ากว่าที่ควร และโปรเจกต์ที่เปิดอยู่เรียงตามเวลาล่าสุด จึงอยู่ที่ไหนก็ได้ในคอลัมน์ หรือหลุดจอไปเมื่อเลื่อน
- **รุ่นนี้** แถวเดียวสูง 33px: ไอคอน (ไอคอนที่โปรเจกต์พกเอง → framework ที่ใช้ → ภาษา → อักษรตัวแรกในสีของโปรเจกต์) ชื่อ จำนวนงานที่รอ (จุด + ตัวเลข) เข็มหมุดที่ปลายขวา และจำนวน/อายุ · stack คำอธิบาย และ path อยู่ใน tooltip ของแถว
- โปรเจกต์ที่เปิดอยู่ขึ้นบนสุดเสมอ และติดอยู่บนระหว่างเลื่อน
- ไอคอนของโปรเจกต์ (`assets/logo.svg`, favicon, appicon) ส่งมาเป็น data URI เพดาน 48 KB พร้อมแถวเดียวกับ stack — การ์ดไม่ต้องยิงคำขอของตัวเอง
- **ไฟล์** `ProjectSidebar.svelte` · `lib/projectStack.ts` · `lib/projectHue.ts` · `internal/projstack/logo.go` · `internal/engine/sessions.go` · `style.css`

## เปิดแชทไม่ต้องรอ snapshot และไม่ค้างสปินเนอร์ตลอดไป

- **เดิม** `OpenSession` ตอบชิป undo มาพร้อมกัน แต่การตอบคำถามนั้นคือการเก็บ snapshot — `git add --all` ทั้ง work tree วัดบนรีโปของเจ้าของ 109 ms ตอน stat cache อุ่น และ 16.9 s ตอนเย็น ระหว่างนั้นหน้าจอเห็นแค่สปินเนอร์ และคำขอที่ไม่มีวันตอบก็ปล่อยให้ค้างตลอดรัน
- **รุ่นนี้** การเปิดแชทไม่พา undo มาแล้ว ชิปถูกถามหลังแชทขึ้นจอ และใส่ค่าเฉพาะเมื่อแชทนั้นยังเป็นตัวที่เปิดอยู่ · การเปิดมีเพดาน 25 วินาที (รวม fallback และการรอ pane move) เกินแล้วปล่อยคิวและบอกว่าแชทไม่ตอบ กดซ้ำได้ทันที คำตอบที่มาช้ายังถูกจัดการต่อ
- **ไฟล์** `internal/engine/sessions.go` · `cockpit.svelte.ts` · `locales/{th,en,zh}.ts`

## snapshot ไม่กินดิสก์จนเต็ม

- **เดิม** `gc --auto` ถูกตัดกลางคันเมื่อการแคปเจอร์ครบงบ 15 วินาที และ `gc.autoPackLimit` ของ git สั่ง full repack ที่ทำไม่จบ — git ไม่เก็บ pack ที่ไม่มี `.idx` ให้เอง ดิสก์ของเจ้าของหมดเกลี้ยงจากสามไฟล์รวม 91.72 + 51.49 + 6.28 GB
- **รุ่นนี้** store จัดการ pack เอง (`maintain`): จับ lock, กวาด pack ที่เขียนค้างก่อนและหลัง, รวม pack เมื่อเกิน 16 ด้วยงบของตัวเอง (10 นาทีต่อครั้ง, เพดาน 1 GB) และปิด `gc.autoPackLimit` ผ่าน layout version 2 · กวาด pack ครึ่งทางในทุก store ตั้งแต่เปิดแอป
- ไฟล์ untracked ที่ใหญ่กว่า 2 MiB ไม่เข้า snapshot แล้ว (ไฟล์ที่ store ถืออยู่ยังถูกเก็บต่อ จุด undo เดิมจึงย้อนได้ครบ) — store หนึ่งบวมถึง 13.4 GB จาก 12,359 blob ล้นจาก build output
- **ไฟล์** `internal/snapshot/snapshot.go` · `cap_test.go` · `maintenance_test.go`

## สกิล 3D แบบแยกชิ้น และสกิลงานโค้ดบนเดสก์ผู้ช่วย

- `aetox-web-3d` สอนงาน 3D แบบ exploded view / cutaway / assembly ไม่ใช่แค่ reference ของ Three.js แล้ว: สี่สถานะของหน้า (assembled → separated → focus → assembled), ลำดับชิ้นตามแกนเดียว, กล้องโฟกัสทีละชิ้นผ่านตัวควบคุมที่มีอยู่และต้องถึงด้วย touch กับคีย์บอร์ด, dim ชิ้นอื่นแทนการซ่อน, cutaway ที่เห็น geometry จริง, particle flow, physics cap, reduced-motion · เกณฑ์ตรวจรับ: วัด frame time บนเครื่องที่มีชิ้นมากที่สุด, KTX2/Draco แบบโหลดเป็นกลุ่ม, แบรนด์สมมติ
- ประกาศ `desks: assistant, coding` และมี `before:` ของมันเอง — ผู้ช่วยอ่านได้ตอนทำงาน 3D ไม่ใช่เฉพาะงานเขียนโค้ด
- สกิลงานเขียนโค้ดที่เหลือ (`aetox-database`, `aetox-mcp-roblox`, `aetox-performance`, `aetox-security`) ประกาศ `assistant` ด้วย — ไม่มีสกิลที่ถูกกันไว้ให้เดสก์เดียวอีก ผู้ช่วยทำงานเดียวกันได้โดยไม่ต้องสลับเดสก์
- **ไฟล์** `internal/skill/skills/aetox-web-3d/SKILL.md`
