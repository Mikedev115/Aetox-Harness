- **เดิม** `Stage` เอา `asset.Name` จาก GitHub API มาต่อกับ staging dir ด้วย `filepath.Join` แล้วดาวน์โหลดเขียนไฟล์ทันที ส่วนการตรวจลายเซ็นและ sha256 อยู่ทีหลัง ชื่ออย่าง `..\..\Users\<u>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\x.exe` จึงวาง exe ลง Startup ได้ โค้ดรันตอนล็อกอินโดยไม่ต้องมี signing key และการอัปเดตเบื้องหลังเรียก `Stage` เองโดยไม่ต้องกดอะไร

## `/aetox-file/` ไม่ให้เว็บวิวเดาชนิดไฟล์เอง

- **เดิม** `/aetox-file/` เสิร์ฟทุกไฟล์ด้วย `ServeContent` โดยไม่มี nosniff ไฟล์ `.txt`/`.md` ที่เก็บ HTML จึงถูกเดาชนิดแล้วรันได้ และห้องเอกสารเปิด `.html` ใน iframe ที่ไม่มี sandbox บนออริจินเดียวกับแอป สคริปต์ในใบเอกสารจึงเรียก `parent.go.main.App` ได้
- **ตอนนี้** ทุกไฟล์ที่เสิร์ฟจาก `/aetox-file/` มี `X-Content-Type-Options: nosniff` ทั้งทางเอนจินโดยตรงและทาง proxy ของหน้าจอ · `DocumentsPane` เปิด iframe ด้วย `sandbox="allow-scripts"` หน้าเอกสารยังรัน JS ของตัวเองได้ แต่ได้ opaque origin จึงเอื้อมถึงการผูกของแอปไม่ได้ — pane ไม่ได้อ่านอะไรในเฟรม (แค่แสดงผล) จึงไม่มีอะไรเสีย

- **ตอนนี้** migration 89: `pending_changes.helps`/`hurts` INTEGER DEFAULT 0 มีด่าน `hasTable` + `hasColumn` จึง replay บนสโตร์ที่มีคอลัมน์แล้วได้ · helps นับตอนรีวิวเจอแชทอื่นพูดบรรทัดที่พักไว้ซ้ำ ซึ่งคือเหตุผลทั้งหมดที่กลไก hold รออยู่ · hurts นับตอนคำพูดของเขาไปขัดบรรทัดที่อนุมัติแล้ว · hurts ครบ 2 ครั้ง → เสนอใบลบ (`OpRemove`) ให้เขากดอนุมัติ ไม่ลบเอง ตามหลักแรกของระบบนี้ที่ว่าไม่มีอะไรลงดิสก์ก่อนคนอนุมัติ และคิวกันใบซ้ำแยกตาม op อยู่แล้ว จึงไม่เกิดการ์ดซ้ำ · ตัวเลข 2 เป็นค่าที่เราตั้งเอง ยังไม่มีเปเปอร์ระบุ · ไม่มีโมเดลถูกเรียกเพิ่มเลย: ตัวนับคือ UPDATE บนแถวเดียว ไม่กินโทเค็น
- **เทสต์** ใหม่ 4 ตัว: migration ที่ความลึกก่อนหน้า (สร้างสโตร์ความลึก 88 แล้วอัปเกรด) · helps นับซ้ำ · hurts → ใบลบครั้งเดียว · บรรทัดที่ไม่ได้อยู่ในไฟล์นับไม่ได้
- **ยังไม่ทำ** แสดงตัวเลขบนหน้า memory (ต้องแตะ UI แยก ไม่ให้ปนกับคอมมิตนี้)
- **ไฟล์** `internal/engine/db.go` · `internal/engine/review.go`

## ตัวรีวิวเห็นคำตอบบนข้อความสั้น โดยไม่เพิ่มงบโทเค็น

- **เดิม** ตัวรีวิวหลังเซสชันอ่านแต่ข้อความของผู้ใช้ (`review.go:277` "You see only their messages") คำติจึงแปลงเป็นกฎได้ แต่ระบุไม่ได้ว่าคำตอบแบบไหนทำให้เกิด
- **ตอนนี้** ข้อความสั้น (≤240 ตัวอักษร) มาพร้อมคำตอบของผู้ช่วยที่อยู่เหนือมัน ตัดเหลือหัว 200 + ท้าย 120 ตัวอักษร (เพดาน 320) เพราะหัวคือสิ่งที่คำตอบเปิดด้วย ท้ายคือที่ที่บอกว่า "เสร็จแล้ว" ก่อนตรวจ · ข้อความยาวไม่ดึงคำตอบมา: มันคือชิ้นงานถัดไป ไม่ใช่ปฏิกิริยาต่อชิ้นก่อน · ส่วนที่ดึงมาหักจาก `reviewBudgetChars` เดิม (24,000) ใน `reviewSlice` รอบรีวิวจึงไม่แพงขึ้น เปลี่ยนแค่ส่วนผสม และไม่แตะเทิร์นของผู้ใช้ · คำสั่งใหม่หนึ่งย่อหน้า: คำชมที่ระบุพฤติกรรมคือ confirms ของบรรทัดที่มีอยู่ ไม่ใช่บรรทัดใหม่ · คำชมลอย ๆ ("good", "ok") ไม่ใช่บรรทัด · ห้ามเขียนว่าพอใจ/หงุดหงิด และห้ามอ่านอารมณ์จากคำเดียว
- **เทสต์** ใหม่ 5 ตัว: คำตอบมาบนข้อความสั้น · ตัดหัวท้าย · งบรวมไม่เกินเพดานเดิม · digest วางคำตอบถูกตำแหน่ง · คำสั่ง Reviewer มีจริง · ของเดิมของรีวิวทั้งชุดผ่าน
- **ไฟล์** `internal/engine/review.go`

## แยกงานที่ผู้ใช้เก็บจากของชั่วคราว

- **เดิม** ประโยคส่งงานมีแค่ "one file per thing you were asked" ไม่มีอะไรให้โมเดลตัดสินว่าชิ้นไหนเป็นงานของผู้ใช้จริง ชิ้นนั้นควรอยู่ที่ไหนให้หยิบใช้ทีหลัง และชิ้นไหนที่เขาต้องดูเองแทนที่จะอ่านคำอธิบาย
- **ตอนนี้** งานที่เขาจะกลับมาหา: รวมไว้กับเรื่องเดียวกัน ตั้งชื่อให้บอกว่ามีอะไร และบอก path ในคำตอบ ตาม PARA/Johnny.Decimal ที่ออกแบบมาให้หาของเจอทีหลัง · ของทดลอง ภาพแคปเพื่อเช็กงานตัวเอง หรือไฟล์ที่แค่อ่าน ไม่ใช่งานของเขา ไม่ต้องเสนอ · เปิดให้ดูเฉพาะสิ่งที่ต้องใช้ตาเขาตัดสิน (หน้าเว็บที่หน้าตาคือผลลัพธ์ สไลด์ รูป คลิป) ส่วนเนื้อหาที่คำตอบบอกอยู่แล้ว มีค่าแค่ path ไม่ต้องเปิด
- **ต้นทุน** แทนประโยคเดิม 238 B ด้วย 616 B พรอมป์รวม 16,197 B จากเพดาน 16,200 B และยังไม่หลุดไปหา desk ที่ไม่มี write เพราะ longform ถูก gate อยู่แล้ว
- **เทสต์** ใหม่ `TestWorkIsSortedIntoWhatTheUserKeepsAndWhatTheyMustSee` ครอบ assistant/coding และ tool-less
- **ไฟล์** `internal/prompt/prompt.go`

## วางแผน: ให้ดูโครงก่อนถาม

- **เดิม** ย่อหน้าถามของโหมดวางแผนสั่งให้ถาม "BEFORE the deep reading" คือถามก่อนเห็นอะไรเลย ผู้ใช้ได้คำถามกว้าง ๆ ที่ไม่ได้เกี่ยวกับโปรเจกต์นี้ และประโยคปิดเป็นปริศนา ("turning it back is one press; that is about permission only") ที่ตัวเทสต์เองบันทึกไว้ว่าโมเดลอ่านเป็น "ห้ามถาม" ซึ่งเป็นอาการที่ย่อหน้านี้เกิดมาเพื่อกัน
- **ตอนนี้** ลำดับคือ ดูครั้งเดียว (`repo_map`, entry file) → ถามถ้ายังไม่ชัด → อ่านเต็ม · "not a survey" วางไว้ตรงที่ให้สิทธิ์ดู เพราะ "one look first" ที่ไม่มีเพดานคือใบอนุญาตสำรวจทั้งเรพก่อนถาม แล้วคำถามก็ไม่มา (เคส 2026-09-08 ที่ย่อหน้านี้กันอยู่) · "A brief that is already clear gets no question": ไม่มีกิ่งนี้ โหมดนี้จะถามเป็นพิธี ซึ่งเป็นต้นทุนที่มันถูกสร้างมาเพื่อตัด · ประโยคปิดเขียนตรงแทนปริศนา: ห้ามถามขออนุญาตเริ่มหรือออกจากโหมด (ปุ่ม Do เป็นของผู้ใช้) แต่คำถามเรื่องงานไปก่อนแผน ผ่าน `ask_user`
- **เทสต์** `TestPlanAsksAboutTheWorkBeforeItReads` ยึดลำดับสามช่วง (look < ask < deep) แทนการยึดวลี และยึดประโยคที่แบกพฤติกรรมไว้ · `go test ./internal/mode` ผ่าน · `go vet` ผ่าน
- **ไฟล์** `internal/mode/stance.go` · `internal/mode/stance_test.go`
