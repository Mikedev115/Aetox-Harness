## Antigravity — เครื่องมือ Aetox มาครบเป็นค่าตั้งต้น

- **เดิม** migration ที่เขียนแถว Antigravity ไม่ได้ตั้ง `share_mcp` ทั้งที่ตั้งแต่ 20 ต.ค. agy โหลด aetox server เป็น plugin ของโฟลเดอร์เทิร์นได้แล้ว ผลคือแชทที่ต่อ agy ไม่มี `skill_view`, browser pane, `image_ocr`, `ask_main` เลยจนกว่าจะไปเปิด toggle เอง และได้แค่ shelf ของสกิลเป็นไฟล์
- **รุ่นนี้** seed และเส้นทางนำเข้าเปิด sharing ให้ agy เท่ากับอีกสองโปรแกรม · migration 85 เปิด `share_mcp=1` ให้แถว Antigravity ที่มีอยู่แล้ว (guarded ด้วย `hasTable`) เครื่องที่ติดตั้งไว้จึงได้เลยโดยไม่ต้องไปตั้งใหม่ และผู้ที่อยากปิดยังปิดได้ที่ toggle เดียวในหน้าการเชื่อมต่อ
- คอมเมนต์ของ `cliSkillShelf` แก้ให้ตรงความจริง: shelf เป็นทางสำรองของ connection ที่ปิด sharing ไม่ใช่เพราะ agy ไม่มี MCP
- **ไฟล์** `internal/engine/code_adapter_defaults.go` · `internal/install/install_import.go` · `internal/engine/db.go`

## โหมด `auto` ของ agy 1.4 เลือกได้แล้ว

- **เดิม** agy 1.4.12 ประกาศ `--mode` (accept-edits, auto, plan) แต่ตัวเลือกโหมดยังเป็นชุดของ 1.3.3 คือ Default/accept-edits/plan/bypass ผู้ใช้จึงเลือกโหมด auto ของตัวโปรแกรมเองไม่ได้
- **รุ่นนี้** `ModesFor("antigravity")` มี `auto` อยู่ระหว่าง accept-edits กับ plan และส่ง `--mode=auto` ผ่าน branch เดียวกับสองโหมดข้างเคียง · `auto` ไม่ติด `--dangerously-skip-permissions`
- **ไฟล์** `internal/cliagent/antigravity_gate.go` · `internal/cliagent/antigravity_run.go`

## การ์ดขออนุญาตไม่เด้งรายคลิกในเบราว์เซอร์ของ agy

- **เดิม** การ์ด permission ของ Antigravity ตั้งกฎว่า tool ที่ไม่อยู่ในรายการ "ไม่ถาม" ต้องผ่านการ์ดทุกตัว รายการนั้นเขียนไว้ตอน agy 1.3.3 และยังไม่มี tool ชุดที่ 1.4.12 เพิ่มมา (init frame ประกาศ 60 tools) เบราว์เซอร์ของ agy ทั้งชุด — คลิก, พิมพ์, screenshot, execute js, เปิดหน้า — จึงเด้งการ์ดทีละครั้ง รวม 33 ตัว ทั้งที่ตอนใช้ agy เองไม่มีใครถามรายคลิก
- **รุ่นนี้** เพิ่ม 23 ตัวในรายการไม่ถาม: tool เบราว์เซอร์ทั้งชุด, ความจำ/inbox/marketplace ของ agy (`delete_knowledge`, `manage_inbox`, `send_message`, `search_marketplace`, `list_plugin_accounts`) และ `generate_image` ที่เขียนลง artifact folder ของมันเอง
- ยังเด้งการ์ดตามเดิม 6 ตัวที่แตะเครื่องหรือโลกภายนอก: `run_command`, `send_command_input`, `notebook_execution`, `run_workflow`, `schedule`, `read_url_content`
- **ไฟล์** `internal/cliagent/antigravity_gate.go`

## ติดตามงาน — สั่งเฝ้างานแล้วอ่านความคืบหน้าในแท็บ ไม่ต้องกลับมาถามใหม่

- **เดิม** ถามว่า "ติดตามงานนี้ 6 ชั่วโมง" ผู้ช่วยตอบได้แค่ให้กลับมาถามใหม่เอง — ไม่มีที่ให้เฝ้างานที่กำลังรันอยู่ และไม่มีที่อ่านความคืบหน้าของมัน
- **รุ่นนี้** tool `watch` (list/start/stop) ให้ผู้ช่วยเฝ้างานหนึ่งงานแล้วรายงานใน **แท็บงานเบื้องหลัง** · `start` รับ `hours` (ค่าตั้งต้น 6) และ `minutes` (ค่าตั้งต้น 3) ส่วนแถวนั้นปิดเองเมื่อจบ: delegate ที่ finished/collected, dev server ที่หยุด หรือครบเวลา
- delegate ไม่ได้ใช้ clock — register ของ subagent บอกทุกความเคลื่อนไหวอยู่แล้ว (asked · began · asking · answered · finished · collected) จึงฟังจากของจริง ไม่ใช่ไปถามซ้ำเป็นรอบ
- แถวที่จบแล้วยังอยู่ (done · expired · stopped) เพื่อให้แท็บบอกได้ว่าจบเพราะอะไร แทนที่จะหายไปเงียบ ๆ
- **ไฟล์** `internal/engine/watches.go` · `internal/engine/watch_tool.go` · `desktop/frontend/src/lib/workbench/JobsPane.svelte` · `internal/safety/tools.go`

## `RULES.md` — กฎการทำงานที่ผู้ช่วยจำข้ามแชท

- **เดิม** ผู้ใช้ต้องเตือนซ้ำเรื่องวิธีทำงาน (คุยแผนก่อนลงมือ เทสต์ก่อนคอมมิต) — USER.md เก็บข้อเท็จจริงเกี่ยวกับตัวเขา และ SHAPE.md เก็บวิธีตอบ ไม่มีไฟล์ไหนเก็บคำสั่งเรื่องงานได้จริง
- **รุ่นนี้** session review เขียนกฎลง `memory/RULES.md` ได้ (`about: "rules"`) เฉพาะกฎที่ยกคำพูดของเจ้าของมาอ้างได้ · prompt อ่านไฟล์นี้ต่อจาก SHAPE และหน้าหน่วยความจำแสดงไฟล์นี้พร้อมคำอธิบายผู้ฟัง (ผู้ช่วยและทุกโต๊ะอ่าน ลูกมือไม่อ่าน)
- บรรทัดที่เสนอซ้ำของเดิมกลายเป็น **แทนที่**: รีวิวส่ง `replaces` มาเป็นถ้อยคำของบรรทัดเดิม สองบรรทัดที่ขัดกันเองจึงไม่ถูกเก็บคู่กันอีก และการ์ดอนุมัติบอกว่าแทนที่บรรทัดไหน
- ทุกบรรทัดที่เขียนผ่านประตูนี้บอกวันที่ที่ยืนยันล่าสุด ("— 13 พ.ย.") เพื่อให้โมเดลรู้ว่าบรรทัดนั้นเก่าแค่ไหน และไม่เติมซ้ำถ้าบรรทัดมีวันที่อยู่แล้ว
- เพดานไฟล์ปรับตามที่เจ้าของสั่ง: MEMORY.md 10 KB · USER.md 5 KB · SHAPE.md 3 KB · RULES.md 3 KB

## การ์ดภาพชี้ไฟล์จริง แม้พาธจะยาวเกิน 60 ตัวอักษร

- **เดิม** การ์ดภาพใต้แถว `image_make` ใช้ `s.subject` เป็นที่อยู่ไฟล์ ซึ่งเป็นป้ายชื่อที่ถูกตัดที่ 60 ตัวอักษรพร้อมเติม `…` พาธเต็มของรูปที่ยาวเกิน 60 จึงกลายเป็นที่อยู่ที่ไม่มีไฟล์จริง ตัวเสิร์ฟไฟล์ตอบ 404 แล้วการ์ดขึ้นว่าไม่พบไฟล์ภาพ ทั้งที่ไฟล์อยู่บนดิสก์ (13 พ.ย. 2026 แชท mypsd9: รูปทุกใบยาว 61–67 ตัวอักษรจึงล้มทั้งชุด)
- **รุ่นนี้** การ์ดใช้ `writtenFiles[0]` เป็นที่อยู่ และถอยไปใช้ subject เฉพาะบันทึกเก่าที่ไม่ได้เก็บพาธจริง บันทึกเดิมจึงกลับมาแสดงได้ทันทีโดยไม่ต้องเจนรูปใหม่ · ตัวเสิร์ฟไฟล์เสิร์ฟรูปตามพาธเต็มที่เข้ารหัสไดรฟ์ (`%3A`) ได้
- **ไฟล์** `desktop/frontend/src/lib/Chat.svelte` · `internal/engine/filehost_test.go`

## ข้อความบนจอไทยเป็นภาษาไทยจริง และมีเทสต์กันไว้

- **เดิม** ข้อความสั่งงานของทีมถูกเขียนไว้ให้โมเดลอ่าน ("Tell the person…") ทั้งที่เป็นประโยคที่คนอ่าน จึงขึ้นบนจอไทยทั้งดุ้น (การ์ดส่งงาน 12 พ.ย. 2026) และไม่มีเทสต์ตัวไหนดูว่าประโยคในตาราง th เป็นภาษาไทยจริง
- **รุ่นนี้** เขียนใหม่ทั้ง th/en ให้พูดกับคนตรง ๆ: แชทนี้ยังไม่ได้เลือกทีม จึงส่งงานให้ %s ไม่ได้ — เลือกทีมจากเมนู «ทีม» ก่อน หรือทำงานนี้ในแชทนี้เอง · ถอดวลีสั่งโมเดลออกจาก `engine.cutRoomBusy` ด้วย
- ไล่ประโยคอังกฤษที่ยังค้างบนจอไทยได้ 44 คีย์จาก 52 คีย์ใน allowlist เขียนใหม่ให้อ่านรู้เรื่อง (`adsmeta.noToken`, `github.noAccount`, `botbridge.noToken`, `engine.providerNotFound`, `life.badWho`, `cutroom.edit.unknownOp`, `skill.n8n*`, `windmill.*`, `youtube.badPrivacy` ฯลฯ) และชี้ไปที่ «ตั้งค่า → การเชื่อมต่อ» ตามชื่อที่แอปใช้จริง ไม่ใช่ "Settings" · ตัวเลข `%s/%d/%q` เท่าเดิมทุกคีย์
- allowlist เหลือ 9 คีย์ที่เป็นรายชื่อที่เครื่องอ่าน ไม่ใช่ประโยค (ชื่อฟิลด์ chroma/mask, ค่า resolution, ชื่อ op ของ cutroom, ค่า fx, โดเมน, ชื่อฟีเจอร์ Windows) ทุกตัวมีเหตุผลกำกับ
- เทสต์ใหม่ `TestThaiSentencesAreWrittenInThai` (ประโยคในตาราง th ต้องมีอักษรไทยอย่างน้อยเท่าละติน เว้นแต่มีเหตุผลใน allowlist) และ `TestNoSentenceAddressesTheModel` (ห้ามวลีที่พูดกับโมเดลทั้งสองตาราง)
- **ไฟล์** `internal/uimsg/sentences_th.go` · `internal/uimsg/sentences_en.go` · `internal/uimsg/uimsg_test.go` · `internal/subagent/team_test.go`
