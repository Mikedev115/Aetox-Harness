# 🪟 Aetox v1.10.33

วันที่ 31 ตุลาคม 2026

**รุ่นของเอนจิน: Devin เข้ามาอยู่ในรายการที่เลือกได้ และทุกเอนจินเปิด/ปิดได้ทีละตัว · ปุ่ม "ไม่รอ" บอกได้ว่าหยุดไม่ได้เพราะอะไร แทนที่จะกดแล้วเงียบ · โหมดเขียนเปิดได้ทุกเอนจิน · โปรไฟล์ตั้งค่าที่เป็นของผู้ใช้เดินทางข้ามเครื่องได้ · MCP ต่อเฉพาะเซิร์ฟเวอร์ของโต๊ะที่เปิดอยู่**

## เอนจิน: Devin

- **ไดรเวอร์ใหม่คุยกับโปรแกรมของ Devin ผ่าน ACP ของตัวมันเอง** เปิด `devin acp` บน stdio — บัญชี แพลน รายชื่อโมเดล และโหมดมาจากโปรแกรมนั้นทั้งหมด Aetox ไม่เก็บ credential ของ Devin ไว้เองสักตัว
- **รายชื่อโมเดลกับระดับ effort ถามจากตัวโปรแกรม** ด้วย session เปล่าที่ไม่คิดเงิน แคตตาล็อกจึงเป็นสิ่งที่โปรแกรมนั้นบอกในวันนี้ ไม่ใช่ตารางที่เรากรอกไว้แล้วค้าง
- **สี่โหมดของ Devin** Smart · Ask · Plan · Bypass พร้อมเทสต์ที่บังคับว่าทุกไดรเวอร์ต้องมีโหมดเริ่มต้น ไม่มีตัวไหนเปิดมาแล้วไม่มีโหมด
- **ขั้นลงชื่อบอกคำสั่งของมันเอง** `devin auth login` และแถวเอนจินที่ยังไม่มีโลโก้ค่ายแสดงชื่อ Devin แทนช่องว่าง
- **ปุ่มเพิ่มโฟลเดอร์ถูกซ่อนกับไดรเวอร์นี้** เพราะ `devin acp` ไม่รับ `--add-dir` — ซ่อนดีกว่ากดแล้วไม่มีอะไรเกิดขึ้น
- **กฎ executable ที่ใช้ร่วมกัน** แยกกฎกลางของเอนจินแบบเนทีฟให้ OpenCode เรียกใช้ร่วม ไม่มีสำเนาที่สองให้เพี้ยนกันทีหลัง

## เอนจิน: เปิด/ปิดได้ทีละตัว และใช้ได้ทั้งสองโต๊ะ

- **สวิตช์บนการ์ดของแต่ละเอนจิน** เก็บในคอลัมน์ `enabled` ของโปรไฟล์อะแดปเตอร์ พร้อม migration แบบมี guard ที่รันซ้ำได้ และเปิดทุกแถวเดิมไว้ก่อน — ไม่มีใครตื่นมาเจอเอนจินหาย
- **แถวที่ปิดหายจากแถบเอนจิน ข้ามตอนเปิดแชท และแชทที่ค้างอยู่ถูกจัดคิวกลับ Aetox** ค่าเริ่มต้นไม่เลือกอะแดปเตอร์ที่ปิดหรือถูกลบ
- **โต๊ะ Editor ใช้เอนจินภายนอกได้แล้ว** ไม่ใช่แค่โต๊ะ Coding และเปิดหน้าจัดการได้แม้ยังไม่มีแชท
- **เครื่องที่ติดตั้งอยู่แล้วเห็น Devin** ผ่าน seed ใน migration ไดรเวอร์ที่เพิ่มเข้ามาทีหลังจึงไปถึงร้านที่มีข้อมูลอยู่แล้วได้ ไม่ต้องล้างโปรไฟล์
- **`App.RunningCalls()`** ให้ host ถามได้ว่ายังมี tool call ค้างอยู่ไหมก่อนสร้าง App ใหม่

## แชท: โมเดลที่ตอบได้เทิร์นเดียว และปุ่ม "ไม่รอ"

- **คำปฏิเสธ "multiturn chat is not enabled" กลายเป็นคำที่บอกทางออก** ตรวจจับทั้งทาง endpoint และ stderr ของเอนจินภายนอก ดึงชื่อโมเดลที่ถูกปฏิเสธออกมา แล้วบอกว่าโมเดลนี้รับบทสนทนาที่มีประวัติไม่ได้ ต้องเปลี่ยนโมเดล — ใช้ทั้งตอนเทิร์นล้มสด ๆ และตอนเปิดแชทกลับมา ข้อความดิบของผู้ให้บริการยังอยู่ใต้ข้อความนั้น
- **ปุ่ม "ไม่รอ" บอกได้ว่าหยุดไม่ได้เพราะอะไร** ผลของการหยุดมีสามแบบ: หยุดได้ · ไม่มีงานนั้นแล้ว · ติดต่อเอนจินไม่ได้ — แต่ละแบบขึ้นคำของตัวเอง แทนที่จะทิ้งคำตอบไปเฉย ๆ
- **แถวที่รออยู่ปิดพร้อมหมายเหตุ** เมื่อเอนจินไม่มีงานนั้นแล้ว แทนที่จะปล่อยให้นาฬิกาเดินค้างเหนือสิ่งที่ไม่มีอยู่จริง และแถวที่ปิดแล้วไม่เขียนอะไรเพิ่ม
- **การนับงานค้างรวมงานที่ parked** `RunningCalls()` นับ running + parked ให้ host ถามก่อนสร้าง executor ใหม่ คำสั่งหยุดของแถวที่ยังรออยู่จึงไม่หลุดไปถึงงานอื่น
- **`StopToolCall` ตอบตามจริง** true เฉพาะงานที่แชทนั้นกำลังรอจริง และ false สำหรับแชทหรือ ref ที่ไม่มี

## เอดิเตอร์: โหมดเขียนเปิดได้ทุกเอนจิน

- **สวิตช์โหมดเลิกซ่อนปุ่มเขียนด้วย lock หรือ disabled** Editor เปิดได้แม้แชทนั้นรันเอนจินอื่น หรือกำลังรอสลับเอนจิน
- **จุดทำงานและตัวนับแสดงเฉพาะฝั่งที่มีเรื่องบอก** ไม่เว้นช่องว่างที่คนอ่านเป็นความผิดพลาด และจุดย้ายมาอยู่ฝั่งเขียนเองเมื่อแชทในแผงข้างกำลังทำงาน
- **ตัวเลือกเอนจินเปิดรายการอะแดปเตอร์จากไซด์บาร์ได้เสมอ** เลือกเอนจินให้แชทได้เฉพาะเมื่อแชทนั้นรันเอนจินได้ และไดอะล็อก "ใช้ไม่ได้" ถูกตัดออก
- **หัวเมนูอ่านชื่อเอนจินผ่าน `codeEngineLabel`** ชื่อจึงตรงกันทุกที่ที่มันปรากฏ

## เติมโค้ด: ปิดเมื่อแชทใช้เอนจินภายนอก พร้อมบอกเหตุผล

- **`FillSettings` มี `available` กับ `reason`** และ `FillCode` ข้ามด้วย `external-engine` เมื่อแชทเขียนโค้ดด้วยเอนจินภายนอก — นั่นไม่ใช่โค้ดที่ Aetox เติมให้
- **ตัวแก้ไขหยุดขอ ghost text เมื่อ `available` เป็น false** และรับคำตัดสินจากผลการขอ (`external-engine`, `no-provider`) มาใช้ต่อ พร้อมถามการตั้งค่าใหม่เมื่อสลับเอนจินของแชท
- **แถบเครื่องมือไฟล์ขึ้นป้ายสั้น "ปิดอยู่"** พร้อมคำอธิบายเต็มใน tooltip แทนข้อความปฏิเสธจาก harness
- **การ์ด FillBrainCard แสดงสถานะหยุด** เพราะเอนจินภายนอกหรือยังไม่มีโมเดล แทนบรรทัด "ตอนนี้ใช้…" ที่อ่านไม่ออกว่าทำไมไม่ทำงาน
- **แถบหัวไฟล์ตัดเนื้อหาและไม่ล้นไปทับไฟล์ข้างเคียงในโหมดแบ่งจอ**

## แท็บไฟล์: ปุ่มปิดหลบเมื่อพื้นที่แคบ

- **แถบวัดความกว้างของตัวเอง** ด้วย `container-type: inline-size` แทนที่จะอิงความกว้างหน้าต่าง
- **แคบกว่า 320px ปุ่มปิดถูกซ่อนทั้งแถว** (เช่นในแบ่งจอที่บานหน้าต่างเหลือ ~180px) ไม่ถูกตัดเหลือเศษที่ขอบ
- **ปุ่มปิดทั้งหมดยังใช้ได้ผ่านเมนูแท็บ** ซึ่งมีคำสั่งปิดครบทั้งสี่แบบ จึงให้ปุ่มนี้เป็นตัวหลบก่อนเพราะมันปิดทั้งแถว

## เอนจินภายนอก: ประกาศไฟล์ที่เขียนตอนจบเทิร์น

- **เก็บพาธที่ tool result บอกว่าเขียนไว้ แล้วประกาศเป็น `files-changed` ตอนจบเทิร์น** พร้อมแปลง absolute path เป็นพาธเทียบรากแซนด์บ็อกซ์ให้ตรงกับแท็บที่เอดิเตอร์รู้จัก
- **เทียบสถานะ working tree ก่อน/หลังเทิร์น** (สถานะ + จำนวนบรรทัดที่เปลี่ยน) เพื่อจับไฟล์ที่เขียนเองแม้ไม่มีอีเวนต์บอก หรือไฟล์ที่ถูกแก้ค้างอยู่ก่อนแล้ว
- **เลื่อนการรีบิลด์ session config เมื่อยังมีเครื่องมือทำงานค้างใน executor** ไม่ใช่แค่เทิร์นที่ลงทะเบียนไว้ คำสั่งหยุดจึงไม่ตอบว่าไม่มีอะไรให้หยุดทั้งที่ยังมีงานวิ่งอยู่

## MCP: ต่อเฉพาะเซิร์ฟเวอร์ของโต๊ะที่เปิดอยู่

- **ของเดิม** Deferred ครอบเฉพาะเซิร์ฟเวอร์ที่มีแต่ agent ถือ ส่วนตัวที่ผูกกับโต๊ะถูก spawn + handshake + `tools/list` ทุกครั้งที่เปิดแอป ไม่ได้นั่งโต๊ะนั้นก็ตาม
- **ตอนนี้ Deferred คิดจากโต๊ะของแต่ละ session** Manager ถูกสร้างด้วยโต๊ะตอน bootstrap และ re-stamp เมื่อสลับโต๊ะ (`SetDeferred` ไม่ปิด connection เดิม) ส่วน `rebuildMCP` reconcile ด้วยโต๊ะของ session — เซิร์ฟเวอร์ของโต๊ะอื่นรอจนมี session ที่ต้องการดึงขึ้นมา (`RegisterFor`)
- **หน้า MCP เติมบรรทัดอธิบาย** ว่าโต๊ะที่ไม่ได้ติ๊กจะไม่ถูกต่อตอนเปิดแอปและไม่เห็นเครื่องมือของตัวนั้น

## ความจำ: จำภาษาที่ผู้ใช้ใช้

- **ภาษาถูกถอดออกจากรายการห้ามของตัวสรุปบทสนทนา** เดิมมันอยู่ในรายการเดียวกับคำผิดและโทนเสียง ทั้งที่ภาษาคือสิ่งที่ตัดสินภาษาของทุกคำตอบถัดไป — ที่ผู้ใช้เจอว่าตอบอังกฤษทั้งที่คุยไทยก็มาจากตรงนั้น
- **ตอนนี้ภาษาเป็นหนึ่งในบรรทัดที่ควรเก็บ** เมื่อข้อความทั้งแชตเป็นภาษาเดียวกัน ให้เขียนชื่อภาษานั้นเป็นภาษานั้น
- **ยังผ่านการ์ดอนุมัติเดิม** เสนอเป็นบรรทัดโปรไฟล์ ผู้ใช้กดเก็บเอง ไม่มีการเขียนไฟล์ความจำอัตโนมัติ และไม่แตะพรอมป์กลาง

## ตั้งค่า: โปรไฟล์ที่เดินทางข้ามเครื่องได้

- **allow-list ของ `internal/settingsprofile` มี 57 ค่า** ที่เป็นของผู้ใช้เดินทาง ส่วน path, คีย์, ไฟล์โมเดลเสียง และไฟล์ workflow อยู่กับเครื่อง พร้อมรายงานว่าอะไรต้องตั้งใหม่ที่ปลายทาง
- **ขีดจำกัด 512 KB · 400 รายการต่อช่อง · ชื่อ 120 ตัวอักษร** เกินหรือเป็นโปรไฟล์ว่างปฏิเสธทั้งใบ ไม่เขียนทับค่าเดิมเลย
- **หน้าตั้งค่ามีหมวดโปรไฟล์ตั้งค่า** การ์ดไฟล์กับแผนทีละแถวก่อนกดใช้ เห็นทุกค่าที่จะเปลี่ยนก่อนมีอะไรถูกเขียนลงเครื่อง
- **ขีดจำกัดที่ต้องรู้** การซิงก์ผ่านบัญชีอีเมลยังไม่มีที่เก็บบนคลาวด์ให้ต่อ รุ่นนี้จึงเป็นครึ่งที่ใช้ได้จริง: ไฟล์โปรไฟล์ที่ผู้ใช้พาไปเอง
- **แก้บั๊กที่เจอจากการกดใช้จริง** โปรไฟล์ที่ตรงกับเครื่องทุกค่าแล้ว Go ส่ง `changes` เป็น null ทำให้หน้าจออ่าน `.length` ของ null และไม่ขึ้นการ์ด "ไม่มีอะไรจะเปลี่ยน"
