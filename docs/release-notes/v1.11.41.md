# 🐧 Aetox v1.11.41

วันที่ 27 พฤศจิกายน 2026

รุ่นแรกที่มีแอป Linux ให้ดาวน์โหลด: แพ็ก `.deb` สำหรับ Ubuntu กับ Debian และ tarball ที่อัปเดตตัวเองได้ ก่อนออกรุ่นได้ติดตั้งจริงบนห้า distro เปิดแอปบน X11 และ Wayland และรันเทสต์ทั้ง repo บนเคอร์เนล Linux ระหว่างทางเจอบั๊กที่ Windows ปิดบังไว้หลายตัว ตัวที่หนักสุดคือด่าน shell ที่ปล่อยให้อ่าน key ใน `~/.ssh` ได้บน Linux และ key ของ credentials ที่สอง process อาจสร้างคนละตัว รุ่นนี้ยังแก้ประตูผู้ช่วย/โค้ดให้กลับมาเจอแชตเดิมทุกทางที่ออกไป

## ด่าน shell บน Linux: `~` ไม่ใช่ช่องโหว่ และ deploy ผ่าน ssh ได้

- **เดิม** ด่านอ่าน `~/.ssh/id_rsa` เป็นโฟลเดอร์ชื่อ `~` ในโปรเจกต์ แต่ shell ของ Linux แปลง `~` เป็นโฟลเดอร์ home จริง คำสั่งอย่าง `cat ~/.ssh/id_rsa`, `timeout 60 cat ~/.ssh/deploy_key` และ `sudo -u root cat ~/.ssh/...` จึงผ่านด่านได้ · คำสั่งที่ส่งไปรันบนเซิร์ฟเวอร์ (`ssh prod "cd /srv/app && git pull"`) ถูกตรวจเป็น path ในเครื่องเรา deploy ผ่าน ssh บน Linux จึงถูกปฏิเสธทุกครั้ง
- **ตอนนี้** (`ea03fa0e8`) ด่านแปลง `~` เป็น home ก่อนตรวจ เหมือนที่ shell ทำ · path แบบ `/...` ในคำสั่งปลายทางของ ssh เป็นของเครื่องปลายทาง ยกเว้นสามอย่างที่ยังเป็นของเครื่องเรา: ที่เก็บความลับ (เพราะปลายทางอาจเป็นเครื่องนี้เอง เช่น `ssh localhost`), path ที่ขึ้นต้นด้วย `~` และ redirect (`<`, `>`) ที่ shell ในเครื่องเปิดเอง · key ที่ส่งให้ `ssh -i` เป็น path เต็มก็ไม่ถูกปฏิเสธซ้ำแล้ว

## ห้องรหัสสำคัญ: เอเจนหยิบคีย์ไปใส่ไฟล์ได้เอง โดยโมเดลไม่เห็นค่า

- **เดิม** หน้าจอเรียกห้องว่า "รหัสสำคัญ" แต่ข้อความที่โมเดลเห็นเรียกห้องว่า "ความลับ" · เครื่องมือ `secret_list` อยู่ในแพ็ก `services` ที่โต๊ะโค้ดกับ editor ไม่มี จึงไม่เคยมีใครเห็นเครื่องมือนี้เลย · เปิด `vault.json` หรือ `.env` ไม่ได้และไม่บอกว่ามีทางอื่น
- **ตอนนี้** (`534f93954`, `2cd37d77b`) คำที่โมเดลเห็นเรียกห้องว่า รหัสสำคัญตรงกับหน้าจอ และ `vault.json` ถูกปฏิเสธพร้อมบอกทาง (`secret`, `{{secret:ชื่อ}}`, `secret put`) · แพ็ก `secret` มีสามทางที่ค่าคีย์ไม่ผ่านโมเดล
  - `put` เขียน `VAR=ค่า` ลงไฟล์ในโปรเจกต์ เฉพาะไฟล์ที่ git ignore (ไฟล์ที่ track อยู่หรือจะถูกคอมมิตถูกปฏิเสธ) แทนบรรทัดเดิม คง line ending และถามอนุมัติแบบเขียน
  - `clip` เก็บข้อความใน clipboard เป็นคีย์ใหม่แล้วล้าง clipboard (หลายบรรทัดปฏิเสธ)
  - shell `save_output_as` เก็บ output ของคำสั่ง (เช่น `gh auth token`) ลงห้องแทนที่จะกลับไปหาโมเดล · `{{secret:ชื่อ}}` ใช้ใน env ของ `launch.json` ได้ dev server จึงได้คีย์โดยไม่มีสำเนาบนดิสก์
- vault ถูกโหลดตั้งแต่เปิด session เพื่อเซ็นเซอร์ทุกค่าตั้งแต่รอบแรก · ชื่อที่ซ้ำกับคีย์ที่มีอยู่ถูกปฏิเสธ ไม่เขียนทับของที่คนพิมพ์ไว้
- ลองด้วยประโยคจริงบน dev: รอบที่สาม `secret put` เขียน `GITHUB_CLIENT_SECRET` ลง `backend/.env` ได้ และค่าไม่อยู่ใน `tool_runs`, ข้อความ หรือ engine log
