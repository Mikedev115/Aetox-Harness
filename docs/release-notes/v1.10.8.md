## ขั้นที่จบแล้วเป็นบรรทัดเดียว แล้วพับเก็บตอนตอบเสร็จ

เจ้าของ 20 ต.ค. ชี้ภาพหน้าจอ: "ทำให้มันพับได้ได้ไหม" แล้วเลือกจาก lab ห้าแบบว่า "อยากได้แบบ C แล้วพับเก็บ"

- **เดิม** ทุกช่วงงานใน turn วาดสามบรรทัด: คิดเป็นเวลา N วินาที, ประโยคของโมเดล, ใช้ N เครื่องมือ
  งานที่ทำหกขั้นจึงมีสิบแปดบรรทัดคั่นระหว่างคำถามกับคำตอบ
- **รุ่นนี้**
  - ระหว่างทำ ขั้นที่จบแล้วค่อย ๆ หดเหลือบรรทัดเดียว (ประโยคแรก เวลา จำนวนเครื่องมือ) ใต้หัว "ทำไปแล้ว N ขั้น"
    ขั้นที่กำลังทำยังเต็มอยู่ด้านล่าง
  - ขั้นจะกลายเป็นบรรทัดเมื่อจบจริง คือโมเดลพูดประโยคถัดไป ผู้ใช้พิมพ์แทรก หรือ turn จบ ไม่ใช่ตอนเงียบระหว่างรอบเครื่องมือ
  - ตอบเสร็จแล้ว บรรทัดทั้งหมดพับเข้าหัว "ทำงานไป N ขั้น · ใช้ N เครื่องมือ · N วินาที" บนจอเหลือหัวกับคำตอบ
  - กดหัวเพื่อดูทุกขั้น กดบรรทัดไหนก็เห็นประโยคเต็มกับแถวเครื่องมือของขั้นนั้น ปุ่มดูความคิดอยู่ในพับเดียวกัน
  - สิ่งที่ไม่ถูกย่อเป็นบรรทัด: ขั้นที่ยังมีงานรัน งานที่มอบให้เอเจนหรือผู้ช่วย การ์ด server รูปที่วาด
    ข้อความที่ผู้ใช้พิมพ์แทรก และขั้นสุดท้าย
  - ทุกการขยับเป็นความสูงของบล็อกเดียว ใช้ท่าพับเดิมของแอป วัดจากหน้าแชทตัวจริงในเบราว์เซอร์ headless เทียบกับรุ่นก่อน
    สามรอบ: เฟรมช้าสุด 28 ms ไม่มีเฟรมยาว รุ่นก่อนช้าสุด 33–67 ms งาน 30 ขั้นได้ผลเท่ากัน

ไม่ได้ทำ: จำกัดจำนวนบรรทัดระหว่างทำไว้แค่ไม่กี่บรรทัดล่าสุด ตอนนี้แสดงทุกบรรทัด

## โต๊ะโค้ดแก้ bug แบบที่ทีมอันดับต้นทำ

- **เดิม** ใน SWE-bench-Live lite รอบที่ 3 งาน pdm-3237 ถูกแก้ผิดไฟล์เพราะไม่เคยรันคำสั่งที่พัง
  บางข้อ test ใหม่ผ่านแต่ test เดิมพัง เพราะไม่ได้รัน test ที่ครอบโค้ดที่แก้ และคำว่า "ตามสัดส่วน" ทำให้โมเดลข้ามขั้นพวกนี้
- **รุ่นนี้** คำสั่งของโต๊ะโค้ดบอกชัด:
  - งานแก้ bug ต้อง reproduce ก่อนแก้ แล้วแสดงว่าการ reproduce เดิมผ่านหลังแก้
  - รัน test เดิมที่ครอบโค้ดที่แก้
  - ก่อนบอกว่าเสร็จ ตรวจ diff ของตัวเองว่ามีแต่สิ่งที่ตั้งใจ ไม่มี debug output ไฟล์ชั่วคราว หรือบรรทัดที่ไม่เกี่ยว
