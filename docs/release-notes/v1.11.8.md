# 🪟 Aetox v1.11.8

วันที่ 12 พฤศจิกายน 2026

**รุ่นนี้เพิ่มมอด: วางลิงก์ GitHub อันเดียวแล้วได้ทั้งสกิล เอเจน คำสั่ง ห้อง และ MCP มาอยู่ในเครื่องพร้อมกัน · หน้าตั้งค่า › เกี่ยวกับคุณ บอกได้แล้วว่าโควตาพรอมป์ต์เต็มเพราะอะไร · ตั้งจำนวนมือที่ทำงานพร้อมกันได้ 1–5 · และแถบโปรเจกต์คลิกขวาได้ ปักหมุดได้ในคลิกเดียว**

## มอด — วางลิงก์เดียว ได้ทั้งชุด

- **เดิม** การติดตั้งของจากภายนอกทำได้ทีละชิ้น: สกิลชุดหนึ่ง MCP อีกชุด คำสั่งอีกที่ และไม่มีอะไรบอกว่าชิ้นไหนมาจากที่เดียวกัน ถอนก็ต้องไล่ทีละที่
- **รุ่นนี้** รีโป GitHub ที่มี `aetox-mod.json` กลายเป็นมอดหนึ่งก้อน: วางลิงก์ในแชทแล้วขอให้ติดตั้ง การ์ดขึ้นมาพร้อมส่วน "มอดนี้มีอะไรบ้าง" ที่ไล่ชื่อสกิล เอเจน คำสั่ง และห้อง พร้อมบอกว่ามี hook กับ MCP อย่างละกี่ชิ้น
- ลงเป็นโฟลเดอร์เดียวใต้ `mods/<name>/` ไม่แตะ `hooks.json` หรือ `mcp-servers.json` ที่ผู้ใช้แก้เอง — ตัวโหลดทั้งชนิดอ่านโฟลเดอร์ของมอดเป็นแหล่งที่สอง ปิดทั้งมอดด้วยไฟล์ `disabled` ถอนด้วยการลบโฟลเดอร์
- hook ของมอด **ยังไม่ทำงาน** จนกว่าจะมีไฟล์ `hooks.armed` — การ์ดบอกบรรทัดนี้ก่อนกด เพราะ hook รันคำสั่งบนเครื่องได้
- ห้องของมอดแสดงแล้วแม้เครื่องยังไม่เคยมีโฟลเดอร์ rooms มาก่อน
- **ไฟล์** `internal/modpack/` · `internal/engine/install_tool.go` · `internal/skill/mod_install.go` · `internal/config/config.go` · `desktop/rooms.go` · `InstallCard.svelte` · `locales/{th,en,zh}.ts`

## งบพรอมป์ต์บอกความจริงว่าติดที่ไหน

- **เดิม** ตัวเลขเดียวบนแถบงบพรอมป์ต์ตอบไม่ได้ว่าที่เต็มเพราะการ์ดรอคำตอบค้างอยู่ หรือเพราะใบที่อนุมัติแล้วกินที่เกิน และแถบขึ้นไม่เต็มทั้งที่ของถูกตัดออกไปแล้ว
- **รุ่นนี้** สองเมเตอร์แยกกันบนหน้าตั้งค่า › เกี่ยวกับคุณ › "รูปแบบการทำงานของคุณ": **รออนุมัติ N / 8** และ **ใช้อยู่ N ใบ · ต้องการ X / Y B** พร้อมบรรทัด "ส่งได้ S ใบ · อีก R ใบไม่มีที่" เมื่อมีใบถูกตัด
- เมเตอร์ที่สองนับ "ที่อนุมัติแล้วต้องการใช้" ไม่ใช่ "ที่ส่งได้จริง" — ตัวเลขจึงขยับเมื่ออนุมัติใบใหม่ที่ยังไม่มีที่ลง และแถบเต็ม 100% เมื่อมีใบถูกตัด ไม่ใช่ค้างที่ 65% ตามไบต์ที่ส่งได้
- การ์ดที่รอคำตอบหยุดที่ 8 ใบ รายการโชว์ 8 ใบแรกและมีปุ่ม "ดูทั้งหมด" — งานชนิดเดียวกับที่มีอยู่แล้วถูกปรับการ์ดเดิม ไม่เพิ่มใบใหม่ทับถม
- ไฟล์วิธีทำงาน (SHAPE.md) เพดานขึ้นเป็น 1.75 KB และนับเฉพาะบรรทัดที่โมเดลอ่านจริง กฎท้ายไฟล์จึงถึงโมเดลแล้ว
- **ไฟล์** `internal/journal/` · `internal/learned/learned.go` · `BrainPanel.svelte` · `locales/{th,en,zh}.ts`

## จำนวนมือที่ทำงานพร้อมกัน ตั้งได้ 1–5

- **เดิม** เพดานจำนวนเอเจนที่รันพร้อมกันเป็นค่าคงที่ในโค้ด
- **รุ่นนี้** ตั้งค่า › ตัวหลัก มีช่องตัวเลขใต้แผนผังมือ (ค่าเริ่มต้น 5 ซึ่งเป็นค่าสูงสุด) มีผลกับทุกแชทที่เปิดอยู่ทันที
- ลดเลขลงแล้วงานที่รันอยู่ไม่ถูกตัด งานใหม่รอคิวตามลำดับ · เพิ่มเลขแล้วคิวไหลต่อทันทีโดยไม่ต้องสร้างงานใหม่
- **ไฟล์** `internal/subagent/runner.go` · `internal/engine/delegate_switch.go` · `internal/config/config.go` · `Settings.svelte` · `locales/{th,en,zh}.ts`

## แถบโปรเจกต์คลิกขวาได้ และมีปุ่มปักหมุดจริง

- **เดิม** แถวโปรเจกต์ไม่มีตัวรับคลิกขวาเลย · เข็มหมุดปลายแถวเป็นเพียงสัญลักษณ์ และเมื่อชี้เมาส์ปุ่ม + กับ ⋯ มาทับจนหมุดจางหาย การปักจึงต้อง hover → ⋯ → เลือกในเมนู
- **รุ่นนี้** ปุ่มหมุดอยู่ในกลุ่มปุ่มปลายแถว (หมุด · + · ⋯) กดครั้งเดียวปัก กดอีกครั้งถอด ปักแล้วเป็นสีเน้นและยังเห็นตอนไม่ได้ชี้ · ปุ่ม + กับ ⋯ ไม่ขยับตำแหน่ง
- คลิกขวาที่แถวเปิดเมนูชุดเดียวกับ ⋯ ตรงตำแหน่งเมาส์ ถูกดึงกลับเข้ากับขอบหน้าต่างเมื่อเปิดใกล้ขอบ และปิดด้วย Escape หรือคลิกที่อื่น
- **ไฟล์** `ProjectSidebar.svelte` · `desktop/frontend/src/style.css`

## เอนจิน CLI ที่ติดตั้งอยู่ กับการเรียกเครื่องมือของเอเจน

- OpenCode 2 ที่ติดตั้งผ่าน npm หาโปรแกรมเจอแล้ว (เดิมการ์ดขึ้นว่าไม่พบ) และบัญชีที่ล็อกอินอยู่แสดงเป็น subscription หรือ api-key พร้อมชื่อเจ้า แทนที่จะว่างเงียบ ๆ
- เลขรุ่นบนการ์ดทนต่อรูปแบบที่ CLI พิมพ์มา เช่น `opencode v2.2.6` หรือ `2.1.270 (Claude Code)` — เดิมขึ้นว่าอ่านรุ่นไม่ได้ทั้งที่รันได้
- ถ้ายังไม่มีโมเดลและไม่มี credential การ์ดบอกให้รัน `opencode auth login` แทนการบอกแค่อ่านรุ่นไม่ได้
- เอเจนที่เรียกเครื่องมือที่ไม่มีในเซสชันได้ข้อความที่บอกชื่อเครื่องมือ และเรียกผิดสคีมาได้ชื่อพร้อมเหตุผลจากตัวตรวจ แทนประโยคปฏิเสธรวม ๆ — จึงแก้คำขอแล้วทำงานต่อได้ ไม่วนถามซ้ำ
- **ไฟล์** `internal/cliagent/` · `internal/mcpgateway/server.go` · `ExternalAdapters.svelte`
