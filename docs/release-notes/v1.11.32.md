# 🪟 Aetox v1.11.32

วันที่ 21 พฤศจิกายน 2026

รุ่นนี้คืนตัวเลขบริบทที่หายไปจากจอทุกครั้งที่สลับแชทกลับมาที่แชทซึ่งหลับอยู่ และปิดช่องว่างชุดสุดท้ายของแท็บเบราว์เซอร์บนลินุกซ์ — จำลองขนาดจอ อัปโหลดไฟล์ พิมพ์คีย์ และ permission ที่นับการกดของผู้ใช้จริง

## วงแหวนบริบทไม่หายหลังสลับแชท

- **เดิม** แชทที่เปิดกลับมาถูกสร้างเป็น conversation แบบ dormant (ไม่มี agent และไม่มี registry) มาตรวัดจึงคิดส่วนข้อความและบล็อกเครื่องมือได้ 0 แล้ว `contextPromptUsageFor` หักค่าประมาณที่บันทึกไว้ออกจนเหลือ 0 พอดี · ฝั่งจอทิ้งค่า 0 และปุ่มบริบทแสดงเมื่อ `used > 0` เท่านั้น วงแหวนจึงหายทั้งอันทุกครั้งที่สลับไปแชทที่พ้น 3 ช่องอบอุ่น — เริ่มตั้งแต่ `9158b1eaf` (6 พ.ย. 2026) ที่เปลี่ยนมาเปิดแชทแบบ lazy (เจ้าของ 21 พ.ย. 2026: "สลับไปมาปุ๊บ บริบทเซสชันนั้นหาย")
- **ตอนนี้** `dormantPromptEstimate` อ่านรอบล่าสุดที่ผู้ให้บริการนับไว้ (`token_usage` ของ session + model + provider เดียวกัน) เพราะแชท dormant คือแชทที่ไม่มีอะไรเปลี่ยนตั้งแต่รอบนั้น · `contextBreakdownFor` ใช้ค่านั้นเมื่อ `conv.agent` ว่าง และติดธง estimated เพราะส่วนแบ่งระหว่าง system กับ tools ยังเป็นค่าประมาณของรอบนั้น (store เก็บสองก้อนนี้รวมกันเป็น `est_fixed_tokens`)
- **ความจำของโมเดลไม่ได้หายไปด้วย** `activateConversation` ยังโหลด memory ที่บันทึกไว้ตอนแชทตื่นมาทำเทิร์นเหมือนเดิม ที่หายคือตัวเลขบนจอ
- **เทสต์** `TestContextMeterSurvivesAReopen` — เปิดแชทกลับแบบ dormant แล้ว used/max/measured ต้องเท่าเดิม · probe ก่อนแก้ reopen ให้ used=0 measured=false หลังแก้ 31209 tok measured=true · บน dev เปิดแชทเก่าแล้ว `ContextBreakdownFor` ตอบ 31209 ทันทีตอนยัง dormant และวงแหวนขึ้น 3% · แพ็กเกจ `internal/engine` ยังแดง 4 ตัวเดิมที่มีอยู่ก่อนรุ่นนี้ (ทีม/ชุดเครื่องมือ/มิเกรชัน 88)
- **ไฟล์** `internal/engine/context_meter.go` · `internal/engine/app.go` · `internal/engine/context_meter_test.go`

## CDP ที่เหลือบน WebKitGTK

- **เดิม** รอบแรกทำได้แค่ eval/แคป/PDF ทำให้จำลองขนาดจอ อัปโหลดไฟล์ผ่าน file input และพิมพ์คีย์ยังเป็นของ Windows เท่านั้น
- **ตอนนี้** `Emulation.setUserAgentOverride` ตั้งผ่าน `WebKitSettings` ของแท็บนั้น (UA แยกต่อแท็บจริง) · `setDeviceMetricsOverride`/`setTouchEmulationEnabled` ผ่าน user script ต่อแท็บ (devicePixelRatio, maxTouchPoints, ontouchstart, meta viewport) · `DOM.setFileInputFiles` ยัดไบต์จริงผ่าน DataTransfer (เพดาน 32 MiB) · `Input.insertText`/`dispatchKeyEvent`/`dispatchMouseEvent` สร้าง event ในหน้า · `captureBeyondViewport` ใช้ `SNAPSHOT_REGION_FULL_DOCUMENT` แล้ว crop ตาม clip ใน Go · `setShape` วาดขอบโค้ง/ติ่งด้วย cairo เหนือแท็บโดยไม่บังการกด
- **ยังไม่เท่า** `Input.*` เป็น event ของหน้า (`isTrusted=false`) หน้าที่ยึด `isTrusted` ยังต้องใช้ทาง JS
- **เทสต์** live test บน WSLg ผ่าน: getVersion, UA override, devicePixelRatio=3, maxTouchPoints=5, meta viewport, อัปโหลด `invoice.txt` (19 ไบต์), `Input.insertText`, key/mouse event, แคปทั้งหน้า 13,122 B และ crop 400x100 = 435 B · `go vet -tags webkit2_41 ./desktop/` ผ่าน

## permission นับคลิก/คีย์จริงของผู้ใช้

- **เดิม** `browser_permission.go` ให้ผ่านเฉพาะคำขอที่ผู้ใช้เป็นคนสั่ง (`IsUserInitiated` ของ WebView2) แต่ WebKitGTK ไม่ส่งข้อมูลนี้มาใน permission-request เลย โฮสต์ลินุกซ์จึงต้องถือทุกคำขอเป็นผู้ใช้กด — เป็นจุดที่หลวมกว่า Windows จุดเดียวที่เหลือ
- **ตอนนี้** `browser_gtk_linux.c` ฟัง `button-press-event`/`key-press-event` บน webview เก็บเวลา monotonic และ `aetox_tab_user_gesture` ตอบว่ามีการกด/พิมพ์ภายใน 5 วินาทีหรือไม่ · สคริปต์ในหน้าแตะคิวอีเวนต์ของ GDK ไม่ได้ จึงปลอมไม่ได้ (ต่างจากการอ่าน `navigator.userActivation` ซึ่งหน้าเว็บคุมได้) · `browser_linux.go` ส่งค่านี้เข้า `browserPermissionAllowed` และ log ทั้ง userInitiated และผล
- **เทสต์** `go vet -tags webkit2_41 ./desktop/` ผ่าน · live test บน WSLg ผ่านทั้งสองตัว
- **ไฟล์** `desktop/browser_gtk_linux.c` · `desktop/browser_linux.go` · `PLATFORM-SUPPORT.md`

## สถานะการทดสอบ

รันบนเครื่องเจ้าของ 21 พ.ย. 2026 หลังอัปเลขรุ่น ไม่ได้รันทั้งชุดซ้ำตาม `docs/RELEASING.md` §1:

- `go test ./internal/version/ ./internal/mobilelink/` ผ่านทั้งสองแพ็กเกจ
- `go build ./cmd/... ./internal/... ./desktop/...` ผ่าน · `go build ./...` ล้มที่ `scratch/` ซึ่ง `.gitignore` ครอบไว้ (โปรแกรมทดลองเก่าที่ไม่คอมไพล์กับ API ปัจจุบัน ไม่เกี่ยวกับรุ่นนี้)
- `go test ./internal/engine` ยังแดง 4 ตัวเดิม และ `go test ./desktop` บนลินุกซ์แดง 6 ตัวเดิม — ทั้งสองชุดแดงอยู่ก่อนรุ่นนี้ ตามที่บันทึกไว้ในคอมมิตของงานนั้น
- ยังไม่ได้รัน `./desktop` บน Windows และไม่ได้กดหน้าจอในรุ่นนี้
