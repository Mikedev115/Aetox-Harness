# 🪟 Aetox v1.10.38

วันที่ 31 ตุลาคม 2026

**รุ่นนี้วางหน้าต่างที่สองของแอปไว้ครบทั้งเส้น — แอปเดิมเปิดอีกบานในโปรเซสเดียวกัน ฝัง WebView2 ได้จริง ใช้ engine กับฐานข้อมูลชุดเดิม และได้ยิน event เท่าบานแรก — แต่ปุ่มที่เปิดมันถูกถอดออกตามที่เจ้าของสั่ง จึงยังไม่มีอะไรใหม่ให้กดบนหน้าจอในรุ่นนี้**

## หน้าต่างที่สอง — ของที่อยู่ในโค้ดจริง แต่ยังไม่มีปุ่ม

- **ปุ่มไม่อยู่บนแถบแล้ว** (เจ้าของ 31 ต.ค. 2026: "เอาปุ่มนี้ออก") ที่ถอดคือปุ่ม ไอคอน ข้อความผิดพลาดบนแถบ คีย์แปลภาษา และ CSS ของมัน สิ่งที่ยังอยู่คือตัวงานทั้งหมด — หน้าต่าง สะพานที่ให้มันเรียก `*App` ตัวเดิม การแจก event ที่ท่อเดียว และเซิร์ฟเวอร์หน้าที่จ่ายหน้าให้มัน `OpenSecondWindow` ยังเป็น binding เหมือนตัวอื่น เปิดได้จากที่ไหนก็ได้ที่เรียกมัน
- **ทำไมไม่ใช่โปรเซสที่สอง** โปรเซสที่สองแปลว่า engine ที่สอง ตัวเขียนฐานข้อมูลตัวที่สอง และบานที่สองที่ตายตามบานแรก รุ่นนี้จึงใช้หน้าต่าง WebView2 ระดับบนที่มีอยู่แล้วในโปรเจกต์ (แท็บที่ detach และบาน export ของ deck) ไม่ได้สร้างของใหม่ สองบานจึงเป็นแอปเดียวกันจริง: engine เดียว ฐานข้อมูลชุดเดียว ปิดบานที่สองแล้วแอปอยู่ต่อ
- **สะพานให้ทุก binding ใช้ได้โดยไม่แก้ไฟล์เดิม** Wails ใส่ `window.go.main.App` กับ `window.runtime` ให้บานที่มันสร้าง บานที่สองจึงได้ตัวแทนของสองตัวนั้น (`frontend/src/lib/secondWindow.ts`) แล้วคุยกับ `*App` ตัวเดิมผ่าน `postMessage` และ reflection (`desktop/secondbridge.go`) — เมธอดที่ไม่ได้เปิดให้เรียกถูกปฏิเสธ และ log บอกชื่อเมธอดกับเหตุผล
- **event มาทางท่อเดียว** หน้าต่างที่สองได้ยินทุก event จาก `a.emitEvent` (`desktop/events.go`) ซึ่งเป็นจุดที่ทุก event ผ่านอยู่แล้ว event ที่เพิ่มเดือนหน้าจึงถึงทั้งสองบานเองโดยไม่มีใครต้องต่อทีละตัว
- **หน้าของบานที่สองเสิร์ฟจาก loopback ในโปรเซสนี้** (`desktop/secondserve.go`) ด้วยไฟล์ชุดเดียวกับที่ฝังให้ Wails

## สองอาการที่เจอตอนกด และวิธีที่แก้

- **ฝังไม่สำเร็จ `0x8007139f`** WebView2 สร้าง environment ได้ แต่ปฏิเสธ controller ด้วย `ERROR_INVALID_STATE` เพราะบานที่สองขอใช้โปรไฟล์ `app` ตัวเดียวกับบานหลักที่ Wails ถือ environment อยู่แล้ว และ thread ของบานใหม่ใช้บริบท DPI คนละชุดกับหน้าต่างหลัก แก้ทั้งสองอย่างตามสูตรที่แท็บเบราว์เซอร์ใช้อยู่ (โปรไฟล์ของตัวเอง และคัดบริบท DPI จากหน้าต่างหลัก) และให้เหตุผลจริงของ engine ติดไปกับข้อความที่ผู้ใช้เห็น แทนประโยคที่ไม่มีสาเหตุ
- **ขึ้นหน้าต้อนรับเหมือนติดตั้งใหม่** บานที่สองเสิร์ฟจาก loopback จึงเป็น origin อีกอัน และ `localStorage` ผูกกับ origin: บานใหม่เริ่มจากศูนย์ และศูนย์คือหน้าตาของ "ติดตั้งใหม่" (wizard, ธีมปริยาย) ของที่ต้องส่งไปจึงไม่ใช่ธีมกับภาษาแยกชิ้น แต่เป็นค่าที่แอปจำไว้ทั้งชุด — `PREFERENCE_KEYS` ตัวเดียวกับที่ปุ่ม replay ใช้ล้าง (`firstRun.ts`: `exportedPreferences` / `adoptPreferences`) เขียนลง storage ของบานที่สองก่อน init ตัวแรกอ่าน ไม่ใช่การย้ายค่าตั้งไป Go และไม่ต้องมีที่อ่านค่าเฉพาะหน้าใน theme/i18n/typeScale

## ความมั่นใจของรุ่น

- `go test ./desktop/` ผ่านทั้งแพ็กเกจ (64.6s) — เทสต์ของงานนี้ยิงเมธอดจริง/ผิดรูป/panic ผ่านสะพาน, หน้า SPA + route + path traversal, event ถึงบานที่สอง, กดซ้ำแล้วยกบานเดิม, ปิดแล้วเปิดใหม่ได้ และคำถามเรื่องหน้าต่างฝั่ง Go
- เทสต์หน้าจอ `secondWindow` / `secondWindowPrefs` / `localeGuard` / `doorStrip` / `shellSwitch` ผ่าน 36 ข้อ รวมการยืนยันว่า export/adopt รอบเดียวได้ค่าเดิม คีย์นอกรายการไม่ถูกเขียน ค่าที่ไม่ใช่สตริงไม่ถูกเขียน และ address พา door + prefs ไปครบ
- `go vet ./desktop/` ผ่าน · `svelte-check` เหลือ 8 error เดิมใน `Capability.svelte` และเทสต์ 3 ไฟล์ ซึ่งมีมาก่อนรุ่นนี้
- **ฐานข้อมูลไม่เปลี่ยน** ไม่มีขั้น migration ใหม่ในรุ่นนี้ (`internal/engine/db.go` เหมือน v1.10.37 ทุกไบต์) ฐานข้อมูลเดิมจึงเปิดด้วยรุ่นนี้ได้ตามเดิม
- **ข้อจำกัดที่ต้องบอกตรง ๆ** ทางเดียวที่เปิดบานที่สองได้ตอนนี้คือเรียก binding `OpenSecondWindow` — ไม่มีปุ่มบนหน้าจอ จึงยังไม่มีการกดจริงยืนยันหน้าตาของบานที่สองในรุ่นนี้ ตัวงานคุมด้วยเทสต์ฝั่ง Go และฝั่งหน้า
