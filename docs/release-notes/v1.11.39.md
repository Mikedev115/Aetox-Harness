วันที่ 26 พฤศจิกายน 2026

รุ่นนี้เป็นรอบที่สองของหน้าแชทและแถบข้าง: แถบบนเหลือไอคอนล้วนและทุกปุ่มมีหน้าที่เดียว หน้าแชทมีแถวที่อ่านจากโปรเจกต์เองขึ้นมาให้เห็นก่อนส่งงาน และแถบข้างเป็นแถวเดียวทั้งสองโต๊ะ ระหว่างทางมีของที่ทำให้อ่านงานเก่าและงานที่กำลังทำได้ตรงขึ้นอีกสี่เรื่อง: ไทม์ไลน์บอกคนเขียนและเวลาที่ผ่านมา, สรุปเซสชันที่โมเดลเขียนเอง, สกิลเรียกด้วยชื่อสั้น และไกด์บนโต๊ะโค้ดที่ไม่พาเดินออกจากโต๊ะ

## แถบบนไอคอนล้วน แถบข้างแถวเดียว และหน้าแชทที่บอกงานค้างก่อนส่ง

- **ตอนนี้** (`cbae8bd13`) แถบบนเหลือไอคอนล้วน: ประตู แชท/โค้ด เป็นสองไอคอนพาดหัวคอลัมน์ คำอยู่ที่ tooltip และกดประตูที่อยู่ในอยู่แล้วคือกลับไปห้องแชท · ย่อ ≡ กับเต็ม ▢ อย่างละหนึ่งหน้าที่และติดสว่างตามรูปที่คอลัมน์เป็น · ปุ่มแชทใหม่ (+) ย้ายไปหัวแถบข้าง · ชื่อแชตเป็นเมนูที่มี เปลี่ยนชื่อ คัดลอก id เก็บ และลบ (ยืนยันสองจังหวะ)

- หน้าแชท: แถวที่อ่านจากโปรเจกต์เอง (ไฟล์ยังไม่คอมมิต, คอมมิตยังไม่พุช, แชทล่าสุดในโปรเจกต์) ขึ้นก่อนชุดที่แจกและกินที่ได้สูงสุดสามช่อง · แถวสถิติซ่อนเมื่อยังไม่มีข้อความ · โปรเจกต์/แบรนช์/ทีม รวมเป็นกรอบเดียวมีตัวคั่น
- composer: ระหว่างคอลัมน์ glide รอจบแล้ว fit ครั้งเดียวแทนการวัดทุกเฟรม (วัดได้ 54 ครั้งที่เขียนความสูงต่อการกดสวิตช์ครั้งเดียว) · ตัวเฝ้าความสูงของ pane กรองเฉพาะส่วนสูง ไม่ fit ซ้ำเมื่อความกว้างเปลี่ยน
- เมนูชื่อแชตเปิดด้วยการกดที่ชื่อ โฟกัสจึงอยู่บนปุ่ม (`6a3aab2b5`): Escape ปิดเมนูได้แล้ว และเมื่อกำลังแก้ชื่อ Escape ออกจากช่องเปลี่ยนชื่อก่อน (tester 26 พ.ย. 2026: «กด Escape แล้วเมนูยังอยู่»)

## สรุปเซสชัน: เวลาที่ใช้ กรอบพับ และสรุปที่โมเดลเขียน

- **เดิม** แผงหัวมุมบอกได้แค่ว่าห้องอ่าน/แก้อะไร ไม่บอกว่าใช้เวลาเท่าไรและคุยเรื่องอะไร (owner 25 พ.ย. 2026: «แสดงว่าเซสชันนี้ใช้มานานแค่ไหน … รายละเอียดเซสชันมาแสดงตรงนี้แทน»)
- **ตอนนี้** (`e09944bb4`) `engine/session_digest.go` กับ migration 90 (`session_digests`) เก็บจำนวนข้อความ ช่วงเวลาที่อ่านจากแถว `sessions` และสรุปพร้อม `upto_id` ของข้อความสุดท้ายที่อ่าน — ข้อความใหม่กว่านั้นทำให้ `Stale` จริง สรุปเก่าจึงไม่ดูเหมือนของวันนี้ · binding `SessionDigest` อ่านฟรี ไม่เรียกโมเดล และ `SessionDigestRefresh` เรียกครั้งเดียว เก็บแล้วอ่านซ้ำไม่จ่ายอีก
- `SessionStrip`: chip เวลาที่ใช้ บล็อกสรุป + บูลเลต + «สรุปใหม่» และ «แหล่งที่มา» กับ «ไฟล์ที่สร้าง/แก้» เป็นกรอบพับที่หุบไว้ก่อน กดกาง · ทางไปแผงผลงานเดิมย้ายไปท้ายกรอบไฟล์
- คำขอ JSON ตรง ๆ แทนการบังคับ tool call เพราะผู้ให้บริการบางเจ้าตอบกลับมาเป็น error แปลง JSON ของฝั่งมัน (25 พ.ย. 2026) และงานนี้ต้องการแค่สองฟิลด์
- ลูปอ่านบทสนทนาในสรุปใช้ `query-direct` อย่างมีเหตุผล (`51f50257f`): เปลี่ยนไปใช้ `eachRow` ไม่ได้เพราะ `eachRow` ข้ามแถวที่ scan พลาดแล้วไปต่อ ซึ่งทำให้สรุปถูกสร้างจากบทสนทนาที่ยังไม่ครบและอ่านเหมือนครบ — ลูปนี้ abort แทน และมี `rows.Err()` อยู่แล้ว

## ไกด์บนโต๊ะโค้ดไม่พาเดินออกจากโต๊ะ

- **เดิม** `guide.start()` เรียกเส้นทาง `capabilities` ตรง ๆ ทุกครั้งที่เปิดไกด์ ทั้งที่คอลัมน์ความสามารถไม่ถูกวาดบนโต๊ะโค้ดเลย กด F1 กลางงานโค้ดจึงได้ทัวร์ห้องของโต๊ะผู้ช่วยที่เดินผ่านประตูออกไป โดยไม่มีใครขอ
- **ตอนนี้** (`f6d5b638f`) นโยบาย «เปิดไกด์แล้วไปทัวร์ไหน» อยู่ที่ `routes.ts` `openingRouteFor(desk)` ตาม `guide-architecture.md` §2: ผู้ช่วย = ห้องความสามารถตามเดิม (owner 23 พ.ย. 2026) · โค้ด = ไม่มีทัวร์ เพราะทุกเส้นทางของโต๊ะโค้ดกดปุ่มเอง ซึ่งการเปิดไกด์ไม่ควรทำแทนคนที่กำลังทำงานอยู่ · `guideState.start()` อ่านค่านั้นแทนการเขียนชื่อเส้นทางเอง

## หน้าต่าง «เพิ่ม provider» ไม่เปิดมาเกาะเชลฟ์ที่เพิ่มครบแล้ว

- **เดิม** หน้าต่างเลือกเชลฟ์ครั้งเดียวตอน mount จาก `addable()` ที่นับจาก `enabled` ซึ่งยังโหลดไม่เสร็จ หน้าต่างจึงเกาะ «แพ็กเกจที่สมัครไว้» ตอนที่มันยังดูเหมือนเพิ่มได้ 7 เจ้า พอ `enabled` มาถึง การ์ดกลายเป็น «เพิ่มแล้ว» ทั้งแถว เลขบนเชลฟ์หาย แต่เชลฟ์ไม่ย้ายตาม (mike 24 พ.ย. 2026: ภาพหน้าจอที่เชลฟ์ซึ่งเปิดมาไม่มีเลขกำกับ)
- **ตอนนี้** (`315f70b13`) เชลฟ์เลือกใหม่ได้ทุกครั้งที่ข้อมูลเปลี่ยน จนกว่าผู้อ่านจะกดเลือกเอง (`shelfPicked`) · เชลฟ์ที่ทุกการ์ดเปิดครบแล้วบอกออกมาเป็นบรรทัดใต้ชิป แทนที่จะเงียบ (`settings.providerShelfFull`, th+en)
