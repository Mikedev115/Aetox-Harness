# 🧩 Aetox v1.9.22

วันที่ 12 ตุลาคม 2026

**สลับแชทเร็วขึ้น แถบซ้ายแบ่งแชทเป็นสัปดาห์และโชว์แค่ 5 ล่าสุด หน้าโค้ดมีประวัติของโปรเจกต์ และเครื่องมือค้นกับแก้ไฟล์ไม่ช้าอย่างเมื่อก่อน**

## แถบซ้ายและประวัติแชท

- แถบซ้ายของผู้ช่วยโหลดแค่เดือนนี้ จัดกลุ่มเป็นสัปดาห์ (ตั้งเป็นวันหรือเดือนได้) และโชว์ 5 แชทล่าสุด กด "เพิ่มเติม" เพื่อดูที่เหลือ
- ห้องสมุดเซสชันรายเดือนเป็นหน้าเต็ม เปิดจากเมนู ⋯ ของหัวแชท และจากแถว "แชทเดือนก่อนๆ"
- หน้าโค้ดมี "กำลังทำ" อยู่บนสุด (แชทที่รันอยู่ รอคำตอบ หรือยังไม่อ่าน) แต่ละกอง Agent/Editor โชว์ 5 แชทล่าสุด
- "ประวัติทั้งหมดของโปรเจกต์" แบ่งรายวัน กรอง Agent/Editor ค้นได้ และซ่อนแชทสั้น (≤ 2 ข้อความ) เป็นค่าเริ่มต้น
- ก่อนหน้านี้ที่หน้าโค้ดรายการยาวหลายร้อยแชท (โปรเจกต์ Aetox มี 147 แชท วันเดียว 35) ตัดเป็นเดือนก็ไม่ช่วย

## สลับแชทเร็วขึ้น

- เก็บ engine ของ 3 แชทล่าสุดไว้ สลับกลับมาไม่ต้อง bootstrap ใหม่ (วัดใน dev: สลับ 8 ครั้งระหว่าง 3 แชท bootstrap เหลือ 3 ครั้งจาก 8)
- แถบซ้ายไม่อ่านรูปปกโปรเจกต์ทุกครั้งที่สลับ ข้อมูลต่อการสลับจาก 2.4 MB เหลือ 71–309 KB
- ตั้งค่าหรือหน้าปัดเปลี่ยน แชทที่เก็บไว้จะถูกสร้างใหม่ ไม่กลับมาด้วยค่าเก่า

## เครื่องมือค้นและแก้ไฟล์

- แก้ไฟล์พร้อมกันหลายเลน (เช่น helper แก้ข้าง main agent) ตัวเช็ค LSP ไม่แย่งคำตอบกันแล้ว วัดใน worktree สองเลน 24 edits: 93.5 วิ (timeout 11 ครั้ง) เหลือ 7.6 วิ ไม่มี timeout
- `grep` อ่านไฟล์ทีละ 16 และไม่หลุดเข้า `output/` กับ `scratch/` เมื่อ git ตอบช้า (เคยกิน 11 นาที 17 วิ ต่อหนึ่งการค้น) วัด: 8 searches 14.4 → 4.1 วิ
- `trace` ครั้งแรกสร้าง index 29.3 → 7.0 วิ และ `repo_map` ได้แผนที่ครบแม้ cache เย็น (เดิมตัดที่ 605 ไฟล์ ตอนนี้ครบ 1,888)

## ไม่ได้ทำ

- ให้ `edits` เช็คหลายไฟล์พร้อมกัน ลองแล้วช้ากว่าเดิม (7 ไฟล์ 1.0 → 2.2 วิ เพราะ gopls typecheck ซ้อนกัน)
- ค้นด้วยมากกว่า 16 workers แทบไม่เร็วขึ้น (400 ไฟล์: 1.4 / 1.4 / 0.9 วิ ที่ 16/48/96)

## อื่น ๆ ในรุ่นนี้

- วงแหวนบนบรรทัดพิมพ์ของเทอร์มินัล (มือผู้ช่วย) อยู่ 4 วินาทีแล้วหายเอง ไม่ค้างจนมีข้อความใหม่ และคลิกในช่องของแท็บนับว่าคนเห็นแล้ว
- จับเวลาช่วง chair MCP, permissions/hooks, task tools และ NewApp ในขั้นเปิดแชท ดูใน debug log ได้ว่าช้าตรงไหน
- release.yml รัน suite ทุกครั้ง และ RELEASING.md มีทางบิ้วในเครื่องเมื่อ Actions ไม่เริ่มงาน
