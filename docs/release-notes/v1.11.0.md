# 🪟 Aetox v1.11.0

วันที่ 8 พฤศจิกายน 2026

**รุ่นนี้ตัดของที่ถามคำถามผิดออกจากเส้นทางของผู้ใช้ — ทีมเหลือชั้นเดียวที่ทำงานได้จริง โต๊ะ specialized ยุบเข้า assistant และวิซาร์ดเปิดเครื่องครั้งแรกจบที่ฝั่งที่เขาจะใช้ แทนที่จะจบที่หน้าเดียวกันทุกเครื่อง** พร้อมกันนั้นห้องทำงานติดตั้งเป็นแพ็กได้ อวาตาร์มีครบ 30 ท่าที่ขยับจริงทุกท่า แชทอ่านยาวได้ด้วยที่คั่นเทิร์นและทูลทิปกลาง งานเบื้องหลังบอกได้ว่าแชทไหนยังถืออยู่ และการ์ดแยกกลุ่มคอมมิตก็เลิกพาไฟล์ระดับกิกะไบต์เข้าคอมมิตทั้งโฟลเดอร์

## แชทที่อ่านยาวได้

- **ที่คั่นเทิร์นและทูลทิปกลาง** ผู้ใช้เจอทางตันหลายจุด: ทูลทิปบนแถบพื้นเบลอขึ้นกล่องแต่ไม่มีข้อความ, แชตยาวไม่มีแผนที่เทิร์นและเปิดมาอ่านประวัติทั้งก้อน, พรีวิวผลของ worker พิมพ์ขีดตารางออกมาเป็นคำ · รุ่นนี้ย้ายจุดที่ใช้ร่วมกันออกมาเป็นโมดูลที่ทดสอบได้ (`markdownActs`, `TooltipLayer`/`tooltipPlace`, `turnRail`/`TurnRail`, `WorkingRow` กับ type งานใน `jobs.ts`)
- **แถวเครื่องมือแบบแบน** ไทล์จาง จุดคั่น ชื่อไฟล์ขีดเส้นจุด รางผ่านไอคอน · แผงคำสั่งไม่กางเอง ต้องกดที่แถวเท่านั้น และเลิกมีบรรทัด "ใช้ N เครื่องมือ" ตอนงานまだรัน
- **ลากไฟล์และภาพเข้าแชทได้ทั้งคอลัมน์** พร้อมแผ่นเชิญเต็มหน้าต่างที่บอกผลตามโซน (แนบ / เปิดบนโต๊ะ / เพิ่มเข้าโปรเจกต์ / เปิดไฟล์) · ลากภาพที่อยู่ใน bubble กลับเข้าช่องพิมพ์ได้ · โฟลเดอร์ที่ลากมาวางได้ประโยค "แนบโฟลเดอร์ไม่ได้ — เลือกไฟล์ข้างในแทน" สามภาษา
- **ระหว่างรอ** บรรทัด "กำลังคิด" อยู่ตลอดเทิร์นและนาฬิกาไม่รีเซ็ตหลัง tool จบ · แถวเซสชันเลื่อนขึ้นลงนุ่ม ๆ เมื่อลำดับเปลี่ยน · แถบข้างบอกเวลาธรรมดา วงหมุนตอนทำงาน และปักหมุดจากแถวได้
- **ไม่แตะ Go, SendMessage หรือฐานข้อมูล** งานลากไฟล์เป็นงานฝั่งหน้าจอทั้งชุด

## ความจำ: วิธีตอบมีไฟล์ของตัวเอง

- **เดิม** สิ่งที่เรียนรู้เรื่อง "อยากให้ตอบแบบไหน" ถูกเก็บปนกับเรื่องอื่น และมีเพดาน ~220 ตัวอักษรต่อบรรทัด ซึ่งตัดคำสั่งที่ยาวกว่าหนึ่งประโยคทิ้ง
- **รุ่นนี้** `SHAPE.md` เป็นที่เก็บของเรื่องรูปแบบคำตอบ · `prompt.go` พับไว้ใต้หัวข้อที่เป็นคำสั่ง ไม่ใช่ข้อมูล · หน้าความจำเพิ่มแถว "วิธีตอบที่คุณชอบ" และบอกว่าใครอ่าน
- **เต็มแล้วปิดรับการเพิ่ม ไม่พับเอง และไม่เรียกโมเดลทิ้ง** พร้อมเตือนเมื่อไฟล์ใกล้เต็ม เปิดไฟล์นั้นจากการแจ้งเตือนได้ และบอกเมื่อมีบรรทัดรออนุมัติ

- **ตัวแยกกลุ่มคอมมิต** อ่านงานที่โปรเจกต์เพิ่งเขียนก่อนลำดับ path, ตอบด้วยเลขไฟล์แทน path ทั้งชุด, จัดกลุ่มทีละก้อน 80 ไฟล์ และมีแถบ "กำลังเขียนข้อความ k/total" ระหว่างแยกกลุ่ม · เพดานเวลาของข้อความเป็น 90 วินาที + 2 วินาทีต่อไฟล์ สูงสุด 240
- **เพดานไฟล์ 100 MB** แถวโฟลเดอร์ในแผง git มีแค่ชื่อ ไม่มีขนาด `git add -- .scratch/` จึงกวาดทุกอย่างข้างใน และ `git add` มีเพดานรวม 30 วินาที — 8 พ.ย. 2026 การ์ดที่มี `.scratch/` พา sqlite 1.8 GB สองไฟล์เข้าไป คอมมิตจบด้วย `git add timed out after 30s` โดยไม่มีใครรู้ว่าไฟล์ไหนเป็นต้นเหตุ
- **รุ่นนี้** เปิดโฟลเดอร์ untracked เป็นรายไฟล์ก่อน `git add` และก่อน `commit --only`, ข้ามไฟล์ที่ใหญ่เกินพร้อมบอกชื่อและขนาดกลับไป, เส้นทาง hunk ใช้ด่านเดียวกัน และแผงแปลทั้งสองกรณีเป็นประโยคของผู้ใช้สามภาษา
- **การ์ดคอมมิต** มีปุ่ม "ไม่ถามอีกในเทิร์นนี้"

## เปิดแชตเร็วขึ้น และไม่ทิ้งงานตอนปิดแอป

- เปิดแชตแบบ lazy, แบ่งหน้าทรานสคริปต์ และเก็บรันแผนข้ามแอปปิด พร้อมบังคับหลักฐานก่อนปิดขั้นแผน
- สลับเซสชันไม่สร้างลิสต์ใหม่ทั้งชุด · มาตรวัดเครื่องถามทุก 15 วินาทีตอน idle แทนทุก 5 · แคช git 60 วินาที และตรวจ stack ด้วย stat ก่อน ReadDir
- ลิสต์เซสชันคง identity ข้ามการรีเฟรช และแชทใหม่ย้ายไปบนสุดของราง

## Telegram: ข้อความที่แตกเป็นชิ้นเป็นเทิร์นเดียว

- **เดิม** ข้อความยาวที่ Telegram ตัดเป็นหลาย update และอัลบั้มรูป กลายเป็นหลายเทิร์น — โมเดลตอบชิ้นแรกเป็นคำถามของมันเองแล้วอ่านชิ้นที่เหลือเป็นคำถามใหม่ · `listenTelegram` เก็บ offset ไว้ในหน่วยความจำของ call เดียว ซึ่ง engine เรียกใหม่ทุกครั้งที่ reconnect จึงเริ่มที่ศูนย์แล้ว Telegram ส่ง update เดิมซ้ำ
- **รุ่นนี้** รวมชิ้นต่อ (แชต, ผู้ส่ง) ก่อนสร้างเทิร์น เงียบ 250 ms และ 800 ms เมื่อมีไฟล์ · คำสั่งที่ขึ้นต้นด้วย `/` ไม่รอ · offset จำในโปรเซส 512 รายการ ตั้งใจไม่เขียนลงดิสก์ เพราะ offset ที่รอดข้าม restart จะทิ้งข้อความที่ส่งตอนแอปปิด
- **โควตาขาออก** 1 วินาทีต่อแชท และ cooldown จาก `retry_after` ของ Telegram/Discord
- **ไม่ได้ทำ** Discord ยังไม่ resume ด้วย sequence/session — ข้อความที่หลุดช่วงขาดการเชื่อมต่อหายไป

## ผู้ให้บริการและโมเดล

- แถว custom ที่พูด OpenAI protocol ตั้งระดับคิดได้ และส่ง `reasoning_effort` จริง (เดิมเมนูระดับคิดถูกปิดทั้งช่องพิมพ์และหน้าตั้งค่า) · เมื่อโฮสต์ตอบ 400 เรื่องฟิลด์นี้ ทาง replay ที่มีอยู่ถอดออกให้เอง
- หลายบัญชีต่อผู้ให้บริการเดียว และฟอร์มเพิ่มผู้ให้บริการถาม endpoint กับชื่อที่แสดงได้ก่อนมีแถว · หน้าตั้งค่าเหลือสิบบรรทัด
- **หน้าเกตเวย์** เรียงเป็นแถวผู้ให้บริการ: ที่อยู่ที่คัดลอกได้ ชื่อที่แก้ได้ ตัวเลือกโมเดล จำนวนที่กรองแล้ว และช่องค้นหา โดยแต่ละรายการพับเก็บชิปบัญชี สวิตช์โมเดล และแถบค่าใช้จ่ายของตัวเอง
- `context window` ของ Ollama เป็นของเซิร์ฟเวอร์ ไม่ใช่ของโมเดลการ์ด และเปิด API ภายนอกสำหรับตรวจ loopback และค้นหาโมเดลด้วย context
