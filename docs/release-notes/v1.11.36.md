## prompt_view: เอเจนเปิดชั้นวางชุดคำสั่งอ่านเองได้

- **เดิม** เอเจนเห็นสกิลกับชุดคำสั่งจากดัชนีในพรอมป์เท่านั้น — ชื่อ หมวด และ `before:` ที่ยิงทุก surface จะเลือกอะไรที่ไม่มี `before:` ก็ต้องเดาจากชื่อ และ `skill_view` เปิดได้ทีละตัวโดยไม่รู้ว่าชั้นวางมีอะไรบ้าง
- **ตอนนี้** `prompt_view` (`internal/skill/prompt_view.go`) เปิดทั้งชั้นวางทีละบรรทัด หรือเปิดเฉพาะหมวด ใช้ `description` ที่พรอมป์ไม่เคยส่งให้เห็น ตัดที่ 160 ตัวอักษร และจัดหมวดด้วย `AreaOf` ชุดเดียวกับดัชนี ผู้ใช้จึงเห็นกลุ่มเดียวกับที่พรอมป์พิมพ์
- frontmatter มี `when:` ใหม่ — cue สั้น ๆ ขึ้นในวงเล็บหลังชื่อในดัชนี ถูกรองจาก `before:` ที่ต้องยิงทุก surface; สกิลมีอย่างใดอย่างหนึ่ง ไม่ต้องมีทั้งคู่ และ `aetox-skill-writing` สอนกติกานี้แล้ว
- ชุดคำสั่ง (preset) ขึ้นบนสุดของรายการพร้อม cue ของมัน (ถ้าไม่มี ใช้บรรทัดแรกของ body) และ desk tag · `when:` ถูกอ่านและเขียนกลับทั้งตอน parse และตอนบันทึกจากหน้าต่าง — เซฟทับแล้ว cue ไม่หาย
- `prompt_view` ขึ้นทะเบียน `TierOnUse`: คำนิยามไม่อยู่ในบล็อกเครื่องมือที่ส่งทุกคำขอ (เคยกิน 75 tok, เพดาน 80) เหลือชื่อในดัชนีโหลดตอนเรียกครั้งแรก · อ่านเอกสารอย่างเดียวจึงไม่ขอสิทธิ์ และอยู่หมวด agent จึงติดทุกโต๊ะเหมือน `skill_view`
- **เทสต์** `go test ./internal/command ./internal/skill ./internal/bootstrap` ผ่าน · `TestPresetCueSurvivesASave` · `TestPromptViewListsPresetsWithTheirCue` · `go test ./internal/engine -run TestEveryToolRunsThroughTheRealDispatcher` ผ่าน และ `prompt_view` อยู่ในลิสต์ ran for real

## แชท: การ์ดคำถามใช้ช่องพิมพ์เป็นช่องตอบ

- **เดิม** ตอนเอเจนถาม ใต้แชทซ้อนกันห้าชั้น: การ์ดคำถาม (ที่มีช่องพิมพ์ของตัวเอง) แถบสิ่งที่ต้องทำ ชิปโปรเจกต์ ช่องพิมพ์ และสถิติอีกสองบรรทัด — แทบไม่เหลือที่ให้อ่านแชท (mike, 23 พ.ย. 2026: "มันกินพื้นที่ไปเยอะมากครับ … จนแทบไม่เห็นเนื้อหาเลย")

- ระหว่างมีคำถาม ชิปโปรเจกต์กับ TodoDock ถูกซ่อน (`askDock`) การ์ดพับเหลือบรรทัดเดียวได้ (`askFolded`) คำถามใหม่เปิดเต็มเสมอ «ข้ามข้อนี้» กับ «กลับไปข้อที่กำลังถาม» อยู่บรรทัดเดียวกัน และการ์ดสูงไม่เกิน 45vh แล้ว scroll ข้างในเอง (`style.css:6705`)

## ซูมทั้งหน้าต่างด้วย Ctrl+ล้อเมาส์

- **เดิม** หน้าต่างซูมไม่ได้เลย: Wails ตั้ง `IsZoomControlEnabled(false)` และปิด browser accelerator keys ซึ่งตามเอกสาร Microsoft พา Ctrl+Plus/Minus ไปด้วย (ปิดเพราะ F5/Ctrl+F เป็นของแอป จึงเปิดคืนทั้งก้อนไม่ได้)
- **ตอนนี้** ซูมเป็น WebView2 ZoomFactor ของหน้าต่างหลัก ไม่ใช่ CSS zoom ชั้นที่สาม — page zoom ขยับ `devicePixelRatio` ตาม และทุกจุดที่แปลง CSS เป็นพิกเซลจริง (`BrowserPane`, `AgentHand`) คำนวณจาก dpr อยู่แล้ว
- `SetViewZoom` จำกัด 50–250% ขั้นละ 10% · Ctrl+ล้อเมาส์สะสม delta จนครบหนึ่ง notch (100px) แล้วก้าวเดียว — trackpad ที่ส่ง delta เล็กต่อเนื่องจึงไม่กระโดด และล้อที่เลื่อนไปมาให้ผลสุทธิ · Ctrl+= / Ctrl+Shift+= (ปุ่ม '+') / numpad · Ctrl+0 = 100% · ค่าเก็บใน localStorage (`aetox-view-zoom`) และคืนให้วิวที่ถูกสร้างใหม่หลังเว็บวิวตาย
- ล้อที่ผูกแบบ `passive:false` ถอยออกเมื่อ pane นั้น `preventDefault` ไว้แล้ว (ห้องบริษัท แผนที่สมอง ไทม์ไลน์ตัดต่อ จึงยังซูมภาพของตัวเองได้)
- **เทสต์** `viewZoom.test.ts` 10 ข้อ · `shortcuts.test.ts` 10 ข้อ · `go test ./desktop/ -run ViewZoom` ผ่าน (clamp กับค่าที่คืน) · บน dev `:34115` เรียก `SetViewZoom(1.5)` แล้วจับภาพหน้าต่างเทียบก่อน/หลังเห็นการขยายจริง และคืนค่า 1 กลับแล้ว
