# 🧹 Aetox v1.11.47

วันที่ 29 พฤศจิกายน 2026

Aetox เหลือ desk เดียว: หน้าขียนคู่กับโค้ด (`editor`) และตัวเติมโค้ด (fill) ถูกถอดออกทั้งเส้น เหลือ coding ที่ทำงานกับโปรเจกต์จริง · แชตเก่าที่เคยบันทึกไว้ด้วย mode `editor` ยังเปิดอ่านได้ครบ ไม่หายไปกับ desk ที่ถูกถอด · ท่อน "คำสั่งถัดไป" ท้ายคำตอบกลายเป็นการ์ดกดได้ ไม่ต้องคัดลอกโค้ดสามบล็อกด้วยมือ · browser: device preset `mobile` ได้ขนาดจริงแม้แผงแคบ คลิกตรงจุด และแผงเว็บไม่ค้างว่างตอนเปิดหน้า · memory: บรรทัดที่จำบอกแชตที่มันเรียนรู้มาจริง, `replace` ไม่ทับ fact คนละเรื่อง, แก้ line ที่ node ที่มันอยู่จริง และการ์ดบอก line ใกล้กันจาก node อื่น

## desk เหลือ desk เดียว — ถอด `editor` กับ fill ออก

- **เดิม** มี desk สองแบบ: `coding` ที่ทำงานกับโปรเจกต์ และ `editor` หน้าขียนคู่กับโค้ด พร้อมฟีเจอร์เติมโค้ด (fill) ที่ยิงโมเดลทุกครั้งที่พิมพ์ — ทั้งเส้นนี้มี UI ของตัวเองตั้งแต่ mode switch, write pane, dock, quick open, file tabs, LSP nudge, search/problems pane, desk settings, fill card ไปจนถึง explorer
- **ตอนนี้** (`181a326f5`)
  - โค้ดเหลือ desk เดียวคือ `coding` ไฟล์ UI ที่ผูกกับ desk `editor` ถูกลบทั้งชุด (`ModeSwitch`, `WriteHost`, `WritePane`, `Dock`, `QuickOpen`, `FileTabs`, `LspNudge`, `SearchPane`, `ProblemsPane`, `DeskSettings`, `FillBrainCard`, `Explorer`) พร้อม forwarder ฝั่ง Go ที่เคยรับคำสั่งของ desk นั้น
  - ตาราง `fill_calls` ที่เคยจดทุกครั้งที่ขอเติมโค้ดถูกทิ้งที่ migration 94 (`drop_fill_calls`) ชื่อตารางเหลืออยู่ที่ขั้นนั้นที่เดียว
  - คอมมิตนี้ลบ 10,856 บรรทัด เพิ่ม 2,463 บรรทัด ใน 150 ไฟล์
- เทสต์: `retired_desk_test.go` สองตัวผ่าน · `go build ./cmd/... ./internal/... ./desktop/...` ผ่าน · svelte-check 4 error / 22 warning เท่า baseline v1.11.46

## แชตเก่าที่บันทึกด้วย mode `editor` ยังเปิดได้

- **เดิม** แถวในตาราง `sessions` เก็บ mode ที่ใช้ตอนนั้นไว้ ถ้า desk `editor` หายไป แถวเหล่านั้นจะชี้ไปที่ mode ที่ไม่มีโค้ดรองรับแล้ว
- **ตอนนี้** (`181a326f5`)
  - แถวที่ mode เป็น `editor` ถูกอ่านแล้วนับเป็น `coding` ทั้งรายการแชต ตัวกรอง `SessionMode` และตอนเปิดแชต — แต่แถวในฐานข้อมูลไม่ถูกเขียนทับ ค่าที่เคยเก็บไว้ยังอยู่เหมือนเดิม (`TestAStoredEditorSessionReadsAsCoding`)
  - store ที่เก่ากว่า migration 34 ยังได้ตาราง `fill_calls` ว่างก่อนถึงขั้น 94 แล้วถูกทิ้งในขั้นนั้น (ขั้น 94 ใช้ `DROP TABLE IF EXISTS` เพราะ store ที่ใหม่กว่านี้ไม่มีตารางนี้แล้ว) — `TestTheCompletionTableIsDroppedOnUpgrade`
- เทสต์: สองตัวข้างต้นผ่านบน store ที่สร้างที่ depth ก่อนหน้า ไม่ใช่ store ใหม่ที่ schema ครบแล้ว

## คำสั่งถัดไปท้ายคำตอบเป็นการ์ดกดได้

- **เดิม** คำตอบที่จบด้วยหัวข้อสั้น ๆ แล้วตามด้วยโค้ดบล็อกไม่ติด language tag สามบล็อก (รูปแบบที่ไฟล์โปรเจกต์อย่าง `CLAUDE.md` สั่งให้โมเดลเขียน) ต้องคัดลอกทีละบล็อกด้วยมือ
- **ตอนนี้** (`181a326f5`)
  - engine อ่านท่อนนั้นเป็น `prepared_reply` (`suggestedCommands`) สูงสุดสามคำสั่ง ไม่ซ้ำ และส่งมาเป็นการ์ด "คำสั่งถัดไป" ใต้คำตอบ ส่วน bubble แสดงคำตอบโดยตัดท่อนนั้นออก
  - กติกาเดียวกันทั้งสองฝั่ง (`internal/engine/prepared_reply.go` กับ `lib/suggestedCommand.ts`): ต้องมีหัวข้อ `**…**` หรือ `# …` ปิดท้าย และบล็อกต้องไม่มี language tag อย่างเดียวต่อบรรทัด — บล็อกที่มี tag (```bash) คือของให้รัน ไม่ใช่ของให้ส่ง จึงไม่ถูกจับ
- เทสต์: `suggestedCommand.test.ts` — จับทุกบล็อกใต้หัวข้อและเหลือคำตอบที่เหลือตามเดิม · เก็บได้สามคำสั่งไม่ซ้ำ · ชุดที่ตรวจว่าคำตอบปกติไม่ถูกแตะ

## browser — device preset `mobile` ได้ขนาดจริง คลิกตรงจุด และแผงไม่ค้างว่าง

- **เดิม** เมื่อแผงแคบกว่าอุปกรณ์ browser รายงานว่า "nothing resized" ทั้งที่มันย่ออุปกรณ์ให้พอดีแผงไปแล้ว (iPad mini 744x1133 วัดได้ 537x818 ทั้งสองด้าน 0.722) agent จึงเชื่อว่าไม่มีอะไรเปลี่ยนและไม่ได้สั่งกลับ กรอบ iPad ค้างอยู่บนแผงของเจ้าของ (`fdd5c3d17`)
- **ตอนนี้**
  - device ที่ย่อให้พอดีแผงนับว่าสำเร็จเมื่อทั้งสองด้านใช้อัตราส่วนเดียวกันและน้อยกว่า 1 และตอบขนาดที่วัดได้จริง; ถ้าพลาดจริงส่งแผงกลับไปเต็มแผง ไม่ให้มีกรอบค้าง (`fdd5c3d17`)
  - mobile device ส่ง width/height ของเครื่องจริงไปพร้อม scale ที่ย่อให้พอดีแผง — page วัดได้ 744x1133 และวาดพอดี window 537x818 (เดิม media queries เห็น width 537 ซึ่งเล็กกว่าเครื่องจริง) · ตอนเป็น mobile ให้ view zoom อยู่ที่ 1 เพราะ zoom 0.722 คู่กับ scale ทำให้ input เลื่อน (คลิกที่ 268 ไปลง 268 แทนที่จะเป็น 371) · click mapping คูณ scale เฉพาะ mobile device ส่วน Desktop preset ยังใช้ zoom เดิมเพราะ path นั้นถูกอยู่แล้ว (`95905a664`)
  - แผงเว็บไม่ว่างค้างเมื่อ agent เปิดหน้าตอนแผงขวายังกางไม่เสร็จ (pane กว้าง 0, log: asked for a 0x866 rectangle): `BrowserSetVisible(true)` ที่ส่งใน tick เดียวกับ `BrowserOpen` เข้าคิว host ก่อน open ได้ แล้ว `onTab` ทิ้งเงียบเพราะยังไม่มีแท็บ — ตอนนี้ `BrowserPane` ให้ทุกคำสั่งของแท็บนั้น (visible, bounds, device, navigate, ซ่อนตอน unmount) รอ `BrowserOpen` resolve ก่อน แล้ว re-glue ครั้งเดียว · `onTab` เขียน log เมื่อทิ้งคำสั่งของแท็บที่ไม่มี พร้อมชื่อคนเรียก (`4895c79b9`)

## memory — บรรทัดที่จำบอกแชตที่เรียนรู้มา และการแก้ไม่ทับของคนอื่น

- **บรรทัดที่จำบอก chat ที่เรียนรู้มาจริง** (`f8005fb0a`) — เดิม evidence ของบรรทัดที่ agent จำใช้ `a.cur().id` คือแชตที่อยู่บนจอตอนนั้น ไม่ใช่แชตที่เรียก memory tool วัดจาก `aetox.db` 28 พ.ย. 2026: 104 จาก 318 บรรทัดชี้แชตผิด และสองบรรทัดที่แชตเรซูเม่จำชี้ไปแชตของวันที่ 27 · ตอนนี้ประตูของแต่ละแชตถือ conv ของตัวเอง (ที่เดียวกับที่ `recordToolRun` ใช้) และ `evidence()` อ่าน `conv.id` ทั้งตอน keep และตอน queue ทางที่ไม่มี conv ยังใช้ `cur()` เหมือนเดิม — `TestAKeptLineNamesTheChatItWasLearnedIn`
- **`replace` ไม่เขียนทับ fact คนละเรื่อง** (`39f1cf6fc`) — วัดจาก `aetox.db`: `replace` ของ agent 55 ครั้ง มี 5 ครั้งที่เขียน fact คนละเรื่องทับบรรทัดเดิม (ทิศทาง harness กลายเป็น path คลังโลโก้, baseline เทสต์แดงกลายเป็นกฎ frame: desk) ทั้ง 5 ครั้งเกิดหลังคำปฏิเสธไฟล์เต็มที่บอกว่า "replace or remove a line that has stopped being useful" · ตอนนี้ `learned.SameSubject` เทียบเฉพาะตัว fact (ตัด Why/How) ด้วย trigram Dice เกณฑ์ 0.12 — replay replace จริง 55 คู่: ทับข้ามเรื่อง 0.06–0.08 จับได้ 5/5, เขียนใหม่เรื่องเดิมต่ำสุด 0.16 ไม่ขวางเลย 0/50 (บรรทัดสั้นกว่า 16 ตัวนับว่าเรื่องเดียวกัน) · `replace` ที่ old ชี้บรรทัดคนละเรื่องเก็บเป็น `add` บรรทัดเดิมอยู่ต่อ และบอก model ว่าถ้าบรรทัดนั้นผิดให้ `remove` แยก ถ้าไม่มีที่ให้บรรทัดใหม่ปฏิเสธพร้อมบอกว่าจะลบ fact อะไร (ไฟล์ที่ปิดแล้วคือการ์ดรออนุมัติ และ SHAPE ไม่ผ่านด่านนี้) · คำปฏิเสธไฟล์เต็มไม่ชวน `replace`/`remove` บรรทัดอื่นแล้ว เหลือ "write it shorter"
- **แก้ line ที่ node ที่มันอยู่จริง** (`42296d012`) — `replace`/`remove` ได้ "nothing remembered contains" 29 ครั้ง เพราะ model ชี้ file ผิด (about/topic) line เก่าที่ผิดจึงค้างข้าง line ใหม่ และอย่างน้อย 4 line อยู่ใน file อื่นจริง (`you/release-flow.md`, `modes/coding.md`, file ของ project) · ตอนนี้ old ที่ไม่อยู่ใน file ที่ชี้ถูกหาใน file พี่น้องฝั่งเดียวกัน (เรื่องของผู้ใช้: `USER.md` + ทุก branch; ที่งานสอน: file ของหัว/โต๊ะ + file ของ project) — เจอ file เดียวแก้ที่นั่นและบอก model ว่าแก้ที่ไหน, เจอหลาย file ไม่แก้และแสดงทุกที่ให้เลือก, ไม่ข้ามฝั่งผู้ใช้/ผู้ช่วย, และต้องมี old ยาวอย่างน้อย 16 ตัวเพื่อกันคำสั้นอย่าง "Go" ไปลบ line ใน node อื่น · หลังเก็บ line เรื่องผู้ใช้ แสดง line จาก file อื่นที่ใกล้กันไม่เกิน 2 line ให้ model ตัดสินเอง (trigram Dice ถ่วงด้วย IDF) — replay บนสำเนา memory จริง 167 line แสดง 18 line (11%) และสัญญาณหลอกจากคำขึ้นต้นตกจาก 0.25 เป็น 0.13
- **สองคำกำกวมใน about user** (`42b57af6d`) — line เรื่องผู้ใช้ที่ถูก undo 17 line: เดาจากเหตุการณ์ 1–2 ครั้ง 6 line (เช่น สรุปว่าคำขอหนึ่งหมายถึงการออกรุ่นย่อยทุกครั้ง) และเรื่องของ project/ลูกค้าที่เขียนเป็นเรื่องของผู้ใช้ 6 line (ราคา NEON OFFICE, โมเดลของ ep03) ทั้งสองแบบพิงคำ "what a request of theirs reliably turns out to mean" กับ "what they are building" · เปลี่ยนเป็น "has turned out to mean more than once" และ "+ (its name and aim; a project's or client's details go in its own topic)" · tool block 7,873 → 7,893 tokens (budget 8,600) จะวัดอัตรา undo ของ line เรื่องผู้ใช้หลังออกรุ่นเทียบ ~11% (5/44) — ไม่มีเทสต์ใหม่เพราะเปลี่ยนเฉพาะถ้อยคำใน prompt
