# 🪟 Aetox v1.10.23

วันที่ 28 ตุลาคม 2026

**ปิดหรือเปิดโมเดลทั้งชุดที่เห็นอยู่ด้วยการกดครั้งเดียว พร้อมแถบเลิกทำที่คืนทั้งชุด · และเบราว์เซอร์รู้แล้วว่าหน้ากำลังเจนงาน — `wait` รอได้สี่แบบ ปุ่มที่ยังกดไม่ได้ถูกบอกว่ากดไม่ได้ และการกดซ้ำบนหน้าที่ไม่ขยับถูกเอ่ยชื่อออกมา**

## ปุ่มปิดและเปิดโมเดลที่เห็นทั้งชุด พร้อมปุ่มเลิกทำ

- **เดิมการปิดโมเดลคือการกดทีละแถว** ผู้ให้บริการอย่าง OpenRouter มี 465 รุ่น ปิดทั้งค่ายจึงเป็น 465 ครั้ง และเขียนไฟล์ค่าตั้ง 465 ครั้ง
- **รุ่นนี้มีปุ่มสองตัวบนหัวรายการโมเดล** `ปิดที่เห็น (n)` กับ `เปิดที่เห็น (n)` — ตัวเลขบนปุ่มคือจำนวนแถวที่ปุ่มนั้นจะเปลี่ยนจริง ไม่ใช่จำนวนทั้งหมด
- **มันทำงานกับรุ่นที่ผ่านตัวกรองอยู่** ไม่มีตัวกรองคือทั้งหมด พิมพ์ `qwen/` แล้วกดครั้งเดียวจึงปิดรุ่นของผู้ให้บริการรายนั้นโดยไม่แตะรายอื่น และช่องค้นเดียวกันก็ใช้เปิดคืนเฉพาะที่ค้นเจอ
- **เขียนครั้งเดียว ไม่ใช่ครั้งละรุ่น** เพิ่ม `SetModelsEnabled` ใน config/engine ที่รวมการเปลี่ยนทั้งชุดไว้ใน `UpdateModelPreference` ครั้งเดียว — ปลายทางอ่านค่าเดิมได้เหมือนทุกอย่าง ไม่มีอะไรในฝั่งอ่านเปลี่ยน
- **id ที่ว่างหรือซ้ำถูกเขียนครั้งเดียว** การเรียกซ้ำ ๆ ด้วยชุดเดิมจึงไม่ทำให้รายการงอก และเปิดคืนแล้วรายการที่ถูกปิดไว้ก่อนหน้าของรายอื่นยังอยู่
- **แถบเลิกทำคืนทั้งชุดที่เพิ่งเปลี่ยน** ขึ้นบรรทัด `ปิดไป n ตัวแล้ว` / `เปิดไป n ตัวแล้ว` พร้อมปุ่ม `เลิกทำ` ที่ย้อนการกระทำนั้นทั้งชุด ไม่ใช่ทีละรุ่น
- **ระหว่างรอไฟล์ถูกเขียน หน้าจอเปลี่ยนล่วงหน้าแล้วย้อนกลับถ้าล้มเหลว** สวิตช์ทุกตัวขยับทันทีที่กด ถ้าเขียนไม่สำเร็จรายการที่ปิดไว้กลับไปเป็นค่าเดิมทั้งชุดพร้อมข้อความผิดพลาด และแถบเลิกทำจะไม่ขึ้น เพราะไม่มีอะไรให้เลิก
- **ตัวนับ `n / total เปิดอยู่` เตือนเมื่อปิดจนหมด** ขึ้นสีเตือนเมื่อไม่มีโมเดลเปิดอยู่เลย ซึ่งเป็นสภาพที่เมนูเลือกโมเดลของแชทว่าง
- **คำไทยเลิกใช้คำว่า "ปัก" กับดาว** ทั้งเมนู หน้าตั้งค่า และคำแนะนำในแอปเปลี่ยนเป็น `ติดดาว` / `ติดดาวที่ค้นเจอทั้งหมด` / `ล้างดาว` ตามที่ปุ่มทำจริง (เจ้าของ: ดาวคือรายการโปรด ไม่ใช่การปักหมุด)
- **ทำไมเลือกทางนี้** การปิดทีละแถวไม่ใช่ปัญหาของความอดทน แต่เป็นปัญหาของจำนวนครั้งที่เขียนค่าตั้ง ทางที่ถูกจึงเป็นการรวมคำขอ ไม่ใช่การกดเร็วขึ้น

## เบราว์เซอร์: รอหน้าเว็บที่กำลังเจนงานได้ และไม่กดซ้ำเมื่อหน้าไม่เปลี่ยน

- **เดิมโน้ตหลัง action ตอบผิดทุกครั้งที่กดส่งงาน** หน้าที่ส่งงานไปเจนแล้วเขียนคำตอบลง DOM เอง ไม่ขยับ URL ไม่เปลี่ยนจำนวนอิลิเมนต์ ไม่ย้ายโฟกัส โน้ตจึงตอบ `the page did not change` ทั้งที่ข้อความกำลังไหลเข้ามา และโมเดลก็กดซ้ำ
- **`stateScript` วัดเพิ่มสามตัวเลข** ความยาวข้อความของหน้า hash ของข้อความนั้น และความยาวข้อความในช่องที่โฟกัสอยู่ (`-1` เมื่อไม่มีช่องไหนถูกโฟกัส — กล่องว่างกับไม่มีกล่องเป็นคำตอบคนละอย่าง) ทั้งสามวัดจาก `aetoxText` ชุดเดียวกับที่ `read` ใช้ จึงเถียงกันเองไม่ได้
- **โน้ตบอกได้ว่าหน้ากำลังเขียน** ขึ้นบรรทัด `the page is writing: text 1,204 → 3,880 characters (still growing)` หรือบอกว่าข้อความสั้นลง (ถูกแทนที่ไม่ใช่ต่อท้าย) หรือความยาวเท่าเดิมแต่เนื้อหาเปลี่ยน
- **โน้ตบอกว่าข้อความที่พิมพ์ไปออกจากกล่องแล้วหรือยัง** `the field is empty now (46 → 0) — the text left it` คือหลักฐานว่าส่งจริง และ `the field still holds the 46 characters that were typed — nothing was sent` คือหลักฐานว่ายังไม่ส่ง — การยืนยันที่ไม่ต้องเดา
- **action ที่ส่งงานไปเซิร์ฟเวอร์ได้ ถูกเฝ้าต่ออีก 1.5 วินาที** `click` `type` `key` `drag` `upload` `back` `dialog` อ่านหน้าซ้ำทุก 200 มิลลิวินาทีจนกว่าจะต่างจากเดิม เพราะวัดจากหน้าจริงแล้วว่า chatgpt.com เปลี่ยนครั้งแรก 1.3 วินาทีหลังกด Enter และ gemini.google.com 0.6 วินาที การอ่านครั้งเดียวตอน action คืนค่าจึงเร็วเกินไปเสมอ `hover` กับ `scroll` ไม่ถูกเฝ้า เพราะคำตอบอยู่ในนั้นตั้งแต่การอ่านครั้งแรก
- **`wait` รับ `state` สี่ค่า** `appear` (ค่าเดิม รอข้อความขึ้น) · `gone` (รอข้อความหายไป) · `change` (รอให้หน้าขยับจากตอนนี้) · `quiet` (รอให้หน้าหยุดขยับ) — เดิมมีทางเดียวคือ `appear` ซึ่งเป็นคำถามที่ใช้กับหน้าที่กำลังทำงานไม่ได้ทั้งสองทาง: รอคำที่หมายถึง "กำลังทำ" ได้คำตอบทันทีโดยไม่บอกอะไร และรอคำที่หมายถึง "เสร็จ" ไม่มีวันได้คำตอบ เพราะหน้าที่ฝากงานไว้กับเซิร์ฟเวอร์ไม่ได้บอกด้วยข้อความ
- **`gone` อ่าน `aria-label` ด้วย ไม่ใช่แค่ข้อความบนหน้า** ปุ่มที่หมายถึง "หยุดสร้าง" ชื่อ `หยุด` บน chatgpt.com และ `หยุดคำตอบ` บน gemini.google.com และไม่มีสตริงนี้อยู่ในข้อความของหน้าเลย สัญญาณเสร็จที่เชื่อถือได้ที่สุดของสองเว็บนี้จึงเคยเอื้อมไม่ถึง — รุ่นนี้อ่านชื่อจาก `aria-label` `aria-valuetext` `alt` `title` ด้วย (จำกัด 800 อิลิเมนต์ต่อ root เพื่อไม่ให้การ poll กลายเป็นการเดินทั้งหน้า)
- **`quiet` ใช้ MutationObserver คู่กับ hash ของข้อความ หน้าต่าง 6 วินาที** วัดจากหน้าจริง: คำตอบที่สตรีมอยู่ไม่เคยเงียบนานกว่า 0.71 วินาที (chatgpt) และ 1.08 วินาที (gemini) แต่ภาพที่กำลังเจนเงียบได้ถึง 3.5 วินาทีสองครั้งเพราะงานอยู่ฝั่งเซิร์ฟเวอร์ — หน้าต่างจึงต้องยาวกว่านั้น 6 วินาที เพราะสองความผิดพลาดไม่เท่ากัน: สั้นเกินไปคือบอกว่าเสร็จทั้งที่ยังทำงาน ซึ่งเป็นข้อบกพร่องที่ฟีเจอร์นี้เกิดมาแก้
- **`quiet` ไม่ฟันธงบนหน้าที่วาดด้วย canvas** คำตอบพา `canvasShare` มาด้วยและบอกตรง ๆ ว่าหน้านี้วาดด้วย canvas จึงไม่ยืนยันว่าเสร็จ — "เงียบ" แปลว่าหน้านี้หยุดขยับ ไม่ได้แปลว่างานจบ
- **คำตอบของ `wait` บอกตัวเลขที่มันเห็นเอง** ข้อความขึ้นต้นเท่าไร จบเท่าไร และใช้เวลาเท่าไร คำตอบจึงแยก "ของที่รอมาถึง" ออกจาก "หน้านี้เขียนไป 12,000 ตัวอักษร และหนึ่งในนั้นอาจเป็นของท่าน" ได้
- **เวลารอเริ่มต้นขยับตาม state** `appear` 10 วินาทีเท่าเดิม · `change` 30 วินาที · `quiet` 60 วินาที เพราะ `quiet` ที่หน้าต่าง 6 วินาทีแต่เพดาน 10 วินาที จะตอบได้แต่งานที่บังเอิญเร็ว และโมเดลที่ต้องคิดเลขระหว่างสองค่านี้คือโมเดลที่คิดผิด
- **คลิกตรวจ `disabled` / `aria-disabled` ก่อนลงมือ** ตามแบบที่ Playwright ทำ: ปุ่มที่ยังรอ input event ของตัวเองอยู่คือปุ่มที่กดไม่ได้ และการตอบว่า `clicked` คือสิ่งที่ทำให้โมเดลกดซ้ำ — รุ่นนี้ตอบว่า `กดไม่ได้ตอนนี้ (disabled) — ยังไม่ได้คลิก` พร้อมบอกว่าเป็น element ตัวไหน
- **คลิกบอกด้วยว่ามีอะไรรบกวนจุดคลิก** ถ้ามี element อื่นทับจุดนั้นอยู่ คำตอบระบุชื่อ element ที่ทับ คลิกยังไปถึงตัวที่ตั้งใจ (สคริปต์ข้าม hit-testing) แต่เมาส์จริงจะโดนตัวที่ทับ — หน้าที่ไม่ขยับหลังคลิกจึงมีคำอธิบายในบรรทัดนั้นแทนที่จะต้องลองอีกสามครั้ง
- **การทำซ้ำถูกเอ่ยชื่อ ไม่ใช่ถูกห้าม** แท็บจำผลลัพธ์ล่าสุดของตัวเอง: action เดิมที่ทำให้หน้าไม่ขยับติดกัน 3 ครั้ง ได้บรรทัดเตือนให้เปลี่ยนวิธี (`read` ดูสถานะจริง หรือ `wait` รอเงื่อนไข) และการเปิด URL เดิมติดกัน 3 ครั้งได้บรรทัดเตือนว่าการเปิดหน้าเดิมไม่ได้บอกอะไรใหม่ และมันโหลดหน้าใหม่ทับสถานะที่กำลังดูอยู่ — สามครั้งเพราะสองครั้งยังเป็นการลองซ้ำ และการนับนี้เป็นเพียงโน้ต ไม่ใช่การปฏิเสธ
- **คำแนะนำของ `wait` ถูกเขียนใหม่ทั้งก้อน** บอกว่าสี่สภาพนำไปคนละที่ · `open` เป็นการเคลื่อนที่ที่ผิดสองต่อบนหน้าที่กำลังเจน (โหลดหน้าใหม่ทับสถานะที่หมายจะดู และเสีย navigation หนึ่งครั้ง) · ห้าม poll ด้วย `open` หรือ `read` · และบอกชื่อปุ่มที่หมายถึง "กำลังทำ" ของสองเว็บจริง
