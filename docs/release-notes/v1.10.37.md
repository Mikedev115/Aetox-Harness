# 🪟 Aetox v1.10.37

วันที่ 31 ตุลาคม 2026

**ปุ่ม «ให้ผู้ช่วยช่วยสรุป» บนไฟล์ความจำที่ใกล้เต็ม รอเป็นนาทีแล้วจบด้วยข้อความอังกฤษว่าโมเดลไม่ได้เรียกเครื่องมือ — รุ่นนี้ให้รอบที่สองถามให้ตรงกับสิ่งที่ผิดจริง และให้การ์ดบอกความล้มเหลวเป็นภาษาคน**

## ความจำ: รอบสองถามให้ตรงเรื่อง และการ์ดพูดภาษาไทย

- **สาเหตุ** ปุ่มนี้ถามโมเดลได้สองรอบในงบ 150 วินาที รอบที่สองเดิมใช้ประโยคเดิมทุกกรณี คือ *"Your previous answer was cut off before the list ended"* ซึ่งจริงเฉพาะกรณีคำตอบถูกตัดกลาง JSON — เมื่อโมเดลตอบเป็นข้อความธรรมดาโดยไม่ได้เรียกเครื่องมือ `memory_consolidation` (ซึ่งเป็นอาการของโมเดลที่ไม่เก่ง forced tool call หรือ CLI ที่ไม่มี function calling) รอบที่สองจึงเป็นการถามคำถามเดิมซ้ำ รอเพิ่มอีกเท่าตัว แล้วจบที่ความล้มเหลวเดิม
- **สิ่งที่ผู้ใช้เห็น (31 ต.ค. 2026)** รอราวสองนาที แล้วการ์ดขึ้น `Error: the model answered without calling memory_consolidation — the answer was not used. Try again, or switch to a model that answers shorter` เป็นภาษาอังกฤษดิบ
- **ตอนนี้** `askToolJSON` เลือกประโยคแก้ตามอาการ: คำตอบที่ถูกตัดกลาง JSON ยังได้ประโยค "เขียนให้สั้นลง" ส่วนคำตอบที่ไม่ได้เรียกเครื่องมือเลยได้ประโยคที่สั่งให้เรียกเครื่องมือ (พร้อมชื่อฟังก์ชัน) — รอบที่สองจึงมีโอกาสสำเร็จ แทนที่จะเป็นการรอซ้ำ
- **คำตอบว่างที่ชนเพดาน** ถูกรายงานว่าเป็นเพดานพร้อมตัวเลข token ไม่ใช่ "ไม่ได้เรียกเครื่องมือ" อีกต่อไป (เดิมฟังก์ชันตรวจเพดานทำงานเฉพาะกรณี JSON พัง) คำแนะนำที่ขึ้นจึงชี้ไปที่สิ่งที่ต้องเปลี่ยนจริง
- **การ์ดพูดภาษาผู้ใช้** เอนจินส่งรหัส `memory-consolidate-no-call` / `-at-limit` / `-timeout` แทนประโยค หน้าจอแปลเป็นประโยคไทยที่บอกว่า «ยังไม่ได้เขียนอะไร» และควรทำอะไรต่อ — ตามแบบเดียวกับ `commit-message-empty` ของหน้าคอมมิตที่ทำไว้ 28 ต.ค. 2026 ตัวประโยคอังกฤษยังอยู่ใต้รหัสสำหรับคนอ่าน log

## ความมั่นใจของรุ่น

- `go test ./internal/engine` ผ่านทั้งแพ็กเกจ (398s) รวมเทสต์ใหม่สามตัว: รอบสองที่สั่งให้เรียกเครื่องมือ (และยืนยันว่าไม่ได้ส่งประโยค "ถูกตัด" อีก), คำตอบว่างที่ชนเพดานถูกรายงานเป็นเพดานพร้อมชื่อรหัส, และการแปลงความล้มเหลวเป็นรหัสที่การ์ดรู้จัก
- เทสต์หน้าจอ `learningReview.test.ts` + `localeGuard.test.ts` ผ่าน 29/29 รวมเทสต์ใหม่ที่ยืนยันว่าการ์ดขึ้นประโยคไทย ไม่ใช่ประโยคอังกฤษของเอนจิน และคีย์แปลครบทั้งสองภาษา
- `svelte-check`: 8 error เดิมในไฟล์ที่รุ่นนี้ไม่ได้แตะ (`Capability.svelte`, `Chat.tools.test.ts`, `localServerSetup.test.ts`, `roundNoteOrder.test.ts`)
- **กดจริงบนแอป dev** (wails dev, ไฟล์ USER.md ขนาดจริง 3,319/4,096 B): กดปุ่มแล้วได้ฉบับร่าง «ตอนนี้ 3,319 B · 11 บรรทัด» เทียบ «ที่เสนอ 1,914 B · 11 บรรทัด» ใน ~4.4 วินาที ความจำไม่ถูกเขียนจนกว่าจะกด «ใช้ชุดนี้»
- **ข้อจำกัดที่ต้องบอกตรง ๆ** เส้นทางล้มเหลว (ไม่มีเครื่องมือถูกเรียก) ไม่ได้จำลองบนแอปจริงในรุ่นนี้ เพราะโมเดลที่รันอยู่เรียกเครื่องมือได้ถูกต้อง — เส้นทางนั้นคุมด้วยเทสต์ของเอนจินและการ์ด ไม่ใช่ด้วยการกดจริง และงบเวลารอของปุ่มยังเป็น 150 วินาทีเท่าเดิม (รุ่นนี้ไม่ได้ลดเวลารอ ลดการรอที่เปล่าประโยชน์)
