## โต๊ะผู้ช่วยมีครึ่ง «ลงมือ» ของตัวเอง และถือเครื่องมือตรวจผลงาน

- **เดิม** ตัวตนของโต๊ะนี้ยาว 69 บรรทัด เป็นทิศทางล้วน ไม่มีบรรทัดที่บอกว่างานเสร็จแปลว่าอะไร หรือจะรู้ได้ยังไงว่าเสร็จจริง — คำว่า check ในไฟล์มีสองที่ และทั้งคู่เป็นชื่อชนิดงาน ไม่ใช่กฎการตรวจ · ด้านเครื่องมือก็ขัดกันเอง: ตัวตนบอกว่าการเขียนหน้าเว็บ สคริปต์ และโปรแกรมเล็ก ๆ เป็นงานของโต๊ะนี้ แต่เครื่องมือสามตัวที่ใช้ตรวจของแบบนั้น (`page_check`, `diagnostics`, `design_check`) อยู่ในหมวด `code` ซึ่งโต๊ะนี้ไม่ถือ โต๊ะที่ถูกสั่งให้ทำของแล้วไม่มีเครื่องมือดูผลจึงรายงานว่าเสร็จด้วยความเชื่อ
- **รุ่นนี้ — ครึ่งลงมือ** เพิ่มส่วนใต้ marker `<!-- acting -->` ใน `assistant.md` เริ่มด้วยสองจังหวะที่เป็นของโต๊ะนี้ทั้งคู่: งานที่มาถึงแล้วให้คิดรายละเอียดเองแล้วส่งคืนให้เสร็จ เหลือให้คนตอบแค่ใช่หรือไม่ใช่ · งานที่ยังไม่มาถึงให้เฝ้าวันครบกำหนด คำสัญญา และของที่หยุดเคลื่อน แล้วเตรียมไว้ก่อนถูกถาม โดย «รุก» หมายถึงเตรียมให้พร้อม ไม่ใช่ตัดสินแทน
- **คำตอบ ไม่ใช่คำถาม** คำถามมีที่ยืนก็ต่อเมื่อคำตอบของมันเปลี่ยนสิ่งที่ทำ และถามครั้งเดียวก่อนลงมือ · ความสงสัยที่เจอกลางทางเป็นของโต๊ะนี้ที่จะตัดสินด้วยของที่มีอยู่ — การส่งปัญหากลับไปเป็นชิ้น ๆ คืออุปนิสัยเดียวที่งานนี้แบกไม่ได้
- **เส้นแบ่งเตรียมได้–ตัดสินไม่ได้** ร่าง รวบรวม จัดเรียง ซ้อม เตือน และจำ เป็นของโต๊ะนี้ · เงินและราคา คำสัญญากับคนอื่น การส่งหรือโพสต์ในนามผู้ใช้ การลบของที่กู้คืนไม่ได้ และอะไรที่เปลี่ยนความสัมพันธ์กับคน เป็นของผู้ใช้
- **บททดสอบก่อนส่ง** «ถ้าคุณเป็นเขาจะเซ็นไหม» — ไม่เซ็นให้ทำใหม่ · ทำไม่จบให้ส่งของที่จบแล้ว พร้อมบอกตรง ๆ ว่าขาดอะไร ลองอะไรไปแล้ว และอะไรกำลังรอเขาอยู่ · ทางไม่ชัด: กระทำที่ย้อนได้ให้ทำเลย ที่ย้อนไม่ได้ให้ถามครั้งเดียวพร้อมทางเลือกและคำแนะนำ ที่ทำไม่ทันให้ส่งของที่ทำเสร็จ · ปิดด้วยความเย็นสามข้อ: ไม่พูดอะไรที่คลุมเครือกว่าความจริง ไม่พาความร้อนจากข้อความหนึ่งไปอีกข้อความ ถามทีละคำถาม และไม่ตัดสินคนที่ทำงานให้
- **ย้ายย่อหน้า «The machine» ลงใต้ marker** เพื่อให้เทิร์นคู่คิด/วางแผนไม่ได้คำสั่งให้ลงมือในขณะที่ถือ tool เป็นศูนย์ — ข้อความเดิมไม่แก้แม้แต่คำเดียว
- **เครื่องมือตรวจผลงาน** เพิ่มสามชื่อในบรรทัด `tools:` ของโต๊ะนี้ และแก้ประโยคเรื่อง code tools ให้ตรงความจริง เพราะสามตัวนั้นอยู่ใน pack `codebase` ตัว dispatcher จึงส่ง pack นั้นแบบตัดเหลือเฉพาะ action ที่อนุญาต (`page_check`, `diagnostics`, `design_check`) ส่วนเครื่องมือที่ต้องมี project root (`symbol`, `impact`, `rename`, `repo_map`, `trace`) ยังอยู่นอกตามเหตุผลเดิมใน `category.go` และ `github`/`github_search` ก็ยังไม่ถูกส่งให้โต๊ะนี้
- **เทสต์** `TestTheAssistantDeskCarriesItsWorkingRules` อ่านไฟล์ที่ ship จาก embed ไม่ใช่ `Load` เพราะไฟล์ผู้ใช้ใน `<DataRoot>/modes` ทับได้ · `mode_test.go` เปลี่ยนกรณีที่ปักว่า assistant ไม่ถือ `diagnostics` (คำสั่งเดิม 6 ส.ค.) พร้อมบันทึกวันที่และเหตุผล และปักเพิ่มว่า `symbol`/`repo_map` ยังอยู่นอก · `assistant_tools_test.go` ปักทั้งสองด้าน · เทสต์ desk ของ engine ปักว่าฝั่ง assistant ส่ง `codebase` แบบตัด action
- **ไม่ได้ทำ** ไม่แตะเครื่องมือชุดที่เหลือ (page_check ตัวละเอียด, PDF, กระดาษตัดสิน) — เจ้าของสั่งให้แยกเป็นเฟสสอง
- **ไฟล์** `internal/mode/modes/assistant.md` · `internal/mode/stance_test.go` · `internal/mode/mode_test.go` · `internal/mode/assistant_tools_test.go` · `internal/engine/desk_test.go`

## ย้อนงานในโฟลเดอร์ที่ไม่มี `.git` ได้ และ rename ไม่หายอีก

- **เดิม** โต๊ะผู้ช่วยไม่มีโปรเจกต์ จึงไม่เคยมี snapshot store — กฎ «ทำแล้วกู้คืนได้ = ทำเลย» ที่เพิ่งเขียนลงตัวตนจึงไม่มีเครื่องมือรองรับ · การทดลองในโฟลเดอร์ธรรมดา (ไม่มี `.git`) เผยอีกบั๊ก: git ยุบ rename เหลือชื่อปลายทาง `Changed` จึงคืนแค่ชื่อใหม่ แล้ว `Restore` ลบชื่อใหม่ทิ้งโดยไม่คืนชื่อเดิม — วัดแล้ว หนึ่งไฟล์เปลี่ยนชื่อได้ `[b.txt]` แล้วไฟล์หายทั้งคู่
- **รุ่นนี้** `snapshot.Changed` diff ด้วย `--no-renames` ให้เห็นทั้งสองข้างของ rename · `engine/undo_browse.go` ยึดโฟลเดอร์ที่กำลังดูอยู่เป็น work tree ของ undo เพดาน 10,000 ไฟล์ แคชต่อ root และไม่มีโฟลเดอร์ = ไม่มี undo ตามเดิม · `channel_runtime.snapshotFor` ใช้สโตร์ของโปรเจกต์ก่อน ไม่มีจึงใช้โฟลเดอร์ที่ดูอยู่
- **ไม่ได้ทำ** ไฟล์ที่เปลี่ยนนอกโฟลเดอร์ที่กำลังดูอยู่ และคำสั่งทำลายไฟล์ที่พิมพ์เองหลังเทิร์นจบ — สมุดย้อนกลับของ shell เป็นงานถัดไปของข้อนี้
- **ไฟล์** `internal/snapshot/snapshot.go` · `internal/engine/undo_browse.go` · `internal/engine/channel_runtime.go` · `internal/engine/app.go` · `internal/snapshot/plain_folder_test.go` · `internal/engine/undo_browse_test.go`

## lookout — ตัวกวาดที่ไม่เรียกโมเดล บอกของที่เลยกำหนดก่อนถูกถาม

- **เดิม** จังหวะรุกของโต๊ะผู้ช่วยวันนี้คือ «เสนอว่าจะจดไหม» ไม่ใช่ «มีของเตรียมไว้แล้ว» จึงไม่มีใครเห็นของค้างก่อนเจ้าของเห็น
- **รุ่นนี้** แพ็กเกจบริสุทธิ์ `internal/lookout` รับ Input แล้วคืน `[]Finding` ครอบสามเรื่อง — งานเลยกำหนด, งานที่ใกล้ถึงภายใน 24 ชม. และพื้นที่ดิสก์ต่ำกว่า 2 GiB — พร้อมลำดับที่คนควรได้ยิน (เลยกำหนดก่อน เรียงจากเก่าสุด) · `LookoutNow()` อ่านงานที่เปิดอยู่จาก life store และพื้นที่ว่างของโวลุ่มที่ `DataRoot` อยู่ แหล่งที่อ่านไม่ได้ทำให้ส่วนนั้นว่าง ไม่ทำให้ทั้งรอบล้ม
- **ทำไมไม่ใช้โมเดล** เพื่อให้คำตอบมีอยู่ตอนโมเดลช้า ปิด หรือไม่มีคีย์ — ตอบได้โดยไม่เรียกโมเดล ไม่ต่อเน็ต และไม่มี timer
- **ไม่ได้ทำ** ยังไม่มีหน้าจอ tool หรือ prompt ตามการแบ่งเฟส: ใครวาดการ์ดเป็นคนตัดสินการจัดวาง
- **ไฟล์** `internal/lookout/lookout.go` · `internal/engine/lookout.go` · `internal/engine/lookout_disk_windows.go` / `lookout_disk_other.go`

## คัดลอกสิ่งที่ทำลงคลิปบอร์ด และแจ้งเตือนเมื่องานยาวจบ

- **เดิม** งานจริงของโต๊ะผู้ช่วยทุกวันคือ «ทำให้แล้วก๊อปไปวางเอง» และงานยาวที่ผู้ใช้เดินหนีไประหว่างรอ — สองอย่างนี้เป็นคำสั่งฝั่งหน้าจอ ไม่ใช่ของเอนจิน จึงไม่มี action ให้เรียก
- **รุ่นนี้** pack `computer` มี action `copy` และ `notify` (`computer_copy`, `computer_notify`) หมวด `shell` · เขียนคลิปบอร์ดด้วย Win32 ตรง (`OpenClipboard` / `SetClipboardData` ด้วย `CF_UNICODETEXT`) ไม่เพิ่มโมดูลและไม่พึ่ง webview ที่อาจไม่มีหน้าเปิดอยู่ · แจ้งเตือนใช้ทางเดิมของแอป (attention toast) เคารพสวิตช์ของผู้ใช้ และกดแล้วกลับมาแชตที่ทำเสร็จ
- **ไม่ได้ทำ** ไม่มี paste และไม่อ่านคลิปบอร์ด เพราะเป็นข้อมูลส่วนตัวของผู้ใช้ ต้องตัดสินแยก
- **ถ้อยคำในตัว signature** คำเตือน «ไม่ใช่ความลับ» และ «งานที่เขาหยุดดู» อยู่ใน signature เพราะเพดาน 520 tokens ของ pack ส่วนคำอธิบายเต็มอยู่ใน Guidance ตามมาตรฐานรีโป
- **ยังไม่ทดสอบสด** การเขียนคลิปบอร์ดจริงและการเด้ง notification จะไปทับคลิปบอร์ดและจอของผู้ใช้ — ต้องตรวจบนเครื่องเจ้าของ (เปิด Notepad แล้ว Ctrl+V · ปิดสวิตช์แจ้งเตือนแล้วต้องได้ประโยคบอกเหตุ ไม่ใช่รายงานว่าขึ้นแล้ว)
- **ไฟล์** `desktop/computer_outbox.go` (+ `_windows.go`, `_other.go`) · `desktop/computer_tool.go` · `internal/skill/category.go` · `internal/skill/packed.go` · `desktop/frontend/src/lib/toolFace.ts`

## ใบส่งงานห้าช่อง และทะเบียนของที่รออนุมัติ

- **เดิม** ตัวตนของโต๊ะผู้ช่วยจบด้วยบททดสอบ «ถ้าคุณเป็นเขาจะเซ็นไหม» แต่ไม่มีรูปทรงให้ตรวจว่าพร้อมเซ็นคืออะไร และไม่มีที่เดียวที่ของที่รอเจ้าของตัดสินไปรวมกัน
- **รุ่นนี้** `Brief` ห้าช่อง — ทำอะไร ทำไม ทางเลือกที่มีจริงพร้อมคำแนะนำ อะไรยังขาด ต้องตัดสินเมื่อไรและถ้าไม่ทำจะเกิดอะไร — ทุกช่องบังคับ และปฏิเสธช่องว่างพร้อมชื่อช่อง เพราะใบที่ขาดช่องอ่านเหมือนงานเสร็จ
- **ที่เก็บ** `WriteBrief` เขียน `.md` ลง `output/<session>/` ที่ห้องผลงานอ่านอยู่แล้ว และลงทะเบียนเป็นงานใน life store ตามวันที่ใน `DecideBy` — ไม่มีตารางใหม่ และ `LookoutNow` รายงานของค้างได้ทันทีโดยไม่ต้องแก้ lookout · เขียนเรื่องเดิมซ้ำในแชทเดียวกันอัปเดตแถวเดิม ไม่สร้างซ้ำ และไม่เลื่อนกำหนดที่ผู้ใช้ตั้ง
- **ไม่ได้ทำ** ยังไม่ลงทะเบียนเป็นผลงานบนหน้าผลงาน
- **ไฟล์** `internal/engine/brief.go` · `internal/engine/brief_test.go`

## เก็บเกี่ยวรายสัปดาห์ — ของที่ผลิตใน 7 วันจากห้องผลงาน

- **เดิม** คำถาม «สัปดาห์นี้ได้อะไร» ตอบได้ด้วยการไล่โฟลเดอร์ตามวันที่ ไม่มีมุมที่รวมของทั้งสัปดาห์ให้เจ้าของตัดสินครั้งเดียว
- **รุ่นนี้** `HarvestWeek(days)` ใช้ตัวสแกนของห้องผลงานตัวเดิม (`artifactRoots` / `sweepArtifacts`) ไม่สร้างดัชนีที่สองและไม่เขียน walker ใหม่ · เรียงใหม่ไปเก่า · `days=0` หมายถึง 7 · `artifacts.go` เปลี่ยน `rangeCutoff` ให้เรียก `dayCutoff` ตัวเดียวกับ harvest แทนการคำนวณซ้ำ ผลลัพธ์เดิมทุกไบต์ · แถว binding ของ `HarvestWeek` / `WriteBrief` / `LookoutNow` มาจาก `go generate`

## การ์ดคำถามจากจอข้างตอบถึงแชทที่ถาม ไม่หายเงียบ

## WebView2 ให้โฮสต์เห็นดาวน์โหลดของแท็บ และตอบสิทธิ์ตาม origin

- **เดิม** upstream `go-webview2` ไม่เคย subscribe `ICoreWebView2::DownloadStarting` — vtable กับ `ICoreWebView2_19` มีอยู่แล้ว แต่ขาด COM type และคนเรียก · ฝั่ง `PermissionRequestedEventArgs` มี slot `GetURI`/`GetIsUserInitiated` อยู่ใน vtable แต่ไม่มีเมธอด Go ห่อไว้ คำขอสิทธิ์จึงตอบได้แบบเดียวทั้งแอป และไม่รู้ด้วยว่าใครขอหรือผู้ใช้เป็นคนสั่งหรือหน้าเว็บขอเอง
- **รุ่นนี้** `aetox_download.go` เพิ่ม COM type ของ `DownloadStarting` พร้อม `DownloadRequest`/`DownloadAnswer` แบบค่า plain โดย `TotalBytes` เป็น -1 เมื่อเซิร์ฟเวอร์ไม่บอกขนาด แทนที่จะกลายเป็น 0 · `chromium.go` ติด `DownloadStartingCallback` และแปลง args เป็น request/answer — `Cancel` ใส่ทั้ง Cancel และ Handled, `ResultPath` เขียนทับปลายทาง ที่เหลือปล่อยไดอะล็อกและโฟลเดอร์เดิมของ engine · subscribe ผ่าน `ICoreWebView2_19` เฉพาะเมื่อโฮสต์ติด callback เท่านั้น ถ้า `QueryInterface` ไม่ได้ก็ยังดาวน์โหลดได้ตามปกติ · `corewebview2.go` เพิ่ม `GetURI`/`GetIsUserInitiated` และให้ `PermissionRequestedCallback` ตัดสินก่อน โดย `Default` ตกไปใช้ `globalPermission`/map เดิม
- **กติกาที่ใช้ทั้งไฟล์** ค่า zero หมายถึง «ปล่อยให้ engine ทำตามเดิม» ทุกจุด — ไม่ติด callback = พฤติกรรมเดิม และไม่ให้ครึ่งที่ portable ต้องเอ่ยชื่อ interface ของ engine
- **ไม่ได้ทำ** คอมมิตนี้แตะแค่ `third_party/go-webview2` — ฝั่งโฮสต์ที่เอา hook นี้ไปใช้ (นโยบายสิทธิ์จริงและที่บันทึก/แสดงรายการดาวน์โหลด) อยู่ในรุ่นนี้เหมือนกันที่ `desktop/browser_download.go` และ `desktop/browser_permission.go`

## PDF เป็นเครื่องมือเดียว 4 action และโต๊ะเปิดที่หน้าที่อ้าง

- **เดิม** `pdf_read` อ่านได้อย่างเดียว: ไม่มีเลขหน้าให้โมเดลอ้าง ไม่มีทางอ่านต่อเมื่อเอกสารยาวกว่า 220 บรรทัด และ PDF สแกนจบด้วย error — ทั้งที่หัวไฟล์เดิมเขียนทางแก้ไว้เองแล้ว («render the pages and OCR them … not built until someone actually hits it»)
- **รุ่นนี้** รวมเป็น tool เดียวชื่อ `pdf` ตามกฎที่หัวไฟล์ `codebase` วางไว้ — `info` / `read` / `render` / `ocr` เป็นสี่ระดับของ act เดียว และอ่านทั้งหมด จึงอยู่ใน `planKeeps` ได้ทั้งตัว ต่างจาก «เปิดบนโต๊ะ» ที่เป็นการกระทำต่อจอ และอยู่ที่ desk ต่อ
- **`info`** `pdfinfo` → จำนวนหน้า/ขนาด/ล็อก ให้โมเดลเลือกช่วงเอง · **`read`** ส่งช่วงหน้าให้ poppler (`-f`/`-l`) ป้าย `[p.N]` ทุกหน้า, `offset`/`limit` ต่อได้ และหน้าเป็นภาพ → render + Tesseract ให้เองในครั้งเดียว · **`render`** `pdftoppm` → PNG คืน path เท่านั้น (ใส่ `Output.Images` เฉพาะเมื่อโฮสต์บอกว่าโมเดลมองเห็น) · **`ocr`** บังคับ OCR สำหรับหน้าที่ text layer เพี้ยน (`ToUnicode` เสีย)
- **สิทธิ์แยกตาม action** `pdf_info` / `pdf_read` / `pdf_render` / `pdf_ocr` — helper ที่ดูหน้าเดียวไม่ใช่การให้สิทธิ์ดึงทั้งเอกสาร และ `pdf_read` คงชื่อเดิมไว้ เพื่อให้กฎ safety ที่เขียนไว้กับมันแล้วยังตรงกับการเรียกอ่าน
- **บนโต๊ะ** `at` → event open-file → `PdfPane` ที่ `#page=N` ทั้งแชทบนจอและ desk ที่บันทึกไว้ · marker ที่แนบมากับแชทเดิมยังถูกจับ เพราะ regex รับทั้ง `pdf_read` และ `pdf` ไม่งั้นเอกสารที่แนบไว้ในแชทเก่าจะหลุดจากโมเดลที่อ่านเอกสารเองได้
- **ไม่ได้ทำ** เครื่องมือแก้ PDF (รวม/แยก/ฟอร์ม/ลายเซ็น/redact) และ pdf.js — เหตุผลอยู่ในหัว `pdf.go` และ `PdfPane.svelte` · **ยังไม่ยืนยัน** reader ใน webview ว่าเคารพ `#page=N` ต้องดูบน dev
- **ไฟล์** `internal/skill/pdf.go` · `internal/skill/pdf_actions.go` · `internal/skill/packed.go` · `desktop/frontend/src/lib/workbench/PdfPane.svelte` · `desktop/frontend/src/lib/stores/workbench.svelte.ts` · `internal/engine/workbench_desk.go`
