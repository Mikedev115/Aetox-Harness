# 🪟 Aetox v1.11.10

วันที่ 12 พฤศจิกายน 2026

**รุ่นนี้แก้เรื่องตัวเลขของผิดแชทสองจุด: แถบสถิติของ pane ที่สองไม่ขึ้นเลยทั้งเส้น และแผงบริบทค้างค่าของแชทที่เพิ่งออกไปหลังสลับเซสชัน · พร้อมแก้คำที่ README ทำให้รุ่นปัจจุบันดูกินโทเคนเกินจริง**

## pane ที่สองมีแถบสถิติของแชทตัวเอง

- **เดิม** เปิดสองเซสชันข้างกันแล้วเห็นตัวเลขเฉพาะ pane ที่เพิ่งคลิก อีก pane ว่างทั้งเส้นจากสามทาง: ค่าใช้จ่ายถูกส่งเป็นค่าว่าง ค่าบริบทอ่านได้เฉพาะแชทที่ engine cursor อยู่ และ CPU/RAM ส่งให้เฉพาะ pane ที่ใช้งาน
- **รุ่นนี้** engine มี `ContextBreakdownFor(sessionID)` ที่ตอบให้แชทที่ระบุ — id ที่โปรเซสยังไม่ถือตอบค่าอ่านว่างพร้อมป้ายชื่อแชทนั้น ไม่ยืมตัวเลขของแชทที่ cursor อยู่ ส่วน pane ที่สองอ่านค่าใช้จ่ายจาก snapshot ที่แชทถูก park ไว้และอัปเดตทุกรอบที่มันทำงานด้วยตัวจำกัดรอบเดียวกับ pane ที่ใช้
- CPU/RAM วาดทั้งสอง pane เพราะ `machineLoad` มีตัวเฝ้าเดียวติดตั้งครั้งเดียว · pane ที่สองใช้ `ChatStats`/`StatusBar` ตัวเดิม ไม่ได้วาดแถบใหม่
- **ไฟล์** `internal/engine/app.go` · `internal/engine/cli_meter.go` · `desktop/frontend/src/lib/Chat.svelte` · `desktop/frontend/src/lib/stores/cockpit.svelte.ts` · `desktop/frontend/src/lib/split/besideView.ts`

## แผงบริบทไม่รับตัวเลขของอีกแชท

- **เดิม** สลับเซสชันแล้วตัวเลขของแชทที่เพิ่งออกไปยังอยู่บนแชทที่เข้ามา สองสาเหตุ: `Chat.svelte` ไม่เคยล้างค่าเดิมตอนเปิดเซสชัน และ effect ที่ขอค่าอ่านใหม่ผูกกับจำนวนข้อความเท่านั้น สองแชทที่มีจำนวนข้อความเท่ากันจึงไม่ขอใหม่เลย · อีกทางหนึ่ง `GetContextBreakdown()` ไม่ส่ง session id ไป ฝั่ง engine ตอบตาม `a.cur()` ของตัวเองซึ่งอาจยังไม่ขยับตอนสลับ
- **รุ่นนี้** ค่าที่วัดได้ประทับ `sessionId` ของ conversation ที่วัด และ `GetContextBreakdown` อ่าน `a.cur()` ครั้งเดียวตลอดฟังก์ชัน ป้ายชื่อกับตัวเลขจึงเป็นของแชทเดียวกันเสมอ · ฝั่งหน้าจอผูกค่ากับ `ctxSession` และผ่านประตูเดียว (`applyCtx`) ที่รับเฉพาะแชทของ pane นี้ที่ยังอยู่บนจอและ engine ยืนยันว่าเป็นแชทเดียวกัน ค่าเก่าถูกล้างก่อน ไม่ค้างข้ามแชท
- ไม่ได้เปลี่ยนรูปแผงหรือวิธีคำนวณ — เป็นเรื่องว่าตัวเลขเป็นของใคร
- **ไฟล์** `internal/engine/app.go` · `internal/engine/cli_meter.go` · `desktop/frontend/src/lib/Chat.svelte` · `desktop/frontend/src/lib/stores/cockpit.svelte.ts`

## README เลิกกล่าวอ้างเรื่องโทเคนของรุ่นปัจจุบัน

- **เดิม** ย่อหน้า "total input 1.1–8.5x / 91% cached" ใน README สามภาษาทำให้รุ่นปัจจุบันดูกินโทเคนกว่าคู่แข่ง ทั้งที่ตัวเลขนั้นมาจากการวัด 1.10.0 และยังไม่มีการวัด 1.11.x
- **รุ่นนี้** แทนด้วยตัวเลขที่รุ่นนี้พิสูจน์ได้: เพดานบล็อกเครื่องมือ 8,600 token ที่เทสต์บังคับ เครื่องที่เพิ่งติดตั้ง 26 tools / ~7,238 token และการ withhold 11 ตัวใน 1.11.0 ที่ทำให้บล็อกลดจาก 12,400 เหลือ 8,600 · รายงาน `coding-harness-1.10.0` ทั้งไทยและอังกฤษระบุว่าคอลัมน์ token เป็นของรุ่นนั้น ไม่ใช่ของวันนี้
- ไม่ได้วัดใหม่และไม่ได้แก้ตัวเลขที่เป็นประวัติ — เปลี่ยนแค่คำที่ทำให้อ่านเป็นสเปกของรุ่นปัจจุบัน
