# 🪟 Aetox v1.10.44

วันที่ 2 พฤศจิกายน 2026

**รุ่นนี้แก้ของที่เจอจากการใช้งานจริงสามเรื่อง — ความจำที่เต็มแล้วปฏิเสธการจำทั้งที่หน้าที่ของมันคือจำ, เบราว์เซอร์ที่เล็งชี้ถูกตัวแล้วแต่กดไม่ติด, และเทสต์ shelf ที่แดงค้างบน main ทั้งที่โค้ดทำงานถูก — พร้อมแก้ชื่อผู้ถือลิขสิทธิ์ที่สะกดผิดในทุกไฟล์ และให้คอมมิตของรีโปนี้บอกว่า Aetox ร่วมเขียน**

## ความจำเต็มแล้วพับของเดิมให้พอดี แทนที่จะปฏิเสธบรรทัดใหม่

- **เดิม** ความจำล้มเหลว 27% ของ 211 ครั้งบนโต๊ะผู้ช่วย และข้อความที่พบมากที่สุดคือ «this scope's memory is full (limit 8192 bytes)» — เครื่องมือที่หน้าที่หลักข้อหนึ่งคือ «จำแทน» กลับปฏิเสธการจำ เพราะเพดานเป็นรายไฟล์และเขียนได้เฉพาะเมื่อยังมีที่ว่าง คนใช้จึงต้องกลับไปกด «สรุปความจำ» เองก่อนแล้วจึงจำได้
- **สาเหตุ** ตัวสรุปที่มีอยู่แล้ว (ปุ่ม «สรุปความจำ») ทำงานเฉพาะตอนมีคนกด ไม่มีเส้นทางใดใน MemoryTool ที่เรียกมันเมื่อไฟล์เต็ม ประตูเขียนจึงมีทางเดียวคือปฏิเสธ
- **รุ่นนี้** ไฟล์เต็มแล้วตัวสรุปถูกเรียกให้พับของเดิมจนเหลือที่พอ แล้วบรรทัดใหม่ผ่านประตูเดิม (`keepMemory`) — ไม่ใช่เขียนเองทั้งดุ้น เพราะประตูนั้นคือที่มาของปุ่ม undo และ ledger ที่จำว่าผู้ใช้เคยปฏิเสธอะไร ถ้าเขียนข้ามประตู สองอย่างนั้นจะหายไป
- **เพดานยังอยู่และยังตรวจเหมือนเดิม** พับแล้วไม่สั้นลงจริง = ไม่เขียนและคืนคำปฏิเสธเดิม · ไม่มีตัวสรุป (เช่นในเทสต์หรือเมื่อผู้ให้บริการล่ม) = คำปฏิเสธเดิม · คำตอบว่างหรือพัง = ไฟล์ไม่ถูกแตะ
- **ต้นทุน** โมเดลหนึ่งครั้ง เฉพาะตอนที่ไฟล์เต็มเท่านั้น
- **ไม่ได้ทำ** บรรทัดที่ถูกพับรวมกันยัง undo ทีละบรรทัดไม่ได้ (เฉพาะบรรทัดใหม่ที่ยัง undo ได้) และตัวเลข 27% จะลดลงเท่าไรต้องรอใช้จริง — เทสต์ใช้ตัวพับปลอม ไม่ได้ยิงโมเดลจริง
- **ไฟล์** `internal/learned/learned.go` (`EntryBudget`, `Rewrite`) · `internal/learned/tool.go` (`Compactor`, `foldForRoom`) · `internal/engine/consolidate.go` (`Compact`) · `internal/engine/app.go` (ต่อตัวสรุปให้ MemoryTool) · `internal/learned/tool_compact_test.go`

## เบราว์เซอร์เล็งซ้ำด้วยข้อความของ element เมื่อกดไม่ติด

- **เดิม** โต๊ะผู้ช่วยคลิกเบราว์เซอร์พลาด 52 จาก 597 ครั้ง (8.7%) แยกเป็นสามกอง: ข้อความซ้ำหลายตัว 51 · ref หาย 36 · ไม่พบข้อความบนหน้า 33 กองที่สองเป็นของเราเอง — aim หา element เจอและวาดวงไปแล้ว แต่พอถึงจังหวะกด element หายไป
- **สาเหตุ** ทุกรอบ read ตั้งเลข ref ใหม่ทั้งหน้า และหน้าที่ re-render เอา attribute ติดไปด้วย ข้อความที่โมเดลได้ยินจึงชี้ไปคนละตัวกับตอนที่เล็ง
- **รุ่นนี้** กดไม่เจอแล้วเล็งซ้ำด้วยข้อความของ element หนึ่งครั้ง (`refMissRetry`) ทำทั้ง click และ type ซึ่งเป็นสองที่เดียวที่กลับไปใช้ ref หลังเล็ง (hover/drag/upload เล็งด้วยพิกัด และ `BrowserClickRef` ของผู้ใช้เองไม่แตะ)
- **ไม่ใช้เลข ref ซ้ำ** เพราะหลัง tag ใหม่เลขเดิมคือคนละตัว และการกดผิดตัวแย่กว่ากดไม่ติด — ความปลอดภัยมาจาก `findByText` ที่ปฏิเสธเมื่อข้อความตรงหลายตัว ปุ่ม «ไม่เจอ» จึงยังคืนคำปฏิเสธเดิม
- **ไม่ได้ทำ** กอง «ข้อความซ้ำ» (51 ครั้ง) ไม่ได้แตะ เพราะระบบเดาตัวที่ใกล้ที่สุดแทนไม่ได้ และการเดาคือพังที่แย่กว่าสำหรับคนที่กำลังดูหน้าจออยู่ · ยังไม่ยืนยันผลจากตัวเลข ต้องรอใช้จริงหลังรุ่นนี้
- **ไฟล์** `desktop/browser_gestures.go` · `desktop/workbench.go` · `desktop/browser_ref_miss_test.go`

## เทสต์ shelf ขอทางที่ไม่ eager อย่างชัดเจน — โค้ดไม่เปลี่ยน

- **เดิม** `internal/bootstrap` และ `internal/subagent` แดงค้างบน main มาก่อนงานนี้: เทสต์เขียน config ของเซิร์ฟเวอร์โดยไม่ตั้ง `Eager` แล้วคาดหวังว่าจะเห็น shelf
- **สาเหตุ** กฎที่เพิ่มมาทีหลัง (`config.MCPServerConfig.EagerLoad`) บอกว่าเซิร์ฟเวอร์ที่ถูกชี้ให้เอเจนเท่านั้นโหลดเต็มตั้งแต่รอบแรก เพราะเอเจนได้มันมาเพื่องานนั้นอยู่แล้ว `ShelfFor` จึงข้ามมัน — เทสต์จึงเห็น shelf ว่าง ทั้งที่โค้ดทำงานตามที่ตัดสินไว้
- **รุ่นนี้** เทสต์ขอทาง shelf อย่างชัดเจน (`Eager: &false`) แทนการพึ่งค่าเริ่มต้น และเพิ่มข้อยืนยันว่าเซิร์ฟเวอร์ agent-only ที่ไม่ตั้งคีย์ไม่อยู่บน shelf — กฎนี้เคยมีแต่คอมเมนต์ ไม่มีเทสต์คุม
- **ไฟล์** `internal/bootstrap/mcp_shelf_test.go` · `internal/subagent/mcp_shelf_test.go`

## คอมมิตของรีโปนี้บอกว่า Aetox ร่วมเขียน

- `scripts/hooks/prepare-commit-msg` เติม trailer `Co-Authored-By: Aetox …` ก่อนบล็อกคอมเมนต์ของ git ไม่ซ้ำบรรทัดเดิม ไม่แตะ merge/squash และไม่มีผลเลยถ้ายังไม่ตั้งที่อยู่ · ที่อยู่เก็บใน `git config aetox.coauthor` ไม่ได้อยู่ในไฟล์ เพราะเป็นเลข id ของบัญชี
