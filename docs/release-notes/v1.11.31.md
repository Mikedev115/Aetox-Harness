# 🪟 Aetox v1.11.31

วันที่ 21 พฤศจิกายน 2026

รุ่นนี้แก้เรื่องที่เจอตอนใช้จอแบ่ง — ระดับคุณภาพของแชทสลับข้างกัน — และเปิดเส้นทางบิลด์แอป Linux ขึ้นมาพร้อม job CI ที่ทำให้ไฟล์ฝั่งที่ไม่ใช่ Windows ถูกคอมไพล์และรันเทสต์อีกครั้งเป็นครั้งแรกนับจาก 18 กันยายน

## ระดับคุณภาพเป็นของแต่ละพาเนล ไม่สลับกันตอนเปิดสองจอ

- **เดิม** คุณภาพเป็นพิกัดของแชทมาตั้งแต่ 15 พ.ย. แต่ถูกต่อสายไว้แค่ทางเปิดเซสชัน ไม่ได้เข้าชุดเดียวกับ stance ที่พาเนลที่พักอ่านผ่าน `besideView` เปิดสองจอเทียบกันแล้วชิป "สูงสุด" ไปโผล่แชทที่ตั้งมาตรฐาน และโฟกัสแชทที่ตั้งสูงสุดไว้กลับขึ้นมาตรฐาน (เจ้าของ 21 พ.ย. 2026: "จู่ๆ คุณภาพสูงสุดก็ไปแสดงอีกเซสชั่น")
- **ตอนนี้** `BesideSnap` เก็บระดับคุณภาพไว้กับสถานีของแชทที่พัก · `arriveAt` จับค่าตอนแชทออกจากจอ · `swapToBeside` คืนระดับให้แชทที่กลับมา และถาม engine เมื่อไม่มี snap ให้คืน · `besideView` อ่านระดับจาก snap แทนการไหลไปอ่านค่าของ cockpit · ชั้นต่ำสุดของพาเนลที่พักคือมาตรฐาน — สิ่งที่แชทไม่เคยเลือกรันอยู่ — ไม่ใช่ระดับของอีกฝั่ง
- **เทสต์** `splitView.test.ts` เพิ่ม 2 เคส: สองพาเนลต่างระดับกันต้องไม่ทับกัน และสลับพาเนลแล้วระดับติดกับแชท · ถอดสองบรรทัดที่แก้ชั่วคราวแล้วรันซ้ำ เทสต์ใหม่ล้มทั้งคู่ (ได้ std แทน max) ยืนยันว่าจับบั๊กจริง · vitest `splitView` (20) กับ `sessionQuality`/`qualityAfterTurn`/`qualityChip` ผ่าน · tester กดบน dev จอแบ่งผ่าน 5/5
- **ไฟล์** `desktop/frontend/src/lib/split/besideView.ts` · `desktop/frontend/src/lib/stores/cockpit.svelte.ts` · `desktop/frontend/src/lib/stores/split.svelte.ts` · `desktop/frontend/src/test/splitView.test.ts`

## เส้นทางบิลด์แอป Linux ใน Docker และ job CI บน ubuntu

- **เดิม** ตั้งแต่ 18 กันยายน ไม่มีอะไรคอมไพล์ไฟล์ `!windows` เลย และ `-race` ไม่ได้รันที่ไหน — ด่านเดียวที่เหลือคือ cross-build ของเอนจิน ซึ่งคอมไพล์อย่างเดียวและไม่รันเทสต์ (`context_windows.go` เคยทำให้เอนจินคอมไพล์บน Linux ไม่ผ่านโดยไม่มีใครเห็นก่อนติดแท็ก)
- **ตอนนี้** `docker/linux/Dockerfile` ใช้ ubuntu 24.04 กับ `libwebkit2gtk-4.1-dev` (noble ไม่มี 4.0 แล้ว) Go 1.26.8, Node 22.22.1 และ wails 2.17.1 ตรงกับ `go.mod` · `scripts/linux/build.sh` คอมไพล์จากเมานต์ ไม่ใช้ `-clean` เพราะ `desktop/build/bin/aetox-dev.exe` ที่ `wails dev` ถืออยู่ลบไม่ได้บน DrvFs และ `node_modules` เป็น named volume เพราะของ host เป็นไบนารี Windows · `scripts/linux/run-wslg.sh` เปิดแอปบน WSLg · job `linux` ใน CI ติดตั้ง GTK/WebKitGTK แล้วรัน `go vet` → `go test` → `go test -race` → `go build` ด้วย `-tags webkit2_41`
- **วัดแล้ว 20 พ.ย. 2026** `bash scripts/linux/build.sh` บน WSL (Docker 29.1.3) ได้ `Built … in 4m25.099s` เป็น ELF x86-64 80,669,584 ไบต์ เปิดผ่าน Docker + WSLg แล้ว `xwininfo` เห็นหน้าต่าง Aetox Harness ขนาด 1440x900
- **ยังไม่ใช่คำประกาศว่า Linux พร้อมใช้** รุ่นนี้ยังไม่ส่งไบนารี Linux ไปกับ release · Docker กับ WSLg พิสูจน์ไม่ได้ว่า z-order, frame extents และ always-on-top ถูกชั้นบน GNOME/KDE จริง (`docker/linux/README.md` §What Docker still cannot prove)
- **ไฟล์** `.github/workflows/ci.yml` · `docker/linux/Dockerfile` · `docker/linux/README.md` · `scripts/linux/build.sh` · `scripts/linux/run-wslg.sh`
