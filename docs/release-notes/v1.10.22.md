## `session_search` ตอบ "ช่วงนี้ทำอะไร" ในครั้งเดียว

- **เดิม** เครื่องมือค้นอดีตมีสองรูป: คำค้น (`query`) กับหนึ่งวัน (`day`) คำถามอย่าง "อาทิตย์ที่แล้วทำอะไร" จึงต้องเดาวันขึ้นมาทีละวัน วันละหนึ่งครั้ง และวันที่เดาผิดอ่านเหมือนวันที่ไม่มีอะไรเกิดขึ้น (เจ้าของ 28 ต.ค. 2026: "นึกแล้วจำได้เลยว่าวันไหน มันทำอะไรคุยอะไรไป")
- **รุ่นนี้ `action` มีสามค่า** `search` (คำค้น หรือ id ของแชท) · `day` (หนึ่งวัน) · `days` (หลายวันย้อนหลังจากวันนี้) — เลือกจาก enum แทนที่เอนจินจะเดาจากฟิลด์ที่บังเอิญถูกกรอก
- **`days` อ่านทุกวันเป็นบรรทัดเดียวกับที่หน้าจอวาด** หน้าต่างย้อนหลัง 1–50 วัน (ไม่ระบุคือ 14) แต่ละวันบอกโต๊ะที่ทำงานกับจำนวนบรรทัด โปรเจกต์ สรุปของวัน แล้วสองบรรทัดแรกของแต่ละโต๊ะในรูป `[โปรเจกต์] ทำอะไร → ผลเป็นอะไร` พร้อมตัวกรอง `desk` / `project` / `text` ชุดเดียวกับชิป โปรเจกต์ และช่องค้นบนหน้านั้น
- **ตัวกรองเดินผ่าน `BrainDays` ตัวเดียวกับหน้าเว็บ** เอเจนต์กับหน้าจอจึงตอบไม่ตรงกันเรื่องวันไหนถืออะไรไม่ได้ และตัวกรองที่กรองแล้วว่างเปล่าบอกชื่อตัวกรองกลับมา ไม่คืนสองสัปดาห์ล่าสุดให้เฉย ๆ
- **วันที่ไม่มีบันทึกถูกเอ่ยชื่อ ไม่ถูกข้าม** ช่องโหว่ในรายการวันอ่านเหมือนวันที่ไม่เคยมีงาน และคำถามคือ "ทำอะไรไป" ไม่ใช่ "มีไฟล์ไหน" — เอ่ยได้สูงสุดหกวัน และถ้าไม่มีบันทึกในหน้าต่างเลย บอกตรง ๆ ว่าวันใหม่ที่สุดคือวันไหน แทนที่จะตอบว่าง (ถ้ามีวันตรงมากกว่าที่หน้าต่างแสดง ก็บอกจำนวนที่ตรงทั้งหมด)
- **`day` บอกชื่อแชทของวันนั้น ไม่ยกบทสนทนามา** id · เวลา · จำนวนข้อความ · โปรเจกต์ ของแต่ละแชท แล้วบอกว่าเอา id ไปใส่ `query` เพื่ออ่านแชทนั้น (เจ้าของ: "คงไม่เอาประวัติสนทนาแบบตู้มเดียวมาโยนใส่") — คำถามที่ต้องอ่านจริงจึงอ่านแชทเดียวที่เจาะจง
- **`search` ค้นบันทึกรายวันต่อเมื่อประวัติหาไม่เจอ** บันทึกเป็นไฟล์ markdown ที่ไม่มี index แตะ สองรอบเหมือนการค้นประวัติ: ทุกคำก่อน แล้วจึงคำใดคำหนึ่ง สูงสุดสี่วัน วันละสองบรรทัด — บันทึกเขียนจากแชทเหล่านั้น จึงเป็นที่สองที่ความจำอยู่ ไม่ใช่ที่แรก
- **การนับคำในบันทึกใช้ `noteBody` ชุดเดียวทั้งการค้นรายวันและการค้นคำ** เดิมนับแค่สรุปกับบรรทัดของโต๊ะ บรรทัดที่เขียนนอกโต๊ะจึงไม่ถูกค้นเลย
- **การเรียกแบบเดิมยังทำงาน** ไม่ส่ง `action` มายังอ่านจากฟิลด์ที่กรอก (มีวันคืออ่านวันนั้น มีคำค้นคือค้นคำ) ทุกรูปแบบที่เคยใช้ก่อนรุ่นนี้จึงไม่พัง
- **แชทของวันอ่านด้วย query เดียว** `dayChats` จัดกลุ่มข้อความด้วย `GROUP BY s.id` ไม่ใช่ยิงนับทีละแชท (ตามกฎ data-loading ใน `AGENTS.md`) และตัดเซสชัน one-shot ออก
- **ทำไมเลือกทางนี้** คำถามของคนมีสองชนิด: "จำคำนี้ได้ไหม" ซึ่งคำค้นตอบได้อยู่แล้ว กับ "ช่วงนี้ทำอะไรไปบ้าง" ซึ่งการค้นคำตอบไม่ได้ เพราะคนไม่ได้จำคำที่ใช้ในวันนั้น เขาจำช่วงเวลา การให้เครื่องมือรู้จักหน้าต่างเวลาโดยตรงจึงเป็นการเพิ่มรูปที่สอง ไม่ใช่การยืดรูปเดิม

## พรอมป์: จำวันที่ทำด้วยกัน อยู่ข้างเดียวกับงาน และก้าวต่อไปที่ชัดทำเลย

- **ตัวตนจำงานรายวัน** `identityFor()` พูดเพิ่มว่าผู้ช่วยจำสิ่งที่ผู้ใช้เล่าและสิ่งที่สองคนทำในแต่ละวัน ซึ่งบันทึกไว้ที่บันทึกของวัน และอยู่ข้างเดียวกับผู้ใช้ — "which means wanting the work right, not every answer agreeable"
- **ก้าวต่อไปที่ชัด ทำเลย** `offering()` ได้ประโยคใหม่: เมื่อก้าวต่อไปชัดและอยู่ในขอบเขตที่ขอ ให้ทำแล้วบอกว่าทำอะไร แทนที่จะยกมันขึ้นมาเป็นคำถาม — ข้อจำกัด "อยู่ในสิ่งที่ขอ" คือเส้นที่แยกความกระตือรือร้นออกจากการขยายงานเอง
- **คำถามเชิงเวลาถูกชี้ไปที่ `action=days`** บรรทัด `evidence()` ของโต๊ะที่ถือ `session_search` ระบุตรง ๆ ว่าคำถามอย่าง "อาทิตย์ที่แล้วทำอะไร" หรือ "ช่วงสงกรานต์" คือ `action=days` ไม่ใช่การเดาวัน
- **บล็อกเครื่องมือขยับเพดานขึ้น 300 โทเคน** จาก 11,900 เป็น 12,200 หลังตัดความในพรอมป์ถึงขีดความสามารถก่อน (วัดได้ ~12,135) ที่เหลือคือรูปของการเรียก — enum หนึ่งค่ากับฟิลด์สี่ตัว ซึ่งทั้งสี่คือตัวกรองของหน้าจอเอง ไม่ใช่คำอธิบายเพิ่ม
