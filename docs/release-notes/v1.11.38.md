# 🪟 Aetox v1.11.38

วันที่ 24 พฤศจิกายน 2026

รุ่นนี้ปิดช่องที่ทำให้คนอ่านการ์ดผิดสองจุดในเรื่องเดียวกัน: ssh ไปเครื่องที่ตัวเองกดไว้ใจแล้ว ยังขึ้นการ์ดที่ดูเหมือน «ไว้ใจไม่ติด» และคู่มือก็เขียนไว้กว้างกว่าที่ระบบทำจริง สองจุดนั้นแก้ที่ต้นเหตุ ไม่ใช่แค่ถ้อยคำ — การ์ดที่ขึ้นแทนบอกเองว่าเครื่องอยู่ในรายการ และคู่มือแยกให้เห็นว่าสามโหมดทำต่างกันอย่างไร ส่วนสกิล `aetox-performance` ที่เดินทางไปกับไบนารีได้ด่านใหม่สามเรื่องที่ทำให้ตัวเลขวัดมาถูกเทียบได้จริง

## ssh ไปเครื่องที่ไว้ใจแล้ว: การ์ดที่ขึ้นแทนบอกว่ารายการถูกอ่านแล้ว

- **เดิม** เครื่องที่อยู่ในรายการ «เครื่องที่ไว้ใจ (ssh)» ไม่ยกการ์ด ssh อีก แต่ในโหมด «ถาม» และ «เฉพาะที่ไม่ปลอดภัย» บรรทัดนั้นยังเป็นการ์ดธรรมดาเพราะเป็นคำสั่งที่ออกเครือข่าย — และการ์ดนั้นมีเพียง «อนุญาต» กับ «ปฏิเสธ» ไม่มีปุ่มไว้ใจที่สามและไม่มีประโยคไหนพูดถึงรายการ ผู้ใช้จึงอ่านได้ว่า «ที่กดไว้ใจเมื่อวานไม่ได้ถูกบันทึก» ซึ่งเป็นอาการที่ถูกรายงานมา (issue #71, 17 พฤศจิกายน 2026)
- **ตอนนี้** `internal/skill/shell_ssh_remote.go` แยกเครื่องที่ไว้ใจออกจากเครื่องที่ต้องถามเป็นสองรายการ เมื่อทุกเครื่องบนบรรทัดอยู่ในรายการแล้ว การ์ด ssh ไม่ถูกยก และการ์ดที่ขึ้นแทนมีประโยคที่บอกชื่อเครื่องกับที่มาของการ์ดเอง: «… is on your trusted list, so no ssh card is raised for it — this card comes from the approval mode asking about the command itself»
- สิ่งที่ **ไม่** เปลี่ยนคือการตัดสินใจ: ผลกระทบ ความเสี่ยง และช่องไว้ใจของการ์ดนั้นมาจากการอ่านคำสั่งธรรมดา ไม่ได้มาจากรายการที่ไว้ใจ และ `toolCallToArgs` แยกคำสั่งด้วยวิธีเดิม — ประโยคที่เพิ่มมาเป็นการอธิบาย ไม่ใช่สิทธิ์ใหม่
- `TestRemoteShellIsAskedUntilTrusted` และ `TestSSHTrustRuleMatchesNoTool` ปักสี่ข้อ: การ์ดที่ขึ้นแทนไม่มี `EffectRemoteShell` · ไม่มีปุ่มไว้ใจให้กด · โหมด «ถาม» และ «เฉพาะที่ไม่ปลอดภัย» ยังถามเพราะบรรทัดออกเครือข่าย · โหมด «สิทธิ์เต็ม» ไม่ถามเลย และเทียบผลกระทบกับความเสี่ยงกับการอ่านคำสั่งเดียวกันแบบไม่มีความไว้ใจแล้วได้ค่าเท่ากัน

## คู่มือ: บรรทัด «เครื่องที่ไว้ใจ (ssh)» บอกความจริงตามโหมด

- **เดิม** หน้าความสามารถ → การเชื่อมต่อ → «เครื่องที่ไว้ใจ (ssh)» เขียนว่า «ssh ไปเครื่องเหล่านี้ไม่ต้องถามก่อน» ซึ่งจริงเฉพาะโหมด «สิทธิ์เต็ม» อีกสองโหมดยังถามในฐานะคำสั่งที่ออกเครือข่าย คู่มือจึงสัญญาเกินกว่าระบบทำ
- **ตอนนี้** ข้อความไทยและอังกฤษ (`desktop/frontend/src/lib/locales/th.ts`, `en.ts`) บอกแยกตามโหมด: ssh ไปเครื่องในรายการไม่มีการ์ด ssh ในทุกโหมด แต่ «ถาม» และ «เฉพาะที่ไม่ปลอดภัย» ยังถามในฐานะคำสั่งที่ออกเครือข่าย ส่วน «สิทธิ์เต็ม» ทำงานได้เลย และเครื่องอื่นถามทุกครั้ง
- `npx vitest run src/test/localeGuard.test.ts src/test/guideCatalog.test.ts` ผ่าน 14/14 — คู่มือยังอ้างคีย์ที่มีจริงและข้อความไม่หลุดจากดัชนี

## สกิล `aetox-performance`: ด่านดริฟต์ งบเดสก์ท็อป และ memory ข้ามรอบ

- **เดิม** สกิลสั่งให้วัดก่อนและหลังแล้วเทียบ แต่ไม่ได้กำหนดว่าเมื่อไรสองตัวเลขนั้นเทียบกันได้จริง ตาราง `references/data-loading.md` จึงจับได้แค่ของที่โตขึ้นระหว่างการใช้งาน ไม่มีแถวสำหรับของที่รั่วข้ามรอบเปิด/ปิดจอ และ `references/tools.md` ไม่มีวิธีวัดหน่วยความจำของทั้ง session
- **ตอนนี้** `SKILL.md` เพิ่มด่านหนึ่งข้อ: การเทียบใช้ได้เมื่อทั้งสองข้างรันในโหมดบิลด์เดียวกัน (dev หรือ release) ข้อมูลขนาดเดียวกัน และเครื่องภายใต้ภาระเดียวกัน ถ้าต่างกันข้อใดข้อหนึ่ง การเทียบนั้นเป็น **โมฆะ** ไม่ใช่ «อธิบายได้» — และให้รันของที่ไม่เปลี่ยนวางข้าง ๆ ในรอบเดียวกัน เพื่อดูว่าเครื่องขยับหรือเปล่า ก่อนโทษโค้ดที่เพิ่งแก้
- `data-loading.md` ได้แถวใหม่ **Leak across cycles**: listener, รายการใน store หรือ DOM node ที่ไม่มีใครปล่อยเมื่อจอปิด — วัดที่ 50 รอบเปิด/ปิด ไม่ใช่รอบเดียว โดยดู private working set ของ process ที่เรนเดอร์ กับ heap snapshot สองใบ ว่าเส้นยังไต่หลังบังคับ GC หรือไม่ · แถว chatty boundary เติมอีกครึ่งที่หายไป: **นับไบต์ด้วย** เพราะหนึ่งครั้งที่หิ้ว 4 MB แพงเท่าสี่สิบครั้งเล็ก
- `tools.md` เพิ่มวิธีวัดหน่วยความจำข้าม session (process ของตัวเรนเดอร์ ไม่ใช่ process ของแอป) และงบเวลาเริ่มต้นสำหรับงานเดสก์ท็อปเมื่อคนใช้ยังไม่มีงบของตัวเอง: คลิกต้องเห็นการเปลี่ยนแปลงของตัวเองภายใน 100 ms · รายการที่ข้อมูลจริงเข้าถึงต้องอ่านได้ภายใน 400 ms · อะไรที่นานกว่านั้นต้องแสดงอะไรบางอย่างภายใน 300 ms — และให้บอกจำนวนเฟรมที่หล่นคู่กับเวลารวม ไม่ใช่บอกแต่ผลรวม
- สกิลเดินทางไปกับไบนารี เนื้อหาที่เปลี่ยนคือสิ่งที่โมเดลอ่านตอนทำงานประสิทธิภาพครั้งถัดไป ไม่มีหน้าจอใหม่ในรุ่นนี้
