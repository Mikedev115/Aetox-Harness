# 🗂️ Aetox v1.10.17

วันที่ 26 ตุลาคม 2026

**ไฟล์ที่เปิดอยู่บอกได้ว่าตัวเองอยู่โฟลเดอร์ไหน — กดท่อนโฟลเดอร์กลับไปได้ คัดลอกที่อยู่ได้ — และแผงไฟล์มีชุดปุ่มมุมมองเดียวกันทั้งฝั่งโค้ดและฝั่งผู้ช่วย**

## ที่อยู่ของไฟล์บนหัวหน้าต่าง

- **เดิม** แถบแท็บมีที่ให้ชื่อไฟล์เท่านั้น ชื่อเดียวไม่ได้บอกว่าไฟล์อยู่ที่ไหน และชื่อเดียวกันมีอยู่เป็นสิบโฟลเดอร์
- **รุ่นนี้** แถวที่อยู่ใต้แถบแท็บของทุกแท็บไฟล์ ทั้งใน Workbench และโหมดเขียน แสดงโฟลเดอร์ของไฟล์ที่เปิดอยู่ แบ่งเป็นท่อนตามลำดับ ชื่อไฟล์ยังอยู่บนหัวตัวแก้ไขเหมือนเดิม ที่อยู่เต็มอยู่ใน tooltip จึงไม่มี path สองแถวซ้ำกัน
- **ทุกท่อนกดกลับได้** ไฟล์ที่มีรากของตัวเองไปทาง `browseFolderAt` ไฟล์ในโปรเจกต์ไปทาง `revealTreePath` เพราะเอนจินปฏิเสธ browse root ที่สองเมื่อมีโปรเจกต์เปิดอยู่ และแผงไฟล์ถูกชูขึ้นมาพร้อมเลื่อนแถวนั้นให้เห็น ไม่ใช่เปิดโฟลเดอร์ให้แล้วทิ้งคนไว้ที่อื่น
- **ปุ่มคัดลอกที่อยู่** แยกจากท่อนโฟลเดอร์ เพราะแถวที่เป็นทั้งลิงก์และปุ่มคัดลอกทำได้ไม่ดีทั้งสองอย่าง ใช้คลิปบอร์ดของเบราว์เซอร์ก่อน แล้วถ้าไม่ได้จึงใช้ `ClipboardSetText` ของ runtime พร้อมข้อความยืนยันสั้น ๆ
- **ปุ่มเปิดโฟลเดอร์ในเครื่อง** มีเฉพาะไฟล์ใต้โปรเจกต์ เพราะ `RevealProjectPath` ตอบเฉพาะ path ที่ sandbox ของเอนจินแก้ได้ ไฟล์ที่เปิดจากนอกโปรเจกต์จึงแสดงที่อยู่โดยไม่มีปุ่มที่กดแล้วได้แต่ error
- **แถวนี้วาดที่เดียว** ทุกชนิดไฟล์มี pane กับหัวของตัวเอง ถ้าแถวอยู่ข้างในจะต้องวาดสิบหกที่ Workbench จึงวาดในช่องไฟล์ครั้งเดียว และ pane ไม่ต้องรู้ว่ามีแถวนี้
- **การพับ path** (เกินสี่ท่อนแล้วเหลือไดรฟ์กับสองท่อนท้าย) ย้ายจาก `FileTree` ไปอยู่ที่ `lib/filePath.ts` ที่เดียว breadcrumb ของแผงไฟล์กับแถวเหนือไฟล์จึงพับทางเดียวกัน และไม่มีสำเนากติกาไว้คนละชุด

## มุมมองของแผงไฟล์ — ชุดปุ่มเดียวสำหรับสองที่

- ปุ่มกรองกับเมนูมุมมองย้ายมารวมเป็น `ViewActions` ตัวเดียว ใช้ทั้ง Explorer ฝั่งโค้ดและแท็บ ไฟล์ ที่เปิดกลางจอ ซึ่งฝั่งผู้ช่วยเดิมไม่มีเมนูมุมมองเลย ห้ามุมมองหนึ่งหายไปจากที่ที่คนมองอยู่
- มุมมองที่เลือกได้: **รายการ · ตาราง · ไอคอน · เนื้อหา** โดยเนื้อหาคือแถวละไฟล์พร้อมบรรทัดข้อมูลของตัวเอง (ขนาดและเวลา หรือคำว่าโฟลเดอร์) และรูปย่อถ้ามี — อ่านไล่ลงได้ ไม่ใช่กระเบื้องที่ต้องกวาดตา
- ไทล์ถูกสร้างแล้วถอดออกในคืนเดียวกันตามที่สั่ง ค่าที่ค้างใน `localStorage` จากบิลด์ที่รู้จักไทล์จึงถูกอ่านผ่าน `fileViewOf()` แล้วตกกลับเป็นรายการ แผงไฟล์ไม่ค้างอยู่โดยไม่มีมุมมอง
- ปุ่มคู่วางข้าง breadcrumb ไม่ใช่ข้างใน เพราะ nav ตัดของที่ล้น (path ยาว) และเมนูที่อยู่ในกล่องที่ถูกตัดคือปุ่มที่ดูเหมือนกดไม่ได้
- ตารางไอคอนเปลี่ยนจากสามคอลัมน์ตายตัวเป็น `auto-fill` ที่ 104px แผงแคบได้สามคอลัมน์เหมือนเดิม แต่แท็บกว้างไม่ยืดเป็นสามกล่องยักษ์ และกระเบื้องที่อยู่นอกจอข้ามการวาด (`content-visibility`) — โฟลเดอร์สี่พันแถวไม่ต้องวาดทั้งหมดก่อนเลื่อน

## เปลี่ยนอื่น ๆ ในรุ่นนี้

- ไฟล์นอกโปรเจกต์ที่เปิดค้างไว้และโปรเจกต์ถูกปิดทีหลัง ท่อนโฟลเดอร์แบบ relative จะถูกวาดเป็นข้อความ ไม่ใช่ปุ่มที่กดแล้วไม่มีอะไรเกิดขึ้น
- `Explorer.svelte` สั้นลงเพราะปุ่มคู่กับเมนูย้ายออกไปอยู่ที่ `ViewActions` แล้ว
- tests ที่เพิ่มในรุ่นนี้: `filePath.test.ts` (การพับ path และการแยก absolute กับ relative), `filePathLine.test.ts` (แถวที่อยู่และเป้าหมายของแต่ละท่อน), `explorerContent.test.ts` (มุมมองเนื้อหาและค่าที่ค้างจากบิลด์อื่น) และ `deskDrop.test.ts` ที่ยืนยันว่า pane วาดไฟล์ที่เปิดจริง
