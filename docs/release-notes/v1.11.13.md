# 🪟 Aetox v1.11.13

วันที่ 14 พฤศจิกายน 2026

**รุ่นนี้เปลี่ยนคอลัมน์ซ้ายของโต๊ะโค้ดเป็นรายการโปรเจกต์จริง: แถว "ไม่ผูกกับโปรเจกต์" อยู่บนสุดคงที่ บอกได้ว่ามีโปรเจกต์อื่นอีก 3 แถว · หน้าต่างเครื่องอ่าน VRAM ที่ใช้จริงจากไดรเวอร์และแท่งคอร์มีเลขกับ P/E · แท็บเบราว์เซอร์จำรหัสผ่านได้เหมือนที่จำคุกกี้ · แชทที่กำลังทำงานเปิดใหม่แล้วประวัติขึ้น และลบได้พร้อมเหตุผล · งานหนึ่งงานส่งให้ CLI ภายนอกได้แล้วพร้อมรหัสความล้มเหลว · และหน้าจอมือถือที่มาจากรุ่นนี้เห็นความคิดไหลระหว่างเทิร์น**

## คอลัมน์โต๊ะโค้ด — โปรเจกต์เป็นแถวจริง และแชทที่ไม่ผูกกับโปรเจกต์มีที่อยู่

- **เดิม** คอลัมน์ซ้ายเห็นแชทของโปรเจกต์ที่เปิดอยู่ตัวเดียว อยากรู้ว่ามีงานค้างที่โปรเจกต์อื่นต้องไปสลับที่แถบบนทีละโปรเจกต์ และแชทที่อยู่นอกทุกโปรเจกต์ (งาน เทส การรันทดสอบ) ไม่มีที่ให้แสดงเลย
- **รุ่นนี้** แถว "ไม่ผูกกับโปรเจกต์" คงที่บนหัวคอลัมน์ กดแล้วถอดโฟกัสโปรเจกต์และเห็นแชทของโฟลเดอร์ทำงานจริง (บนเครื่องผู้พัฒนา 23 แชท) · ใต้รายการแชทมีหัว "โปรเจกต์อื่น" พร้อมชื่อและจำนวนแชท 3 แถว ที่เหลือกด "เพิ่มเติม (n)" ไปที่หน้าต่างเลือกโปรเจกต์ · หน้าต่างเลือกเด้งเองเฉพาะตอนที่ยังไม่มีแชทให้ดู
- โฟลเดอร์ทำงานมีแถวในตาราง `projects` ของตัวเองแล้ว (migration 86 เพิ่มคอลัมน์ `kind`) ชื่อโปรเจกต์ของแชทพวกนี้จึงไม่หลุดออกมาเป็น key ดิบ และแถวถูกรีเฟรชพาธจากสถานะสด ไม่ใช่ธง `active` ที่ค้าง
- แถว "ไม่ผูกกับโปรเจกต์" กรองเฉพาะโต๊ะโค้ด (`ListSessionsForDoor`) จึงไม่มีแชทผู้ช่วยปนเข้ามา
- **ไฟล์** `internal/engine/db.go` · `internal/engine/projects.go` · `internal/engine/sessions.go` · `desktop/frontend/src/lib/workbench/Sidebar.svelte` · `desktop/frontend/src/lib/workbench/ProjectPicker.svelte`

## หน้าต่างเครื่อง — VRAM ที่ใช้จริง และแท่งคอร์บอก P/E

- **เดิม** การ์ดจอบอกแค่ขนาด 8.0 GB จากรีจิสทรี ไม่มีค่าใช้จริง และแถบคอร์เป็นแท่งสูงต่ำล้วน ไม่มีตัวเลข ไม่รู้ว่าคอร์ไหน P หรือ E
- **รุ่นนี้** VRAM/โหลด/อุณหภูมิอ่านจาก NVML ของไดรเวอร์ ค่าเดียวกับที่ Task Manager ใช้ (`DXGI.QueryVideoMemoryInfo` ใช้ไม่ได้เพราะตอบเฉพาะหน่วยความจำของโปรเซสนี้) · แคชเฉพาะ handle ไม่แคชตัวเลข — ค่าการ์ดจอจึงขยับตามจริง (วัดได้ 4%→24%→4%→5%→23%→4% ใน 15 วินาที)
- ไดรเวอร์ที่ไม่ตอบค่าไหน (AMD/Intel) แถวนั้นไม่ถูกวาดเป็น 0 การ์ดออนบอร์ดจึงแสดงเฉพาะสิ่งที่มีจริง
- P/E อ่านจาก `PROCESSOR_RELATIONSHIP.EfficiencyClass` ไม่เดาจากรุ่นซีพียู · แท่งคอร์มีเลข % ต่อคอร์ แถวสรุปเฉลี่ย/สูงสุด(พร้อมคอร์ที่หนักสุด)/จำนวนคอร์หนัก และ tooltip "คอร์ N · P|E · XX%"
- **ไฟล์** `internal/machine/` · `desktop/frontend/src/lib/workbench/MachinePane.svelte`

## แท็บเบราว์เซอร์จำรหัสผ่าน

- **เดิม** แท็บเก็บคุกกี้ถาวรอยู่แล้ว แต่ WebView2 ปิด password manager มาแต่ต้น หน้าเข้าสู่ระบบจึงถามรหัสใหม่ทุกครั้งที่คุกกี้หมด โดยไม่มีอะไรกรอกให้
- **รุ่นนี้** เปิด `IsPasswordAutosaveEnabled` ตอนสร้างแท็บทุกแท็บ เก็บเฉพาะรหัสที่พิมพ์ในแท็บลงโปรไฟล์ของแอป ไม่แตะ Chrome และไม่ดึงรหัสจาก Chrome (Chrome 127+ ผูกคุกกี้/รหัสด้วย App-Bound Encryption คัดลอกข้ามแอปไม่ได้) · runtime เก่าที่ไม่มี Settings4 เปิดแท็บต่อได้ ไม่ล้มทั้งแท็บ
- **ไฟล์** `desktop/webview_browser.go`

## แชท — เปิดแชทที่กำลังทำงานแล้วประวัติขึ้น และลบได้พร้อมเหตุผล

- **เดิม** เปิดแชทที่หน้าต่างนี้ไม่เคยเปิดแต่มีเทิร์นทำงานอยู่ จอโล่งจนกว่าเทิร์นจะจบ (owner 13 พ.ย. 2026: "เปิดแชทเดิมบางอันมันก็หายครับ บางครั้ง พอคุยใหม่ก็กลับมา") และกดลบแชทที่กำลังทำงานแล้วเงียบไปเฉย ๆ
- **รุ่นนี้** แถวว่างไม่นับว่า "อยู่บนจอแล้ว" หน้าที่เปิดอ่านมาจึงถูกวาดทันที ส่วนของ live ยังนำ store อยู่เหมือนเดิม · การลบที่ทำไม่ได้บอกเหตุผลเป็นคำ ไม่ใช่ปุ่มที่กดแล้วไม่มีอะไรเกิดขึ้น
- **ไฟล์** `desktop/frontend/src/lib/cockpit.svelte.ts` · `desktop/frontend/src/lib/workbench/Sidebar.svelte` · `desktop/frontend/src/test/openParkedChat.test.ts`

## ทีมและห้องออฟฟิศ — บอกสาเหตุจริง ไม่ใช่ "ไม่มีทีม"

- **เดิม** แชทที่ถือทีมอยู่แต่ทีมยังไม่ถูกแต่งตั้ง ขึ้นข้อความให้ไปเลือกทีมจากเมนูทีม ทั้งที่เลือกอยู่แล้ว · หน้า `/room` ขึ้น "engine ไม่ทำงาน" ทุกครั้งที่คอนโซลรอ world ครบ 8 วินาที ทั้งที่ engine ตอบเมธอดอื่นปกติ
- **รุ่นนี้** `reach()` แยก "อยู่บนทีม / ยังไม่ถูกแต่งตั้ง / ไม่มีทีม" และบอกชื่อทีมพร้อมที่แต่งตั้ง (ตั้งค่า › สิทธิ์มอบงาน) · 503 ของหน้า room แยก `slow` (บอกว่าตอบไม่ทัน พร้อม waitedMs) จาก `noEngine` และหน้า office มีข้อความของตัวเอง
- **ไฟล์** `internal/subagent/` · `internal/bootstrap/` · `desktop/officeserve.go` · `desktop/frontend/src/lib/office/bridge.ts`

## งานหนึ่งงานส่งให้ CLI ภายนอกได้แล้ว พร้อมรหัสความล้มเหลว

- **เดิม** งานที่ต้องใช้ CLI ภายนอก (claude-code, antigravity, opencode, devin) เริ่มได้เฉพาะทาง worker ของทีม และเมื่อล้มเหลวผู้ใช้ได้ข้อความก้อนเดียวที่แยกไม่ออกว่าติดที่โปรแกรม บัญชี หรือคิว
- **รุ่นนี้** งานหนึ่งงานส่งให้ CLI ภายนอกได้จากเส้นทางเดียวกับงานอื่น และรายงานกลับเป็นรหัสความล้มเหลวที่แยกสาเหตุ
- พิสูจน์บนเครื่องจริงด้วยเทสต์สด: antigravity 1.5.7 ทำงานจบใน 11 วินาที (tool 1 ครั้ง) และโหมด accept-edits เขียนไฟล์จบงานได้ (`worker.txt` มีข้อความตามที่สั่ง) · CLI ที่ติดตั้งแต่ยังไม่ล็อกอินถูกรายงานแยกรายตัว ไม่ทำให้ทั้งชุดแดง
- **ไฟล์** `internal/engine/` · `internal/cliagent/`
