# 🪟 Aetox v1.10.34

วันที่ 31 ตุลาคม 2026

**ร้อนแก้สองข้อ — เครื่องที่อัปจากรุ่นก่อนเปิดประวัติแชทได้ตามเดิม และติดตั้งเซิร์ฟเวอร์ MCP จากห้องสมุดได้อีกครั้ง หลังตั้งแต่ v1.10.25 มันล้มแล้ว rollback กลับทุกตัว**

## ฐานข้อมูล: อัปจากรุ่นก่อนแล้วประวัติแชทเปิดได้

- **สาเหตุ** v1.10.33 วางซีดไดรเวอร์ Devin ไว้ที่ migration 75 และ `INSERT` ระบุคอลัมน์ `enabled` ไปด้วย แต่คอลัมน์นั้นเพิ่งเกิดจาก migration 76 ซึ่งรันทีหลัง ฐานข้อมูลที่ยังไม่ถึง 76 จึงไม่มีคอลัมน์นี้ และ migration 75 ล้มทั้งก้อน
- **อาการที่เห็น** เปิดแอปแล้ว `aetox.db` เปิดไม่ได้ทั้งไฟล์ ไม่ใช่แค่เรื่องโมเดล: แถบซ้ายขึ้น «เปิดประวัติแชทไม่ได้ตอนนี้ — แชทเก่ายังอยู่ครบ ไม่ได้หายไปไหน» และในช่องแชทขึ้นกล่อง «โหลดตัวเลือกโมเดลที่บันทึกไว้ไม่ได้» พร้อมค่าที่คงไว้ให้ตรวจ ข้อความหลังบ้านคือ `migration 75 (devin_adapter): table code_adapter_profiles has no column named enabled`
- **ทำไมรุ่นก่อนหน้าไม่เห็น** สโตร์ที่สร้างใหม่เอี่ยมมีคอลัมน์ `enabled` อยู่ในสคีมาอยู่แล้ว ซีดจึงผ่านเฉพาะเส้นทาง «ติดตั้งใหม่» ส่วนเส้นทาง «อัปเกรด» ไม่มีใครเดินในเทสต์
- **ข้อมูลไม่หาย** `migrate()` รันแต่ละขั้นใน transaction แล้ว rollback เมื่อล้ม `user_version` จึงค้างที่ 74 และไม่มีอะไรถูกเขียนทับ อัปรุ่นนี้แล้วมันไล่ 75 → 76 ต่อเอง ประวัติและตัวเลือกโมเดลกลับมาเป็นเดิม
- **แก้ที่ต้นเหตุ** ซีดไม่เอ่ยคอลัมน์ `enabled` อีก ปล่อยให้ค่า default 1 ของสคีมาและของ migration 76 เป็นตัวตั้ง ซึ่งเป็นค่าที่ซีดต้องการอยู่แล้ว (ตัวซีดตอนอ่านรายการครั้งแรกก็ทำแบบนี้)
- **ไม่แตะเลข migration** ไม่ย้าย 76 ขึ้นก่อน 75 และไม่แก้ไฟล์ฐานข้อมูลของผู้ใช้เลย เพราะการสลับลำดับจะทำให้สโตร์ที่เดินไปถึง 75 แล้วเห็นประวัติไม่ตรงกัน สิ่งที่ต้องเปลี่ยนมีแค่คำสั่ง `INSERT` เดียว

## MCP: กดทดสอบการเชื่อมต่อแล้วต่อได้จริง และติดตั้งจากห้องสมุดไม่ล้มทั้งกระดาน

- **สาเหตุ** ปุ่ม «ทดสอบการเชื่อมต่อ» ล้างความล้มเหลวที่ค้างอยู่ด้วยการปิดไคลเอนต์ก่อนต่อใหม่ แต่ตั้งแต่ 28 ต.ค. 2569 การปิดไคลเอนต์กลายเป็นเรื่องถาวร (`mcp: client is closed`) เพื่อไม่ให้เซิร์ฟเวอร์ที่ถูกปิดตอนปิดแอปฟื้นขึ้นมาเอง หลังปิดจึงไม่มีใครต่อได้อีก คำตอบที่ได้ทุกครั้งคือ `mcp: client is closed`
- **ผลที่ตามมาไกลกว่าปุ่มเดียว** การติดตั้งเซิร์ฟเวอร์จากห้องสมุดพิสูจน์ว่าตัวที่เพิ่งติดตั้งต่อได้จริงด้วยการทดสอบเดียวกัน เซิร์ฟเวอร์ทุกตัวจึง «ต่อไม่สำเร็จ» แล้วถูกถอดออกพร้อม rollback ตั้งแต่ v1.10.25 ไม่มีตัวไหนติดตั้งสำเร็จเลย
- **ตอนนี้แยกสองความหมายออกจากกัน** เพิ่ม `Client.Reset()` ที่ทิ้ง session กับความล้มเหลวที่ค้างและยอมให้ต่อใหม่ โดยไม่ทำให้ไคลเอนต์จบ ส่วน `Close()` ยังเป็นตัวจบถาวรเหมือนเดิม ไคลเอนต์ที่ถูกปิดไปแล้วจึงยังตอบ `ErrClosed` และไม่ฟื้นขึ้นมาเอง
- **ปุ่มทดสอบใช้ Reset** กดซ้ำได้ไม่จำกัด ต่อใหม่ได้ทุกครั้ง และยังใช้ `rebuildMCP()` เดิมไม่ได้ overwrite เซิร์ฟเวอร์ตัวอื่น
- **ตราของ earshot** เทสต์ที่กันไม่ให้เซิร์ฟเวอร์บนชั้นขาดตราแดงเพราะ `earshot` ยังไม่มี ที่มา: รีโปของ Leonxlnx/earshot ไม่มีไอคอนหรือโลโก้ในทรี (มีแต่ภาพนิ่งจากหนังกับภาพแคปใต้ `docs/media`) และอวตาร GitHub เป็นของผู้เขียน ไม่ใช่ตราของโปรเจกต์ จึงเขียนไว้ใน `noMark` พร้อมเหตุผลแทนการวาดตราขึ้นเอง

## ความมั่นใจของรุ่น

- เพิ่มเทสต์ `TestUpgradeFrom74SeedsDevinWithoutEnabledColumn` — สร้างสโตร์ที่ `user_version = 74` พร้อมตาราง `code_adapter_profiles` ที่ยังไม่มีคอลัมน์ `enabled` แล้วไล่ `migrate()` จนถึงรุ่นล่าสุด ต้องผ่าน และแถว `claude-code` เดิมต้องอยู่แถวเดียวพร้อม `enabled = 1` หลัง migration 76
- เพิ่มเทสต์ `TestResetReconnectsAndCloseStaysClosed` — ต่อจริงกับเซิร์ฟเวอร์ stdio ตัวจริง แล้ว `Reset()` ต้องต่อใหม่ได้ และ `Reset()` บนไคลเอนต์ที่ `Close()` ไปแล้วต้องตอบ `ErrClosed`
- ห้าเทสต์ติดตั้ง MCP ที่เคยแดงด้วย `mcp: client is closed` ผ่านแล้ว: `TestAnInstallConnectsThenPlacesTheServer`, `TestAnInstallAnnouncesItselfAndItsEnd`, `TestPoisonedDescriptionsAreHeldFromEveryDesk`, `TestAKeyFromTheCardGoesIntoTheEntryWithItsPrefix`, `TestTheChatCardIsTheApprovalAndReportsBack`
- `TestEveryShelfServerHasABrandMarkOrASayWhyNot` ผ่านแล้ว และเทสต์เดิมที่คุมเส้นทางนี้ยังผ่าน: `TestCodeAdapterEnabledMigrationIsGuarded`, `TestCodeAdapterStoreForeignKeysEnabled`, ชุด `TestMigrate…`
