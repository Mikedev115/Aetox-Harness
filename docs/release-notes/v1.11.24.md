# 🪟 Aetox v1.11.24

วันที่ 18 พฤศจิกายน 2026

รุ่นนี้แตะเรื่องที่ใช้ทุกวันสามเรื่อง — สั่งงานทีมได้ในคำสั่งเดียว, ข้อความที่ส่งผิดลบย้อนได้ และการสลับ session เร็วขึ้นหลายเท่า — ที่เหลือคือ MCP ที่ไม่กินโทเคนเกินจำเป็น กับหน้าจอที่อ่านสั้นลง

## มอบงานให้ทีมได้ในคำสั่งเดียว

- **เดิม** การเรียกทีมจากแชทติดสองชั้น: แชทที่ไม่เลือกทีมส่งงานให้ใครไม่ได้เลย และถึงเลือกทีมแล้ว ชื่อทีมก็ยังถูกปฏิเสธให้ไปเรียกทีละคน (เจ้าของเจอทั้งสองชั้นพร้อมกันตอนทดสอบทีมปล่อยรุ่น 18 พ.ย. 2026)
- **ตอนนี้** `task` รับ `assignments` — หลายชิ้นในหนึ่งคำสั่ง แต่ละชิ้นมี agent และ brief ของตัวเอง และได้ id กลับมาครบทุกคน
- **แชทที่ไม่เลือกทีม** ใช้ทีมที่แต่งตั้งให้หัวหน้าไว้ในหน้าตั้งค่า ไม่ใช่สิทธิ์ใหม่ · แชทที่เลือกทีมใช้เฉพาะทีมนั้น · หัวหน้าที่ตอบว่าไม่มีทีมยังถูกปฏิเสธเหมือนเดิม
- **ไม่เปลี่ยน** การแบ่งงานยังเป็นของหัวหน้าหลัก ไม่ยิงบรีฟเดียวกันทั้งทีม (ตามที่ตัดไว้ 7 พ.ย. 2026) — ที่ลดลงคือจำนวนรอบของ tool call
- **ไฟล์** `internal/subagent/team.go` · `internal/subagent/packed_task.go` · `internal/engine/delegate_switch.go`

## ย้อนกลับข้อความที่ส่งผิด

- **เดิม** ส่งแชทผิดแล้วกดหยุด ส่งใหม่ — คำถามที่ผิดยังอยู่ในบทสนทนาและถูกส่งให้โมเดลคิดด้วย
- **ตอนนี้** ปุ่มลูกศรย้อนกลับบนบับเบิลคำถามทุกอันที่บันทึกแล้ว (ไม่จำกัดเฉพาะอันล่าสุด) ลบทั้งคำถามและคำตอบใต้มันออกจากตารางบทสนทนาพร้อมแถวงานที่อ้างถึง แล้วส่งใหม่ได้โดยไม่มีของเก่าปน
- **ไม่แตะไฟล์ในโปรเจกต์** โดยตั้งใจ — การย้อนไฟล์เป็นคนละคำถามและมีปุ่มของตัวเองอยู่แล้ว
- **ยังไม่ทำ** ชื่อแชทในแถบประวัติยังเป็นข้อความที่ถูกลบ (ชื่อถูกตั้งตอนสร้างเซสชัน) และบันทึกการเรียกเครื่องมือของเทิร์นที่ลบยังอยู่ในฐาน
- **ไฟล์** `internal/engine/drop_exchange.go` · `desktop/frontend/src/lib/Chat.svelte`

## สลับ session เร็วขึ้น

- **ต้นเหตุ** การสลับหนึ่งครั้งสแกน `SKILL.md` ทุกไฟล์บนดิสก์ซ้ำหลายสิบรอบ (โหมดอ่าน 148 ms ต่อครั้ง × 17 โปรไฟล์) และโหลด desk ซ้ำต่อโปรไฟล์ทั้งที่ปลายทางเดียวกัน
- **ตอนนี้** ผลสแกนถูกจำไว้และผูกกับสภาพโฟลเดอร์ (ชื่อโฟลเดอร์ + mtime/size ของ `SKILL.md`) — ไม่มีอะไรเปลี่ยนจึงใช้ผลเดิม แก้ไฟล์เพิ่มหรือลบโฟลเดอร์แล้วสแกนใหม่ทันที หน้าจัดการ skill จึงยังเห็นดิสก์ตามจริง · desk โหลดครั้งเดียวต่อชื่อ
- **วัดบนเครื่องเจ้าของด้วย probe ชุดเดิม** `skillsPlacedOn` 148 → 5.8 ms · `mode.parse` 156–167 → 5–9 ms · `mode.Load` 138–218 → 4–7 ms · `mode.List` 617 → 47 ms · `subagent.List` 79–123 → 8–15 ms · `HelpersAwayFrom` 484 → 10 ms · `canDelegate` 90 → 15 ms (ก่อนแก้ `bootstrap.Engine` 508–662 ms ต่อการสลับ มีครั้งหนึ่งพุ่ง 2,451 ms)
- **เทสต์ใหม่** `TestSkillScanNoticesWhatChangedOnDisk` ยืนยันว่าการแก้ไฟล์ เพิ่มโฟลเดอร์ และลบโฟลเดอร์เห็นผลทันที ไม่ค้างค่าเก่า
- **ยังไม่ทำ** ต้นทุนการ spawn MCP ผ่าน npx (3.6–6.4 วิ ตอน cold) เป็นคนละเรื่องและยังไม่ได้แก้
- **ไฟล์** `internal/skill/discovery.go` · `internal/subagent/profile.go`

## สองสวิตช์หน้าจอ — ค่าเริ่มต้นยังเป็นของเดิม

- **แชทกว้างเต็มหน้าต่าง** เพดาน 840px เดิมเขียนซ้ำอยู่ 6 ที่ รวมเป็นตัวแปร `--chat-col` ตัวเดียว เปิดสวิตช์แล้วเป็น 100% และจำค่าไว้ก่อน mount เฟรมแรกจึงไม่กระพริบ
- **เปิดศูนย์บัญชาการตอนเปิดโปรแกรม** สวิตช์ใหม่ใน ตั้งค่า › ศูนย์บัญชาการ เปิดแล้วตอนบูตจะเปิดพอร์ต 127.0.0.1 และเปิดแท็บข้างแชท โดยไม่ย้ายหน้าจอที่ผู้ใช้ยืนอยู่ และไม่ทำใน spectator window ของ dev
- **ข้อความรับประกันเดิม** ที่ว่าแอปไม่เปิดพอร์ตเองตอนเริ่มโปรแกรม ไม่จริงอีกต่อไปเมื่อเปิดสวิตช์ — แก้ข้อความ th/en/zh พร้อมคอมเมนต์ที่เขียนกฎเดิมไว้
- **ไฟล์** `desktop/frontend/src/lib/stores/chatWidth.svelte.ts` · `desktop/frontend/src/lib/officeServer.svelte.ts` · `desktop/mission.go`

## MCP — นิยามไม่ถูกส่งซ้ำเมื่อเซิร์ฟเวอร์โตขึ้น

- **เดิม** เซิร์ฟเวอร์ที่ถูกบันทึกไว้ตอนมี 4 เครื่องมือ วันนี้ให้ 6 — คำตัดสินว่าอยู่บนชั้นวางหรือไม่ยังอ่านจำนวนจากไฟล์ 4 จึงไม่เกินเพดานและถูกส่งนิยามเต็มทุกข้อความ 2.8k โทเคนต่อเซิร์ฟเวอร์ ต่อเทิร์น ของแชทที่ไม่เคยเรียกมัน
- **ตอนนี้** นับเครื่องมือที่ registry ถือจริงต่อเซิร์ฟเวอร์ ไม่ใช่รายชื่อที่บันทึกไว้ — เกินเพดานฝั่งไหนก็กันทั้งเซิร์ฟเวอร์ และผู้เรียกทุกจุด (desk, chair, worker) ส่ง registry ของตัวเอง แผงกับเทิร์นจึงเห็นบล็อกเดียวกัน
- **แก้ควบคู่** `RegisterFor` บันทึกชื่อเครื่องมือกลับก่อนเช็กว่าถืออยู่แล้ว เซิร์ฟเวอร์ที่ถืออยู่จึงไม่ถูกนับซ้ำ และรายชื่อไม่ค้างที่ขนาดวันติดตั้งอีก · ตอนนี้อ่าน `ToolList` ที่แคชไว้ ไม่ต่อเน็ตเพิ่ม
- **ไฟล์** `internal/mcp/shelf.go` · `internal/mcp/manager.go`

## หน้าจอที่อ่านแล้วไม่ต้องเดา

- **เมนู + › MCP** ไม่ขึ้น "0 เครื่องมือ" กับเซิร์ฟเวอร์ที่ยังไม่เคยต่ออีก — เลขที่อ่านว่า 0 แปลว่ายังไม่รู้ ไม่ใช่ไม่มี แถวจึงเงียบจนกว่าจะมีรายการจริงอยู่ข้างหลัง และกางดูเซิร์ฟเวอร์ที่ไม่มีเครื่องมือจริงยังบอกเป็นคำ
- **การ์ดจัดทีม** จาก 2,556 ตัวอักษรเหลือ 1,201 ที่คอลัมน์แชท 840px — บทสรุป 2 บรรทัด "อ่านต่อ" โผล่เฉพาะเมื่อถูกตัดจริง (วัด `scrollHeight` ไม่เดาจากความยาว) ที่นั่งละ 1 บรรทัด และ 6 ข้อตรวจเริ่มแบบพับ ข้อมูลเดิมยังกดดูได้ครบ ไม่ได้หายไป
- **ไฟล์** `desktop/frontend/src/lib/Palette.svelte` · `desktop/frontend/src/lib/OrgCard.svelte`
