## Aetox Mobile 0.2.0 — Android

[**ดาวน์โหลด APK สำหรับ Android**](https://github.com/Mikedev115/Aetox-Harness/releases/download/mobile-v0.3.1/Aetox-Mobile-Android-Test.apk) · [รายละเอียดรุ่นและสิ่งที่ต้องเตรียม](https://github.com/Mikedev115/Aetox-Harness/releases/tag/mobile-v0.3.1)

แอปแชทบนมือถือสำหรับ Aetox บนเครื่องคุณ แชท โมเดล ไฟล์ และเอเจนต์อยู่บน **Windows** ทั้งหมด มือถือเป็นแค่หน้าจอ เลือกโมเดลและระดับความคิดได้ แนบรูปหรือไฟล์ ตอบคำขออนุญาต และเปิดไฟล์ที่ส่งมอบแล้ว **คุยด้วยเสียงได้** ทั้งพูดแล้วพิมพ์ให้ และคุยสดที่ตอบกลับเป็นเสียงทีละประโยค โดยใช้ตัวแปลงเสียงและเสียงอ่านที่ตั้งไว้ใน Aetox บน Windows ใช้ธีมชุดเดียวกับแอปบน Windows รองรับ Android 10 ขึ้นไป provider key ไม่ออกจากเครื่อง PC

> **เป็นรุ่นทดลองที่เซ็นด้วยคีย์ทดสอบ ไม่ได้มาจาก Play Store** ต้องใช้ Aetox บน Windows **รุ่น 1.9.27 ขึ้นไป** (มี **Aetox Link**) และ HTTPS ที่เชื่อถือได้ผ่าน Tailscale ต้องเปิด Windows กับ Aetox ค้างไว้ และยังไม่ได้ลองคุยด้วยเสียง ถ่ายรูป และติดตั้งบนมือถือจริง

**iPhone:** ใช้ Web Clip เพิ่มไอคอนเว็บเต็มจอแบบลบได้ **ไม่ใช่ IPA/native app** โปรไฟล์ต้องสร้างให้ตรง HTTPS ของ Windows แต่ละเครื่อง จึงไม่เผยแพร่โปรไฟล์ส่วนตัวเป็นตัวติดตั้งกลาง

## harness เดียว สองพื้นที่ทำงาน

**Aetox คือ agent harness แบบเนทีฟสำหรับ Windows:** ระบบที่ห่ออยู่รอบโมเดลและให้เครื่องมือ พื้นที่ทำงาน
สิทธิ์ ความจำ และวงจรตรวจสอบ เพื่อให้โมเดลลงมือทำงานจริง ไม่ใช่แค่สร้างคำตอบ

| ถ้าคุณต้องการ | เปิดหน้าใช้งาน | Aetox ทำให้ |
|:---|:---|:---|
| ให้ AI ทำงานกับไฟล์ เว็บ และเอกสารบนเครื่อง | **ผู้ช่วย**<br>ใช้เครื่อง จดจำ ทำเอกสาร | อ่านเขียนไฟล์จริง รันคำสั่งจริง และขับเบราว์เซอร์ที่คุณนั่งดูและแทรกมือได้ อ่านรูป PDF และเสียง แล้วส่งสเปรดชีต เอกสาร และสไลด์ที่เปิดได้จริงกลับมา |
| เขียน แก้ และทดสอบโค้ด | **โค้ด — use case หลัก**<br>อ่านโค้ด สร้างระบบ ดีบัก | โต๊ะที่ผูกกับโปรเจกต์ โหมด Agent ให้เอเจนลงมือ โหมด Editor ให้คุณเขียนเองโดยมี Aetox ช่วย มี language server, Git, เทอร์มินัลจริง และ `aetox` ในเทอร์มินัล |
| แบ่งงานให้หลายบทบาททำพร้อมกัน | **ผู้ช่วยหรือโค้ด → ทีมที่แต่งตั้งไว้** | ตัวหลักส่งงานทั้งก้อนให้ทีม แผนก หรือบริษัท หัวหน้าแบ่งงานให้พนักงาน แล้วคืนชิ้นงานเป็นไฟล์จริง ไม่ต้องเปิดแชทเลขาแยก |

ผู้ช่วยกับโค้ดใช้ harness คีย์ ความจำ การตั้งค่า และสิทธิ์ชุดเดียวกัน สลับที่แถบบนได้ทันที
ตั้งแต่[รุ่น 1.9.21](docs/release-notes/v1.9.21.md) ไม่มีประตูทีมกับแชทเลขาแยกอีกแล้ว ตัวหลักทั้งสองส่งงานให้ทีมเอง
ส่วนห้องและประวัติแชทเดิมของทีมอยู่ฝั่งผู้ช่วย ใช้กับ[ผู้ให้บริการโมเดลภายนอก 28 ราย](#ใช้กับโมเดลไหนได้บ้าง)ทั้งบนคลาวด์และในเครื่อง และมีผู้ให้บริการทดลองในตัว ไม่มี API key ก็เริ่มลองได้
หน้าจอมีภาษาไทยและอังกฤษครบทุกข้อความ โดยไทยเป็นค่าเริ่มต้น
**[ติดตั้ง](#ติดตั้ง)** ได้จาก Microsoft Store · ตัวติดตั้ง · Aetox CLI

## ระบบสำคัญกว่าโมเดล

**โมเดลให้สติปัญญา; Aetox ให้ระบบที่ทำให้โมเดลลงมือได้จริง**

```
                     MODEL        ← สมอง: รู้ว่าควรทำอะไร
                       ↓
                  ┌─────────┐
                  │  AETOX  │     ← ร่างกาย: ตา หู มือ เครื่องมือ สิทธิ์
                  └────┬────┘
              ┌────────┴────────┐
              ↓                 ↓
          Assistant            Code
         ไฟล์ เว็บ เอกสาร       โปรเจกต์ Git
              └────────┬────────┘
                       ↓  มอบงานทั้งก้อน
                 ทีม / แผนก / บริษัท
                   หัวหน้า → พนักงาน
```

> **ดาวเหนือของโปรเจกต์นี้** *อย่าสร้าง AI ที่ตอบได้มากขึ้น จงสร้าง AI ที่ทำได้มากขึ้น*

รูปแบบนี้มีชื่อเรียกว่า **harness** คือโปรแกรมที่ห่อโมเดลไว้ ให้เครื่องมือ ให้วงทำงาน และให้ที่ลงมือ
โมเดลคือเครื่องยนต์ harness คือตัวรถ โมเดลเดียวกันจึงกลายเป็นคนละผลิตภัณฑ์ได้ในคนละแอป
และคะแนนที่ประกาศกันเป็นของโมเดลกับ harness พร้อมกัน ไม่ใช่ของโมเดลลำพัง

ความสามารถหลายอย่างที่คนมักคิดว่าต้องมาจากโมเดลตัวใหญ่ ใน Aetox เป็นของระบบ:

1. **โมเดลตาบอดขับเบราว์เซอร์ได้** — ระบบติดหมายเลขให้ทุกองค์ประกอบบนหน้าเว็บ โมเดลที่ไม่มี vision
   จึงคลิกได้ถูกปุ่มโดยไม่ต้องเดาพิกัด → [ประตูผู้ช่วย](#ประตูผู้ช่วย)
2. **โมเดลตาบอดอ่านรูปได้ โมเดลที่ฟังไม่ได้ถอดเสียงได้ โมเดลที่ตอบได้แค่ข้อความส่งไฟล์จริงได้** — OCR ภาษาไทย
   และอังกฤษ การถอดเสียงแบบออฟไลน์ และการสร้าง `.xlsx` `.docx` `.pptx` เด็ค และวิดีโอ เป็นของแอป → [ประตูผู้ช่วย](#ประตูผู้ช่วย)
3. **โมเดลเล็กในเครื่องทำงานใหญ่ได้** — โมเดล 9B/35B บน LM Studio หรือ Ollama ได้เครื่องมือชุดเดียวกับโมเดลตัวใหญ่
   และข้อมูลไม่ออกจากเครื่องสักไบต์ → [ใช้กับโมเดลไหนได้บ้าง](#ใช้กับโมเดลไหนได้บ้าง)
4. **โมเดลเดียวกัน ผลไม่เท่ากัน** — บน GPT-6 Luna (`gpt-6-luna` ผ่านบัญชี ChatGPT (Codex) เดียวกันทุกตัว) โค้ดที่ผ่านเทสต์ความปลอดภัย (CWEval func-sec@1)
   ของ Aetox คือ 91.1% · OpenCode 66.7% · Codex CLI 66.7% · omp 68.9% · pi 64.4% จาก 527 รันที่ตัดสินด้วยเทสต์ที่ซ่อนไว้ (รุ่น 1.9.27)
   ส่วนที่นำมาจากสกิลความปลอดภัยที่ติดมากับตัว ปิดสกิลนั้นแล้ว Aetox อยู่ในช่วงเดียวกับตัวอื่น
   วิธีวัดและจุดที่ Aetox แพ้อยู่ใน[ผลวัด](#ผลวัด)
5. **เครื่องมือมากไม่ได้แปลว่าบริบทเต็ม** — เซิร์ฟเวอร์ MCP ที่มี 212 เครื่องมือใช้ดัชนีเพียง 135 โทเคน
   และโหลดรายละเอียดเมื่อใช้จริง → [ระบบทำงานอย่างไร](#ระบบทำงานอย่างไร)
6. **องค์กรที่ระบบคุม ไม่ใช่พรอมต์ขอร้อง** — ข้อความของคุณถึงหัวหน้าทุกชั้นตามตัวอักษร รอบที่ส่งงานกลับถูกนับโดยระบบ
   และหัวหน้าไม่ถือช่องรัน งานจึงแจกได้หลายชั้นพร้อมกันโดยไม่ค้าง → [ทีม](#ทีมผ่านผู้ช่วยและโค้ด)

ตัวแอปคือสองไฟล์ที่มีทุกอย่างอยู่ในตัว — `aetox.exe` คือหน้าต่าง และ `aetox-engine.exe` คือเครื่องยนต์ที่คิดและลงมือ
ไม่ต้องลง runtime ไม่มี `node_modules` ไม่มี Chromium ห่อมาด้วย และเพราะเครื่องยนต์เป็น process ของตัวเอง
มันจึงย้ายไปรันบนเครื่อง Linux อื่นได้: เพิ่มเครื่องที่ ตั้งค่า › เครื่องระยะไกล แล้วกดเชื่อมต่อ แอปส่งเครื่องยนต์ไปทาง `ssh`
ของคุณเอง แชท ไฟล์ เทอร์มินัล และ Git ที่เห็นคือของเครื่องนั้น ส่วนคีย์ผู้ให้บริการไม่ออกจากเครื่องที่หน้าต่างรันอยู่
เพราะเครื่องยนต์ขอให้หน้าต่างเซ็นทุกคำขอ

## ประตูผู้ช่วย

*ใช้เครื่อง จดจำ ทำเอกสาร* — ผู้ช่วยทำงานกับเครื่องทั้งเครื่องเมื่อไม่ได้เปิดโปรเจกต์ หรือทำงานในโฟลเดอร์โปรเจกต์
บวกโฟลเดอร์ที่คุณเพิ่ม ทุกอย่างเกิดขึ้นบนแผงงานข้างแชทที่มีสี่ห้อง คือ สไลด์ เบราว์เซอร์ ไฟล์ และเทอร์มินัล
เอเจนไม่ได้ทำงานหลังม่านแล้วส่งไฟล์มาตอนจบ มันเปิดห้องแล้วลงมือในห้องนั้น และคุณแทรกมือเข้าไปแก้ได้ทุกเมื่อ
โดยไม่ต้องรอให้จบเทิร์น ฝั่งผู้ช่วยมีไฟล์และเชลล์ จึงทำงานซอฟต์แวร์ได้ด้วย และจะไม่โยนงานคืนเพราะงานนั้นเกี่ยวกับโค้ด

> **สิ่งที่ระบบทำแทนโมเดลในประตูนี้**
> - ติดหมายเลขให้ทุกองค์ประกอบบนหน้าเว็บ โมเดลที่ไม่มี vision จึงคลิกได้ถูกปุ่ม
> - แปลงรูปเป็นข้อความด้วย OCR ภาษาไทยและอังกฤษ และถอดเสียงแบบออฟไลน์บนเครื่อง
> - สร้างไฟล์ `.xlsx` ที่สูตรใช้งานได้ `.docx` `.pptx` เด็คนำเสนอ และวิดีโอ
> - คำนวณตัวเลขในตัวแปล JavaScript ที่ฝังอยู่ในแอป แล้วแสดงสคริปต์ให้คุณตรวจ
> - ค้นบทสนทนาย้อนหลังด้วย SQLite บนเครื่อง โดยไม่ใช้โทเคน
> - ถามคุณก่อนโพสต์ ส่ง หรือแชร์สิ่งใดออกไปภายนอก ในทุกระดับการอนุญาต

**สั่งเป็นงาน ไม่ใช่สั่งเป็นขั้น** งานยาวถูกวางแผนก่อนลงมือ และแผนขึ้นจอเป็นกล่องเดียวที่ติ๊กตามจริงระหว่างทำ

## ประตูโค้ด

*อ่านโค้ด สร้างระบบ ดีบัก* — ประตูที่สองคือโรงช่าง ไม่ใช่แชทที่เปิดโหมดเขียนโค้ดไว้ มันผูกกับโฟลเดอร์โปรเจกต์
ที่คุณเปิด และมีหลักการทำงานของตัวเอง: เทิร์นจบเมื่องานเสร็จ ไม่ใช่เมื่อเขียนแผนเสร็จ "เสร็จ" แปลว่าพิสูจน์ด้วย
การรันจริง ของใหม่ต้องมีเทสต์อยู่ในชุดเทสต์ของโปรเจกต์ และหลังเทสต์เฉพาะจุดต้องรันการตรวจเต็มของโปรเจกต์อีกรอบ

> **สิ่งที่ระบบทำแทนโมเดลในประตูนี้**
> - ถาม language server ว่าตัวระบุนั้นประกาศที่ไหน ถูกเรียกจากที่ใด และการแก้จะกระทบส่วนใด
> - โหลดหน้า `.html` ที่เพิ่งเขียนบนจอคอมพิวเตอร์และมือถือ ทั้งโหมดสว่างและมืด แล้วรายงานจุดที่ต้องแก้
> - คืนผลของคำสั่งที่ไม่มีความเคลื่อนไหวเกิน 2 นาทีให้โมเดลทันที แทนการรอจนครบ timeout
> - ส่งคำตอบที่ระบุเองว่างานยังไม่เสร็จกลับไปให้ทำต่อ
> - คงประวัติที่ส่งไปแล้วไว้ไม่ให้เปลี่ยน แคชของผู้ให้บริการจึงใช้ได้ทุกรอบ
> - เก็บสำเนาไฟล์ก่อนแก้ของทุกเทิร์นด้วย shadow-git เพื่อย้อนกลับได้

### สองโหมด: Agent · Editor

สวิตช์บนแถบบนสลับได้ทันที แต่ละโหมดเป็นโต๊ะของตัวเอง มีรายการแชทของตัวเอง และผูกกับโปรเจกต์เดียวกัน

เก็บสวิตช์เป็นแท็บเล็กได้ โดยยังบอกโหมดและสถานะว่ากำลังทำงานหรือรอคุณ หน้า Git มี fetch, pull, push
จำนวนคอมมิตที่นำหน้าและตามหลัง กราฟสาขา และเมนูเปิดหรือสร้าง worktree ดึงลงแบบ fast-forward เป็นค่าเริ่มต้น
เมื่อสาขาแยกทางกันจึงให้เลือก rebase หรือ merge

**Agent — ให้เอเจนลงมือ แล้วคุณดูบนแผงงาน** แชทอยู่ซ้าย แผงงานอยู่ขวา ประกอบด้วยเทอร์มินัล ConPTY จริง
ไม่จำกัดแท็บ เบราว์เซอร์ที่เอเจนขับ ต้นไม้ไฟล์ Git ที่มีไทมไลน์ของคอมมิตในหน้าเดียวกัน และแผนที่โค้ด

<img src="docs/assets/readme-code-20261013.jpg" alt="หน้าโค้ด Aetox โหมด Agent — ตัวอย่างการแก้ไฟล์และรันเทสต์ในเทอร์มินัล" width="100%">

- **หาสาเหตุว่าทำไมเทสต์ไม่นิ่ง** — มัน grep ทั้งรีโป รันชุดเทสต์ในแท็บเทอร์มินัลที่คุณดูอยู่ อ่านจุดที่พัง แล้วแก้ไฟล์
- **รู้ว่าชื่อหนึ่งคืออะไรก่อนจะเชื่อมัน** — `codebase` ถาม language server แทนการค้นแบบข้อความที่ต้องเดา
- **เห็นรูปร่างของรีโปที่คุณไม่ได้เขียน** — แผนที่โค้ดของทั้งต้นไม้ พร้อม `grep` และ `glob` ทั้งต้น
- **เขียนหน้าเว็บแล้วรู้ทันทีว่าพังตรงไหน** — ผลตรวจกลับมาพร้อมผลการเขียน: สคริปต์พัง ตัวอักษรจางกว่าเกณฑ์ AA
  หน้ากว้างเกินจอ โหมดมืดที่พื้นยังสว่าง ตัวไทยที่สระลอยหรือทับบรรทัด และปุ่มเล็กเกินกด
- **อ่าน diff โดยไม่ต้องออกจากบทสนทนา** — กางแถวเครื่องมือแล้วเห็นการเปลี่ยนแปลงเป็น hunk แบบ git

**Editor — คุณเขียนเอง Aetox ช่วย** ไฟล์อยู่กลางจอใน Monaco แผงขวามีเอเจน Explorer Git และชิ้นงาน

- **Ctrl+K ขอแก้ตรงบรรทัด** — พิมพ์สั้น ๆ ใต้บรรทัดที่เลือก คำตอบกลับมาเป็น hunk ให้เก็บหรือคืนทีละก้อน
- **เติมโค้ดจากโมเดลตัวไหนก็ได้** — FIM ของ DeepSeek แบบ OpenAI และ Ollama หรือ chat model ตัวไหนก็ได้
  ตั้งแยกจากโมเดลของแชท
- **Language server อยู่ข้างหลังอีดิเตอร์** — completion, hover, go-to-definition, รายการปัญหา และค้น symbol

- **Git ในอีดิเตอร์** — บรรทัดที่เปลี่ยนใน gutter, blame ที่บรรทัดเคอร์เซอร์, เทียบกับ HEAD ข้างกัน
  และคอมมิตทีละ hunk โดยไม่แตะ index จริงที่เชลล์อาจใช้อยู่
- แบ่งจอสองฝั่ง · รันเทสต์ใต้เคอร์เซอร์ · แทนที่ทั่วโปรเจกต์ · `.editorconfig` · จัดรูปแบบตอนเซฟ ·
  เปิดไฟล์ SQLite เป็นตารางแบบอ่านอย่างเดียว

### งานยาวที่จบได้จริง

งานโค้ดจริงยาวหลายสิบนาที และสิ่งที่ทำให้มันล้มส่วนใหญ่ไม่ใช่โมเดล แต่เป็นสิ่งที่อยู่รอบ ๆ

<details>
<summary>ระบบกันงานยาวไม่ให้ค้างหรือล้มอย่างไร และทำไมงาน GitHub อยู่ที่เอเจน github</summary>

- **คำสั่งที่นิ่งไม่ทำให้เทิร์นค้าง** — "นิ่ง" แปลว่าไม่พิมพ์ ไม่ใช้ CPU และชุดโปรเซสไม่เปลี่ยน คอมไพล์ที่เงียบแต่ยังทำงาน
  จึงไม่ถูกนับว่าค้าง ผลของเชลล์มีเพดาน 30 KB โดยเก็บทั้งหัวและท้าย log ก้อนใหญ่ก้อนเดียวจึงไม่ทำให้ทุกคำขอที่เหลือแพงขึ้น
- **เน็ตหลุดและ 5xx ลองใหม่จริง** — DNS ล้มหรือสายถูกตัดจะลองใหม่ทั้งที่ชั้นการเชื่อมต่อและชั้นเทิร์น
  ส่วน 5xx ถอยแล้วลองใหม่ที่ 2, 5 และ 10 วินาที ไม่จบเทิร์นในเสี้ยววินาที
- **เซสชันยาวจ่ายน้อยลง** — ผลเครื่องมือเป็นข้อความล้วน การอ่านบรรทัดที่ยังอยู่ในบทสนทนาจะได้คำตอบว่าอยู่ตรงไหน
  แทนการส่งซ้ำ และ grep ตัดระหว่างผลลัพธ์ ไม่ตัดกลางก้อน

งาน GitHub ทั้งค้นรีโป อ่าน PR เปิด PR อ่าน CI และคอมเมนต์ ส่งให้เอเจน `github` ที่ถือเครื่องมือชุดนั้น โต๊ะโค้ด
เลิกแบกเครื่องมือ GitHub และบริการที่เชื่อมบัญชีไว้ในทุกคำขอ เพราะใน 30 วันไม่เคยถูกเรียกเลย แต่กินราว 1.4k โทเคน
ทุกรอบ ส่วน merge กับ close จงใจไม่มี การปิดข้อโต้แย้งเป็นคลิกเดียวบนหน้าที่คุณเปิดอยู่แล้ว
โต๊ะนี้จงใจไม่มีตัวเขียนเอกสารหรือสเปรดชีต OCR และตัวอ่าน PDF หรือเสียง เด็ค*เกี่ยวกับ*โค้ดเป็นงานของประตูผู้ช่วย

</details>

### Aetox CLI — โต๊ะโค้ดในเทอร์มินัล

พิมพ์ `aetox` ในโฟลเดอร์ไหนก็ได้เพื่อเปิดโต๊ะโค้ดแบบจอเต็ม ดูเครื่องมือทำงานเรียงขึ้นไปเหนือช่องพิมพ์
ตอบการ์ดขออนุญาตได้ในจอ และพิมพ์แทรกได้ระหว่างที่มันทำงาน

```text
aetox                       จอเต็ม (--plain = ทีละบรรทัด)
aetox chat "งาน"            สั่งครั้งเดียว คำตอบออก stdout สำหรับสคริปต์
aetox login codex           ลงชื่อเข้าใช้ผู้ให้บริการ (codex, copilot, ...)
aetox --whole-machine       เครื่องมือเข้าถึงได้ทั้งเครื่อง ที่เก็บกุญแจยังปิด สำหรับคอนเทนเนอร์หรือ VM ที่ทิ้งได้
aetox --report runs.jsonl   ต่อท้ายหนึ่งบรรทัด JSON ต่อเทิร์น: รอบ โทเคน ค่าใช้จ่าย วินาที เครื่องมือ
```

CLI มี[ตัวติดตั้งของตัวเอง](#ติดตั้ง)แยกจากแอป ถ้าเครื่องมีแอป Aetox อยู่ CLI จะใช้เครื่องยนต์ คีย์ แชท และความจำ
ชุดเดียวกับแอป ถ้าไม่มีก็ใช้เครื่องยนต์ของตัวเอง และบอกเองเมื่อมีรุ่นใหม่ CLI ตัวนี้เองคือตัวที่ใช้วัดผลงานโค้ด

## ทีมผ่านผู้ช่วยและโค้ด

*จัดคน สั่งงาน ดูงานเดิน* — ทีมเป็นความสามารถของตัวหลักทั้งสอง ไม่ใช่ประตูที่สาม บอกผู้ช่วยหรือโค้ดว่าอยากได้ผลอะไร
ตัวหลักลงมือเองได้ ใช้ลูกมือช่วยเฉพาะขั้นได้ หรือส่งงานทั้งก้อนให้ทีม แผนก หรือบริษัทที่แต่งตั้งไว้
หัวหน้าแบ่งงาน ตรวจงานของพนักงาน แล้วส่งผลกลับแชทหลัก ไม่ต้องคุยกับเลขาอีกคน

**จัดทีมครั้งเดียว แล้วส่งงานจากแชท** จัดโครงสร้างที่ **ตั้งค่า → ทีม** และแต่งตั้งผู้รับงานให้ตัวหลักแต่ละคนที่
**ตั้งค่า → ตัวหลัก → ผู้ช่วยหรือโค้ด → มอบงาน** การสร้างทีมกับการแต่งตั้งเป็นคนละเรื่อง ทีมเดียวแต่งตั้งให้ทั้งสองตัวหลักได้

ตั้งแต่[รุ่น 1.9.23](docs/release-notes/v1.9.23.md) สั่งผู้ช่วยให้จัดทีมได้เลย ผู้ช่วยเสนอการ์ดร่าง คุณกด **สร้าง**
แล้วแอปสร้างให้พร้อมปุ่มยกเลิกทั้งชุด ทีมที่สร้างผ่านการ์ดแต่งตั้งให้ผู้ช่วย ส่วนโค้ดต้องแต่งตั้งเพิ่มหากต้องการให้ใช้ทีมเดียวกัน

> **สิ่งที่ระบบทำแทนโมเดลเมื่อต้องมอบงาน**
> - ส่งข้อความของคุณถึงหัวหน้าทุกชั้นตามตัวอักษร ไม่ผ่านการเรียบเรียงใหม่
> - ไม่ให้หัวหน้าถือช่องรันงาน แผนกจึงแจกงานให้สามทีม และบริษัทแจกงานให้สามแผนกพร้อมกันได้
> - นับจำนวนรอบที่หัวหน้าส่งงานกลับให้แก้ แทนการเขียนขอไว้ในพรอมต์
> - ส่งกฎและบริบทของบริษัทกับแผนกไปถึงหัวหน้าตามเส้นทางของงาน ลูกทีมได้รับเฉพาะสิ่งที่ต้องใช้
> - ให้เอเจนแต่ละคนใช้โมเดลของตัวเอง ค่าใช้จ่ายจึงเป็นไปตามงานของแต่ละคน
> - ตรวจโครงสร้างองค์กร เช่น แผนกที่ไม่มีหัวหน้า ทีมที่ไม่เคยถูกใช้ และเอเจนที่ถือเครื่องมือซ้ำกัน

### สามชั้น แต่ละชั้นมีหัวหน้าที่คิดเอง

| ชั้น | ประกอบด้วย | หัวหน้าทำอะไร |
|:---|:---|:---|
| **ทีม** | หัวหน้าทีม + เอเจน | รับงานทั้งก้อน แบ่งเป็นประโยคคน หนึ่งคนหนึ่งชิ้นงานที่ไม่ทับกัน แล้วเก็บผลกลับมาตัดสิน |
| **แผนก** | หัวหน้าแผนก + ทีม | งานกว้างในเรื่องเดียว แจกให้หลายทีมพร้อมกัน ทีมหนึ่งอยู่ได้หลายแผนก |
| **บริษัท** | หัวหน้าบริษัท + แผนก | ภาพใหญ่ทั้งองค์กร แจกให้แผนก หรือจ้างทีมตรงก็ได้ ก่อตั้งได้เมื่อมีแผนกที่มีหัวหน้าครบสามแผนก |

ตัวหลักเลือก**ชั้นต่ำที่สุดที่รับงานนั้นได้** งานชัดของทีมเดียวไปถึงทีมนั้นตรง ๆ งานกว้างขึ้นไปถึงแผนกหรือบริษัท
ไม่มีชั้นไหนบังคับให้ผ่าน เพราะการขึ้นไปสูงกว่าที่งานต้องการเสียหนึ่งรอบโดยไม่ได้อะไรเพิ่ม ลูกทีมได้รับแค่คำสั่ง
ของหัวหน้ากับหน้าที่ของตัวเองในทีม และกฎของทีมถึงทุกคนในทีม

### ดูงานเดินได้ทุกชั้น

- **สั่งจากแชทหลักได้เลย** ผู้ช่วยหรือโค้ดส่งงานให้ทีม แผนก หรือบริษัทที่แต่งตั้งไว้
  ห้องและประวัติแชทเดิมของทีมเปิดได้จากฝั่งผู้ช่วย ไม่ต้องสลับไปประตูที่สาม
- **งานที่มอบเป็นผังเดียวในแชท** หัวหน้าอยู่บน ลูกทีมอยู่ใต้ แต่ละแถวบอกว่ากำลังทำอะไรและมีปุ่มหยุดของตัวเอง
  คำถามของใครก็ขึ้นใต้คนนั้นและตอบได้ตรงนั้น กดแถวแล้วงานเต็มเปิดในแผงขวา
- **ชิ้นงานเป็นไฟล์จริง** อยู่ในโฟลเดอร์ของทีมหรือในโปรเจกต์ที่โฟกัสอยู่ และขึ้นเป็นการ์ดในคำตอบของตัวหลัก
- **ห้องบริษัท** ออฟฟิศ 3D เปิดจากการ์ดบริษัทในห้องทำงาน (หรือศูนย์บัญชาการ) เลือกแมพวิทยาเขตหรือตึกได้ (เครื่องที่ไม่มี WebGL ได้ห้อง 2.5D)
  หุ่นของแต่ละเอเจนนั่งโต๊ะและขยับตามเครื่องมือที่ใช้อยู่ หัวหน้ามีโต๊ะและยศของตัวเอง งานที่เสร็จถูกยกไปส่ง
  เวลาในห้องตามนาฬิกาของคุณ และบอร์ดบอกงานเสร็จวันนี้ · ทำงานอยู่ · รอคุณ
- **ห้องทำงาน** บันทึกสายงานไว้ได้ แต่ละขั้นบอกว่าทีมไหนรับชิ้นไหน กดเริ่มแล้วสายเดินทีละขั้น
  ขั้นไหนหยุดถาม คำตอบไปถึงขั้นนั้นแล้วเดินต่อ
- **คอนโซลบนเว็บ** หน้า `:8317` บนเครื่องคุณใช้ตั้งค่าทีม แผนก และบริษัทได้ และมีมือถือจำลองที่ส่งคำสั่งให้ผู้ช่วย
  ไม่ใช่หน้าเลขาแยก

### องค์กรคือไฟล์ธรรมดา

ทุกชั้นเป็นมาร์กดาวน์บนดิสก์ จัดการทีม แผนก และบริษัทได้ที่ **ตั้งค่า → ทีม** หน้าภาพรวมองค์กรวาดโครงสร้างเป็นต้นไม้
ตรวจโครงสร้างให้ และสรุปว่าแต่ละทีมใช้ไปเท่าไร

```text
<DataRoot>/teams/<ชื่อ>/TEAM.md                หัวหน้า · ลูกทีม · หน้าที่ของแต่ละคนในทีม · ## กฎทีม
<DataRoot>/departments/<ชื่อ>/DEPARTMENT.md    หัวหน้าแผนก · ทีม · ## บริบทแผนก · ## กฎแผนก
<DataRoot>/companies/<ชื่อ>/COMPANY.md         หัวหน้าบริษัท · แผนก · ## บริบทบริษัท · ## กฎบริษัท
```

แอปตั้ง **ทีมคอนเทนต์** เป็นทีมที่มีหัวหน้า และมีรายชื่อเอเจน **ผู้ช่วยในคอมพิวเตอร์** สำหรับงานค้น เอกสาร สเปรดชีต และวิดีโอ
คุณเก็บ เปลี่ยนชื่อ หรือจัดไฟล์เริ่มต้นเหล่านี้ใหม่ในหน้าตั้งค่าได้ หรือให้ผู้ช่วยร่างทีมที่มีหัวหน้าสำหรับงานของคุณ
รายชื่อพนักงานและหัวหน้าที่เลือกได้อยู่ในหน้าบุคลากร ทีมที่มีหัวหน้าจะส่งงานถึงได้ก็ต่อเมื่อแต่งตั้งให้ตัวหลักนั้นแล้ว

### เอเจนหนึ่งคนคือหนึ่งโฟลเดอร์

การจ้างคนใหม่คือการวางโฟลเดอร์ลงใน `<DataRoot>/agents/` ไม่ต้องรอรุ่นใหม่ ไม่ต้องมี plugin API และไม่ต้องรีสตาร์ต
โฟลเดอร์คือตัวตนทั้งหมดของเอเจน: `AGENT.md` (เป็นใคร หยิบเครื่องมือแคบลงแค่ไหน ใช้โมเดลตัวไหน และ `role: head`
ถ้าเป็นหัวหน้า) `MEMORY.md` (สิ่งที่เรียนรู้มา) `STARTERS.md` (แชทเปล่ากับเขาเปิดอย่างไร) และโฟลเดอร์ `skills/`
ส่วนตัวที่เอเจนคนอื่นมองไม่เห็น

โฟลเดอร์นี้คือจุดที่ผู้ช่วยตัวเดียวกับองค์กรแยกทางกัน เอเจนแต่ละคนใช้**โมเดลของตัวเองที่ผู้ให้บริการของตัวเอง**
คนที่ต้องเปิดหน้าราคายี่สิบหน้าใช้โมเดลราคาถูกได้ ส่วนคนที่ต้องชั่งน้ำหนักสิ่งที่หามาใช้ตัวที่แข็งกว่า ค่าใช้จ่ายจึงเป็นไป
ตามงาน ไม่ใช่ตามงานที่ยากที่สุด และแต่ละคนมี**ความจำของตัวเอง** สิ่งที่เอเจนหาข้อมูลเรียนรู้เกี่ยวกับแหล่งหนึ่ง
จึงไม่ไปปนกับวิจารณญาณเรื่องสัญญาของเอเจนเอกสาร

คุณคุยกับพนักงานตรง ๆ ในห้องพนักงานเฉพาะทาง หรือเลือกจากเมนู `@` ในแชทได้ด้วย
การแต่งตั้งอยู่ที่ **ตั้งค่า → ตัวหลัก → มอบงาน** ผู้ช่วยกับโค้ดมีทีมที่แต่งตั้งและลูกมือของตัวเองแยกกัน
นอกจากนี้ยังมี **ลูกมือ** สองตัว (`explore` `general`) ซึ่งเป็นผู้ช่วยภายในแบบชุดตายตัวที่เพิ่มไม่ได้โดยตั้งใจ
แต่ปรับโมเดล ผู้ให้บริการ คำสั่ง เพดานจำนวนขั้น และรูปลักษณ์ได้

**ผู้ให้บริการภายนอก 28 ราย และหน้าต่างแสดงครบทุกราย** — OpenAI · OpenAI-compatible (ปลายทางของคุณเอง) ·

ChatGPT (Codex) · GitHub Copilot และ OpenRouter ใช้การลงชื่อเข้าใช้ ที่เหลือใช้ API key หรือที่อยู่เซิร์ฟเวอร์ในเครื่อง
ปลายทางที่เพิ่มเองเลือกรูปแบบ API ได้ (openai · anthropic · responses)

โมเดลในเครื่องได้รับการปฏิบัติเท่ากับโมเดลบนคลาวด์ Aetox ถาม LM Studio และ Ollama ว่าโมเดลไหน*โหลดอยู่*
สตรีมทั้งคำตอบและความคิด เรียกเครื่องมือได้จริง และนับโทเคนเข้าสถิติชุดเดียวกัน คุณสลับผู้ให้บริการหรือโมเดล
กลางบทสนทนาได้ และบริบทตามไปครบ ทั้งการเรียกเครื่องมือ ผลลัพธ์ และบทสรุปที่ถูกบีบอัด Aetox จะไม่แอบเปลี่ยน
เส้นทางเทิร์นของคุณไปหาผู้ให้บริการรายอื่นที่คุณจ่ายเงินอยู่ รายชื่อโมเดล รุ่นของ API และระดับความคิดถามจาก
ผู้ให้บริการตอนรัน ไม่ได้เขียนตายไว้ในโค้ด โมเดลใหม่จึงขึ้นรายการเองโดยไม่ต้องรอ Aetox รุ่นใหม่

หน้าตั้งค่ามีสวิตช์เปิดปิดโมเดลรายตัว ปิดแล้วซ่อนจากเมนูเลือก แต่ไม่เปลี่ยนแชทที่ใช้โมเดลนั้นอยู่ ดาวคือรายการโปรด
ค้นจากรายชื่อทั้งหมดโดยวาดหน้าต่างของแถวเฉพาะส่วน ที่ **บุคลากร** รวมพนักงานและลูกมือ ค้นหาและกรองยศหรือแหล่งที่มาได้
ภาพรวมแสดงผู้ที่ตั้งโมเดลแยก แต่ละแชทจำโมเดลและระดับคิดของตัวเอง ส่วน 9Router, LM Studio และ Ollama มีการ์ดตั้งค่าที่บอกสถานะติดตั้ง เซิร์ฟเวอร์ และโมเดลหรือคีย์

## ความปลอดภัยและข้อมูลของคุณ

- **ข้อมูลอยู่บนเครื่องคุณ** — ประวัติแชท ผลงาน และข้อมูลในเบราว์เซอร์อยู่บนดิสก์ของคุณ ไม่มีเซิร์ฟเวอร์ของเราคั่นกลาง
  และไม่มี analytics การใช้ผู้ให้บริการบนคลาวด์แปลว่าผู้ให้บริการเห็นเท่าที่ API ของเขาเห็นตามปกติ
- **คีย์และความลับ** — คีย์ถูกห่อด้วย DPAPI ผูกกับบัญชี Windows ของคุณ และความลับถูกกรองออกก่อนลงบันทึก
  และก่อนผลเครื่องมือถึงโมเดล
- **สิทธิ์สามระดับ** — ถามก่อน · เฉพาะที่เสี่ยง · เข้าถึงเต็มที่ และมีสองเรื่องที่ถามในทุกระดับ คือการเผยแพร่ออกไป
  ภายนอก กับการปิดโปรแกรมตามชื่อ
- **ไฟล์ลับถูกปฏิเสธในทุกโต๊ะ** — `.ssh` `.aws` ที่เก็บรหัสผ่านของ Windows โปรไฟล์เบราว์เซอร์ และไฟล์กุญแจของ
  Aetox เอง เครื่องมือไหนก็เปิดไม่ได้

<summary>รายละเอียด: โต๊ะ พื้นที่ทำงาน สิทธิ์ ตัวตรวจเชลล์ และข้อมูลที่เก็บ</summary>

**โต๊ะ (desk)** คือเพดานเครื่องมือของเซสชัน ไม่ใช่จำนวนทางเข้าบนแถบบน โต๊ะที่มากับแอปมีห้าโต๊ะ —
`assistant` (ผู้ช่วย) `coding` (โค้ด โหมด Agent) `editor` (โค้ด โหมด Editor) `specialized` (เอเจนเฉพาะทาง)
และ `secretary` (ผู้ช่วยตอนไม่มีคนเฝ้า สำหรับงานตั้งเวลา ตัวเฝ้างาน และคำสั่งจากเว็บ ไม่ใช่ประตูเลขาแยก)
โต๊ะของแชทถูกกำหนดตั้งแต่เปิด
และไม่เปลี่ยนกลางทาง เซิร์ฟเวอร์ MCP กับการเชื่อมต่อภายนอกถูกวางเป็นรายโต๊ะและรายเอเจน เครื่องมือที่ติดตั้งมาเพื่อ
งานแบบหนึ่งจึงไม่ไปโผล่ในงานอีกแบบ ไม่ใช่ซ่อนจากโมเดล แต่ไม่มีอยู่จริงในแชทนั้น

**พื้นที่ทำงาน** เมื่อเปิดโปรเจกต์ พื้นที่ทำงานคือโฟลเดอร์นั้นบวกโฟลเดอร์ที่คุณเพิ่ม ซึ่งได้สิทธิ์อ่านเขียนเท่ากับราก
โปรเจกต์ เมื่อไม่ได้เปิดโปรเจกต์ พื้นที่ทำงานคือทั้งเครื่อง และไฟล์ที่เขียนจะลงใน `output/<session>` ฟังก์ชันเดียว
เป็นคนตัดสิน path ทุกเส้น รวมถึง symlink และตั้งใจไม่ให้มีด่านที่สองที่ไหนอีก

**การขออนุญาต** มีประตูเดียวที่ทุกการเรียกเครื่องมือเดินผ่าน ทั้งเครื่องมือในตัว เชลล์ และ MCP

| ระดับ | ถามอะไรบ้าง |
|:---|:---|
| **ถามก่อน** | ทุกอย่างที่ไม่ใช่การอ่านเฉย ๆ ในพื้นที่ทำงาน |
| **เฉพาะที่เสี่ยง** | การลบ การแก้ `git` เชลล์ อะไรก็ตามที่แตะ path นอกพื้นที่ทำงาน การลบของบนบริการภายนอก และเครื่องมือที่ไม่ได้ประกาศว่าทำอะไร |
| **เข้าถึงเต็มที่** | ไม่ถาม ยกเว้นสองเรื่องข้างล่าง |

สองเรื่องที่ถามทุกระดับรวมถึงเข้าถึงเต็มที่: **การเผยแพร่ออกไปภายนอก** (โพสต์ แชร์ ส่ง ตอบกลับ ทั้งจากเบราว์เซอร์
และจากบัญชีที่เชื่อม) และ**การปิดโปรแกรมตามชื่อ** ซึ่งจะปิดโปรแกรมอื่นที่ชื่อตรงกันไปด้วย เซสชันปิดสิ่งที่ตัวเองเปิด
ผ่าน handle ของมันเองเท่านั้น เครื่องมือจาก MCP ถูกตัดสินจากสิ่งที่เซิร์ฟเวอร์ประกาศไว้ (อ่านอย่างเดียว · เพิ่ม ·
อาจลบ) ไม่ใช่จากชื่อที่ผู้เขียนเซิร์ฟเวอร์ตั้ง ตัวที่ไม่ประกาศอะไรเลยถือว่า "ไม่รู้" ไม่ใช่ "ไม่อันตราย"

**ตัวตรวจคำสั่งเชลล์** ตรวจ path จริง ไม่ใช่จับรูปแบบตัวอักษร และอ่านตามไวยากรณ์ของเชลล์นั้น path ที่ซ่อนอยู่ใน
เครื่องหมายคำพูด หลังแฟล็ก หลังการเปลี่ยนทางออก หรือหลัง `%VAR%` / `$VAR` / `~` ยังถูกคลี่ออกมาตรวจ backtick
ของ PowerShell เป็นตัว escape และ heredoc ที่ส่งเข้าโปรแกรมเป็นข้อมูล ส่วนสิ่งที่อ่านไม่ออก ได้แก่ `$(...)` `${...}`
backtick ของ POSIX shell `-EncodedCommand` `FromBase64String` และ `Invoke-Expression` ถูกปฏิเสธแทนการเดา
ทุกคำสั่งที่รันถูกต่อท้ายลงบันทึกตรวจสอบสิทธิ์ 0600

**ปฏิเสธกับทุกเครื่องมือไฟล์ในทุกโต๊ะ:** `.ssh` `.aws` `.gnupg` `.azure` `.kube` `.netrc` `.git-credentials`
`.config/gh` `.aetox` ที่เก็บ Credentials และ Protect ของ Windows โปรไฟล์ Chrome / Edge / Firefox / Brave
และไฟล์ของ Aetox เอง ได้แก่ `credentials.json` `oauth.json` `account.json` `mcp-servers.json` `screen.json`
กับโปรไฟล์เบราว์เซอร์ ตอนเลือกโฟลเดอร์ก็ปฏิเสธ
เหมือนกัน จึงพังตั้งแต่หน้าประตู ไม่ใช่ไปโผล่เป็นข้อผิดพลาดงง ๆ ทีหลัง `--whole-machine` ของ CLI เปิดกำแพงโปรเจกต์
แต่ไม่เปิดรายการนี้ ยกเว้นข้อเดียวเพื่อการ deploy: กุญแจใน `.ssh` ที่ส่งให้ `ssh` / `scp` / `sftp` ผ่าน `-i` หรือ
`-o IdentityFile=` ส่งให้ `ssh-add` หรือส่งแบบเดียวกันใน `rsync -e` `GIT_SSH_COMMAND` และ `core.sshCommand` ไปถึงโปรแกรมได้
เพราะ ssh ใช้กุญแจโดยไม่พิมพ์เนื้อกุญแจออกมา ส่วนการอ่าน การคัดลอก การใช้ `-F` กับกุญแจ หรือการเขียนพาธเดียวกันไว้ที่อื่น
ในบรรทัดเดียวกันยังถูกปฏิเสธ และคำสั่งในเครื่องที่การตั้งค่าเหล่านี้และตัวเลือกของ ssh สั่งรัน (`ProxyCommand` `LocalCommand`
`KnownHostsCommand` โดยอ่าน `%d` เป็นโฟลเดอร์บ้าน) ถูกตรวจเหมือนคำสั่งอื่นทุกคำสั่ง คำสั่งที่ล็อกอินไปเครื่องอื่น
(ssh scp sftp rsync ไปเครื่องปลายทาง autossh mosh ssh-copy-id sshfs และ `git push` ผ่าน ssh) ถามก่อนในทุกโหมดรวมถึงเต็มสิทธิ์ บนการ์ดกดไว้ใจเครื่องนั้นตลอดได้ และดูหรือถอน

### รุ่นก่อน — v1.9.23

[รุ่น 1.9.23](docs/release-notes/v1.9.23.md) วันที่ 13 ต.ค. 2026 เพิ่ม:

- **แชทใหม่ที่เอเจนเสนอเป็นการ์ด** เจองานที่ควรแยกแชท เอเจนขึ้นการ์ดบอกโต๊ะและโปรเจกต์ที่จะเปิด กด เริ่ม แล้วแชทใหม่เปิดคู่ข้างแชทเดิม

### รุ่นก่อน — v1.9.22

[รุ่น 1.9.22](docs/release-notes/v1.9.22.md) วันที่ 12 ต.ค. 2026 เพิ่ม:

- **สลับแชทเร็วขึ้น** เก็บ engine ของ 3 แชทล่าสุดไว้ และแถบซ้ายไม่อ่านรูปปกโปรเจกต์ทุกครั้งที่สลับ (2.4 MB เหลือ 71–309 KB)

- **เครื่องมือค้นและแก้ไฟล์ไม่ค้างแล้ว** แก้ไฟล์พร้อมกันไม่แย่งคำตอบ LSP กัน (24 edits จาก 93.5 วิ เหลือ 7.6 วิ) `grep` ไม่หลุดเข้า `output/` และ `trace` ครั้งแรกสร้าง index 7 วิ แทน 29 วิ

### รุ่นก่อน — v1.9.21

[รุ่น 1.9.21](docs/release-notes/v1.9.21.md) วันที่ 12 ต.ค. 2026 เพิ่ม:

- **ห้องตัดที่มีประวัติและงานเบื้องหลัง** แก้ไขแล้วรีสตาร์ตก็ยัง undo/redo ได้ งานยาวรันเบื้องหลังพร้อมความคืบหน้าและยกเลิกได้ และไทม์ไลน์มีมาร์กเกอร์ ripple cut เวฟฟอร์มและพร็อกซี
- **ปฏิทิน บอร์ดไอเดีย และรออ่าน ในวันของผู้ช่วย** ปฏิทินวัน สัปดาห์ เดือน ปี พร้อม block และ deadline บอร์ดไอเดียแบบ Notion และลิงก์ที่ผู้ช่วยอ่านแล้วสรุปให้ก่อน
- **ทีมที่ไม่ต้องผ่านเลขาแยก** ผู้ช่วยและโค้ดส่งงานให้ทีมที่แต่งตั้งไว้ได้เอง ห้องและประวัติแชทเดิมของประตูทีมย้ายมาอยู่ฝั่งผู้ช่วย
- **เอเจนเห็นโต๊ะที่คุณดูอยู่ และ dropdown ตัวเดียวทั้งแอป** เอเจนรู้ว่าคุณอยู่หน้าไหน การรันเครื่องมือแสดงตามลำดับจริงและบอกงานที่รอคิว และทุกตัวเลือกใช้คอมโพเนนต์เดียวกัน

### รุ่นก่อน — v1.9.20

[รุ่น 1.9.20](docs/release-notes/v1.9.20.md) วันที่ 10 ต.ค. 2026 เพิ่ม:

- **วิดีโอคนพูด แผนที่สมองสดและหน้าเกี่ยวกับคุณแบ่งหน้า** ภาพบุคคลกับเสียงกลายเป็นวิดีโอ แผนที่ขยายออกและตามเมาส์ และโฟลเดอร์ความรู้ที่เชื่อมเป็นต้นไม้ไฟล์เดียว

### รุ่นก่อน — v1.9.19

[รุ่น 1.9.19](docs/release-notes/v1.9.19.md) วันที่ 8 ต.ค. 2026 เพิ่ม:

### รุ่นก่อน — v1.9.17

[รุ่น 1.9.17](docs/release-notes/v1.9.17.md) วันที่ 7 ต.ค. 2026 เพิ่ม:

- **คลังสมองส่วนตัวในหน้าเกี่ยวกับคุณ** บันทึกงานรายวันแยกตามโต๊ะ สิ่งที่เรียนรู้เกี่ยวกับการทำงาน ตัวกรองและแผนที่เชื่อมโต๊ะกับโปรเจกต์ พร้อมอ่านคลังความรู้จากโฟลเดอร์ที่คุณเลือกโดยไม่เขียนทับ
- **ศูนย์บัญชาการผ่าน Cloudflare Tunnel** เข้าใช้งานจากนอกเครือข่ายบ้านผ่านโดเมนที่ตั้งไว้ ทุกเครื่องยังต้องจับคู่ก่อนใช้งาน
- **สื่อสารระหว่างทำงานชัดขึ้น** มีคำเตือนเมื่อทำงานเงียบ และตัวกันใน runtime ที่พักกลุ่มเครื่องมือซึ่งยังไม่เริ่มเมื่อคุณพิมพ์แทรก เพื่อให้เอเจนตอบก่อนทำต่อ

  พร้อมสูตรออกแบบกระจกและคลังคอมโพเนนต์ที่มากับแอป
