## เริ่มใช้

1. **ติดตั้ง** จาก Microsoft Store หรือตัวติดตั้งข้างบน เลือกช่องทางเดียวแล้วใช้ช่องทางนั้นต่อไป เพราะตัวจาก Store
   กับตัวจากตัวติดตั้งเก็บการตั้งค่า แชท และคีย์แยกกัน
2. **ต่อโมเดล** เปิด **ตั้งค่า › โมเดล** แล้วล็อกอินด้วย ChatGPT, GitHub Copilot หรือ OpenRouter หรือใส่คีย์
   หรือชี้ไปที่ LM Studio หรือ Ollama ในเครื่องของคุณ
3. **สั่งงาน** เลือก **ผู้ช่วย** สำหรับไฟล์ เอกสาร และเว็บ หรือ **โค้ด** สำหรับโฟลเดอร์โปรเจกต์ แล้วบอกว่าอยากได้อะไร

## สั่งงานเดียว มันคิดหลายขั้นเอง

จุดขายไม่ใช่ "ทำได้หลายอย่าง" แต่คือ **คุณสั่งเป็นงานหนึ่งงาน แล้วมันแยกเองว่าต้องทำอะไรก่อนหลัง**
ด้วยเครื่องมือจริงของทุกขั้น และตรวจผลของแต่ละขั้นก่อนไปต่อ — คุณเห็นทุกขั้นและหยุดได้ทุกเมื่อ

| ขั้น | สิ่งที่มันทำเอง |
|:---|:---|
| **1. อ่านก่อน** | เปิดโปรเจกต์ อ่าน README สคีมาฐานข้อมูล วิธีรันของโปรเจกต์ และเอกสารที่เกี่ยวข้อง |
| **2. วางแผน** | แยกงานเป็นข้อ บอกว่าข้อไหนต้องรอข้อไหน และอะไรที่ยังไม่รู้ |
| **3. ลงมือทีละขั้น** | แก้ไฟล์ เขียน migration รันคำสั่ง เรียก MCP server ที่คุณต่อไว้ ขับเบราว์เซอร์จริง |
| **4. ตรวจของตัวเอง** | รันเทสต์ อ่าน error จาก language server เปิดหน้าเว็บที่เพิ่งสร้างแล้วคลิกดูเอง |
| **5. บอกตามจริง** | อะไรเสร็จ อะไรยังไม่ผ่าน และอะไรที่มันตรวจไม่ได้ |

**ตัวอย่างงานที่ต้องใช้หลายขั้นจริง ๆ**

- *"สร้างระบบจองให้ร้านผม"* — อ่านโจทย์เป็นสเปก → ออกแบบฐานข้อมูล → เขียน migration →
  สร้างหน้าจอ → รันเทสต์ → เปิดเบราว์เซอร์ลองจองเอง → รายงานว่าข้อไหนยังไม่ครบ
- *"หาข้อมูลคู่แข่ง 5 ราย แล้วทำตารางเทียบ"* — ขับเบราว์เซอร์เปิดหลายแท็บ อ่านทีละหน้า → รวบรวม → เขียนเป็น `.xlsx`
- *"อัดประชุมไว้ 2 ชั่วโมง สรุปให้หน่อย"* — ถอดเสียง → แยกหัวข้อกับมติ พร้อมนาทีที่พูด → ดึงงานและชื่อคนรับ → เขียนเป็นไฟล์
- *"แก้บั๊กนี้"* — อ่าน stack trace → หาไฟล์ที่เกี่ยว → แก้ → รันเทสต์ของโปรเจกต์ → ถ้าไม่ผ่านก็วนกลับ

**งานใหญ่เกินคนเดียว** — ส่งต่อให้ทีมแล้วกลับมาพร้อมชุดที่เสร็จ พร้อมบอกว่าใครทำอะไร

## ทำไมโมเดลเดิมทำได้ดีขึ้น

โมเดลคิด ส่วนที่เหลือสภาพแวดล้อมทำ และทำด้วยของจริง ไม่ใช่ของจำลอง

- **มือ** เบราว์เซอร์จริงที่มีแท็บและโปรไฟล์ของมันเอง เทอร์มินัลจริง ตัวเขียนไฟล์ `.docx` `.xlsx` `.pptx` จริง
  และห้องตัดต่อจริง มันไม่ได้อธิบายสเปรดชีตให้คุณฟัง — มันเขียนไฟล์แล้วเปิดขึ้นมาดูเอง
- **ตา** OCR และตัวอ่านเอกสารที่อ่านหน้าสแกนจริง แทนการขอให้ vision model เดา และอ่านหน้าที่จับภาพไว้จริง
  แทนการจำเอา
- **ความรู้ที่โมเดลไม่มี** สกิลเก็บไว้: ขนาดจอ 1280×720 ของห้องนำเสนอ วิธีที่คนร้ายเจาะการเช็ค path
  การปัดเศษในใบกำกับภาษีไทย — และวิธีทำงานของคุณเอง
- **ตรวจก่อนส่ง** รันเทสต์ เปิดไฟล์ที่ทำเสร็จดูเอง และบอกตรง ๆ ว่าส่วนไหนยังพิสูจน์ไม่ได้

## มันเรียนวิธีทำงานของคุณ

สภาพแวดล้อมที่เริ่มจากศูนย์ทุกเช้า คือเครื่องมือที่คุณต้องเช่าใช้ใหม่ทุกวัน Aetox เก็บสิ่งที่รู้เกี่ยวกับคุณไว้

- **วิธีทำงานจะถูกนับก็ต่อเมื่อมันเกิดซ้ำ** วันเดียวคือเหตุการณ์ ส่วนสามวันที่ต่างกันคือวิธีทำงานของคุณ
  มันไม่ตัดสินจากบทสนทนาเดียวว่าคุณเป็นคนแบบนี้
- **คุณเป็นคนบอกว่าใช่** ข้อเสนอที่มาจากนอกเทิร์นจะรอคุณเสมอ และทุกบรรทัดที่ถูกเก็บ ย้อนกลับได้จากใต้คำตอบที่เพิ่มมัน
- **แยกเป็นส่วนตามคนที่ต้องอ่าน — แต่การทำงานจริงค้นถึงกันได้หมด** ชั้นสถาปัตยกรรมแบ่งว่าใครอ่านอะไร
  โปรไฟล์ของคุณไปกับทุกงาน สิ่งที่รู้เกี่ยวกับเครื่องนี้ไปกับโต๊ะที่ต้องใช้ วิธีทำงานของแต่ละห้องอยู่กับห้องนั้น
  และของแต่ละ worker อยู่กับ worker ตัวนั้น — แต่ตอนทำงาน มันค้นย้อนได้ทั้งประวัติ เปิดโน้ตของวันไหนก็ได้
  และดึงเอกสารในเครื่องคุณมาใช้ได้ จึงไม่ต้องแบกทุกอย่างไว้ในทุกคำขอ แต่ก็ไม่ลืมอะไร
- **มันคือโฟลเดอร์ไฟล์ `.md` ธรรมดา ไม่ใช่กล่องดำ** โปรไฟล์ของคุณ สิ่งที่รู้เกี่ยวกับเครื่องนี้ โน้ตของแต่ละห้อง
  โน้ตหนึ่งใบต่อหนึ่งวันทำงาน และเส้นทางที่เห็นคุณทำซ้ำ — เขียนไว้ที่ที่คุณเปิดอ่าน แก้ ยกไปให้เอเจนต์ตัวอื่น
  หรือลบทิ้งได้เอง ไม่มีอะไรที่มันเรียนถูกล็อกไว้ในรูปแบบที่มีแต่ Aetox อ่านได้

ส่วนที่รันเป็นทางเลือกของคุณ และโมเดลก็เป็นของคุณ: 31 providers ทั้งคลาวด์และในเครื่อง ถามรายชื่อโมเดลจาก
provider ตอนใช้งาน โมเดลใหม่จึงขึ้นเองโดยไม่ต้องรอ Aetox รุ่นใหม่ วันนี้งานทั้งหมดรันบนเครื่องคุณ
[ดู provider ทั้งหมด](https://mikedev115.github.io/Aetox-landing/th/features/#models)

## ผลที่วัดได้

**งานโค้ด** — ข้อสอบห้าชุด × 2 โมเดลสาธารณะของ OpenAI ([`gpt-6-luna`](https://developers.openai.com/api/docs/models/gpt-6-luna), [`gpt-5.6-terra`](https://developers.openai.com/api/docs/models/gpt-5.6-terra) ความคิดระดับ medium) × 3 รอบ
เทียบกับตัวครอบอื่นอีกสี่ตัว (OpenCode · Codex CLI · omp · pi) ทุกข้อตัดสินด้วยเทสต์ซ่อน ใช้บัญชีเดียวกัน
และไม่มีการตั้งค่าของผู้ใช้ในทุกตัว

| ข้อสอบ | วัดอะไร | Aetox | ที่ดีที่สุดของตัวอื่น |
|:---|:---|--:|--:|
| **CWEval** `func-sec@1` | ฟังก์ชันที่ทั้งทำงานถูกและผ่านเทสต์โจมตี (จาก 15 ฟังก์ชัน) | **93.3%** (Luna)<br>**97.8%** (Terra) | omp 68.9%<br>OpenCode · omp · pi 77.8% |
| **SlopCodeBench** % เทสต์ผ่าน | งานหลายเทิร์น 6 โจทย์ ตรวจว่าโค้ดเก่าไม่พัง | **91.6%** (Luna)<br>**95.2%** (Terra) | OpenCode 90.8%<br>OpenCode 92.8% |
| **SlopCodeBench** checkpoint ผ่านครบ | checkpoint ที่เทสต์ผ่านทุกข้อ จาก 14 | **4.0 / 14**<br>**7.0 / 14** | OpenCode 3.7<br>OpenCode 6.7 |
| **SWE-bench Multilingual** (caddy-6350) | บั๊กจริงจาก repo สาธารณะ เกณฑ์ทางการ | 1/3 รอบ (Luna)<br>2/3 รอบ (Terra) | OpenCode 2/3<br>pi 3/3 |
| **Web-Bench** | งานที่ spec ของ Playwright ผ่านครบ หลังทำ 6 งาน | 5.3 / 6<br>5.3 / 6 | pi 5.3<br>omp · pi 5.7 |

แรงนำของ CWEval มาจากสกิลความปลอดภัยที่เปิดมาตั้งแต่ติดตั้ง — ถ้าปิดสกิลนี้ Aetox จะได้คะแนนช่วงเดียวกับตัวอื่น
และ SWE-bench คือชุดที่เรายังไม่ชนะ ซึ่งอยู่ในตารางนี้แล้ว

**งานเอกสารและสื่อ** — วัดบนแอปเดียวกัน ตอนเปิดสกิลเทียบตอนปิดสกิล

## วิธีใช้ให้ได้ผล

Aetox ไม่ได้มีมนตร์วิเศษที่ทำให้โมเดลฉลาดขึ้น — มันรีดศักยภาพของโมเดลตามหลักสถาปัตยกรรม
การเอาโมเดลเล็กมาสร้างระบบใหญ่ได้จึงมาจากตรงนั้น **เพราะฉะนั้นการเลือกโมเดลให้เหมาะกับงานจึงสำคัญไม่แพ้กัน**

สถาปัตยกรรมการจัดการบริบทของเราไม่ได้เริ่มจากคำถามว่า "จะประหยัดโทเคนยังไง" แต่เริ่มจาก "รอบนี้โมเดลต้องรู้อะไรจริง ๆ"
ข้อมูลจะถูกแมพเป็นโครงสร้างภายใน แยกหมวดหมู่ออกเป็นโหนด เชื่อมโยงกันเป็นเส้นสาย ในการประมวลผลระบบจะส่งแค่จุดที่ต้องใช้งาน
พรอมป์ต์จึงถูกประกอบใหม่ต่องาน ไม่ได้ส่งทีเดียวทั้งหมดตั้งแต่เริ่ม และจะถูกส่งเข้าประมวลผลแค่เท่าที่จำเป็น
โปรไฟล์ของคุณจะไม่ไปกับทุกคำขอที่ไม่เกี่ยวข้อง โดยครอบคลุมถึงความจำ สกิล และ MCP ทั้งหมดออกแบบภายใต้สถาปัตยกรรมเดียวกัน

เนื้อสกิลและ schema ของเครื่องมือไม่ได้ถูกส่งไปทีเดียว โมเดลเห็นชั้นวางชื่อ แล้วจ่ายค่าเนื้อหาก็ต่อเมื่อเปิดขึ้นมาใช้
ห้าสิบสกิลจึงราคาเท่าห้าสกิล และการเพิ่ม MCP หนึ่งตัวคือเพิ่มชื่อ ไม่ใช่เพิ่ม schema ทั้งชุด
และ agent ทุกตัวสามารถเลือกต่อสกิลและ MCP แยกกันได้

งานที่ต้องเห็นภาพทั้งก้อน เราไม่ปล่อยให้โมเดลขอทีละชิ้น แต่ยกความกว้างให้ครั้งเดียวตั้งแต่ต้น แล้วงานจบในเทิร์นเดียว
นั่นคือที่ไปของโทเคน: ขาเข้าทั้งหมดมากกว่าตัวครอบอื่น 1.1–8.5 เท่า แต่ราว **91% เป็นอินพุตที่แคชไว้** ซึ่งถูกกว่าหลายเท่า
**ภาระจริงคือส่วนที่ไม่ได้แคชบวกขาออก ต่างกันเพียง 1.1–2.1 เท่า**:
Luna 0.64 ล้าน เทียบ 0.30–0.57 ล้าน · Terra 0.93 ล้าน เทียบ 0.50–0.81 ล้าน

โทเคนที่มากกว่าในงานโค้ดบางงานจึงไม่ใช่ของเสีย แต่เป็นผลข้างเคียงของการรีดศักยภาพโมเดลออกมาแลกกับงานที่ดีกว่า
และมันไม่ได้เกิดขึ้นกับงานทั่วไป — งานตามคำสั่งอย่างการเพิ่ม MCP หรือติดตั้งสกิลเป็นชุด ระบบจัดการด้วยกลไกข้างบนทั้งหมด
ผลลัพธ์ในการใช้งานจริงกลับประหยัดอย่างไม่น่าเชื่อ

**นี่คือจุดที่ควรแลก** ไม่ใช่จุดที่ควรกลัว ถ้าอยากลดจริง ๆ ลดด้วยการเลือกโมเดลให้ตรงงาน

- **งานที่ต้องอ่านทั้งโปรเจกต์หรือทำต่อเนื่องยาว** → โมเดลใหญ่ได้เปรียบ
- **งานประจำที่ทำซ้ำ** → โมเดลเล็กพอ และระบบชดเชยส่วนที่ขาดให้
- **ทุกอย่างรันบน Windows** — หน้าจอ เบราว์เซอร์ และชั้นควบคุมคอมพิวเตอร์เป็น Win32 ทั้งหมด

<sub>ตัวเลขแต่ละรอบแกว่ง 1.5–2.5 จุด ต่างไม่กี่จุดจึงอ่านว่าเสมอกัน · วิธีวัดและผลทุกรอบอยู่ใน[รายงาน](docs/reports/coding-harness-1.10.0/README.md)</sub>

## โมเดล

31 providers ทั้งบนคลาวด์และในเครื่อง ChatGPT (Codex), GitHub Copilot และ OpenRouter ล็อกอินได้เลย ที่เหลือใช้คีย์ API
หรือที่อยู่ของเซิร์ฟเวอร์ในเครื่อง LM Studio และ Ollama ได้เครื่องมือชุดเดียวกับโมเดลใหญ่ เปลี่ยนโมเดลกลางแชทได้
บริบททั้งหมดตามไปด้วย

สร้างภาพในเครื่องก็ได้ ชี้ Aetox ไปที่ ComfyUI หรือ Stable Diffusion WebUI (Forge Neo, Forge หรือ A1111)
แล้ววาดด้วย GPU ของคุณเอง รวมถึง FLUX.2 klein [สร้างภาพในเครื่อง](docs/LOCAL-IMAGES.md)

> **ใช้ฟรี แต่ไม่ได้แถมโมเดลบนคลาวด์ฟรี** งานจริงต้องมีโมเดล จะเป็นบัญชีหรือคีย์ที่คุณมีอยู่แล้ว หรือโมเดลในเครื่องก็ได้
> ราคาเป็นไปตาม provider ที่คุณเลือก

## ความปลอดภัยและข้อมูลของคุณ

- **ข้อมูลอยู่บนเครื่องคุณ** แชท ไฟล์ ข้อมูลเบราว์เซอร์ และทุกอย่างที่มันเรียนรู้อยู่บนดิสก์ของคุณ ไม่มีเซิร์ฟเวอร์ของเราคั่นกลาง
  ไม่มีการเก็บสถิติ provider บนคลาวด์เห็นเท่าที่ API ของเขาเห็นตามปกติ
- **คีย์** ผูกกับบัญชี Windows ของคุณ และถูกตัดออกจาก log และผลลัพธ์ของเครื่องมือ
- **คุณเลือกเองว่าให้ทำได้แค่ไหน** ถามก่อน · ถามเฉพาะที่เสี่ยง · เต็มสิทธิ์ ส่วนการเผยแพร่อะไรออกไปข้างนอก
  และการปิดโปรแกรมตามชื่อ จะถามทุกระดับ
- **ไฟล์ลับถูกปฏิเสธ** `.ssh` `.aws` ที่เก็บรหัสของ Windows โปรไฟล์เบราว์เซอร์ และไฟล์คีย์ของ Aetox เอง
  ไม่มีเครื่องมือไหนเปิดได้
- **อะไรเป็นตัวกัน** กฎพวกนี้เป็นการเช็กในโค้ดของ Aetox เอง ไม่ใช่ sandbox ของระบบปฏิบัติการ ถ้าเครื่องมีข้อมูลที่เสียไม่ได้
  ให้ใช้ API key แยกเฉพาะ Aetox และรันใน VM หรือ Windows Sandbox

[รายละเอียดความปลอดภัย](https://mikedev115.github.io/Aetox-landing/th/safety/) · เจอช่องโหว่? [SECURITY.md](SECURITY.md) บอกวิธีแจ้งแบบส่วนตัว
